# 两套定点约定对齐分析（rtl/math ↔ rtl/simsynth）

> 结论先说：**可以合并，但要分层** —— `rtl/math` 的 `fxp_pkg` 适合当"唯一算术库"，
> `sfp/ufp` 适合"静态格式数据通路"，而 `rtl/simsynth` 的 `coeff_t`（运行时指数）必须保留。
> 唯一**必须先统一**的是**舍入规则**（他们截断、我们四舍五入），否则两边的数值不可比
> （我们的黄金向量是与 Python 模型逐位对齐的，改成截断会破坏这一点）。

## 1. 两边的模型

| | **rtl/math**（`fxp_pkg` + `sfp/ufp` + `fp_ops`） | **rtl/simsynth**（`modal_step_pkg`） |
|---|---|---|
| 数值模型 | 值 = `v · 2^-F`，`F` 是**格式参数** | 值 = `mant · 2^-shift`，`shift` 在**系数记录里** |
| 格式来源 | 参数化 interface `sfp #(.iw, .qw)`（elaboration 常量） | `coeff_t` 打包字段（RAM/ROM 里的数据） |
| 移位 | **编译期常量** ⇒ 实测 LUT = 0 | **运行时变量** ⇒ 桶形移位器 |
| 舍入 | **floor**（`>>>` 截断，文档明写"matching the hand-written RTL"） | **四舍五入** `+2^(s-1) >>> s` |
| 实现形态 | 参数化 **interface + 模块**（`sfp_add/mul/mac`，每次调用一份硬件） | 包内**函数**，7 个乘积共用**一个**乘法器（TDM） |
| 位宽 | 64 位载体 + 接口决定的实际宽度 | 32 位状态/激励、24+6 位系数、64 位累加器 |
| 服务对象 | 静态数据通路：CORDIC 坐标变换、`sqrt`/`inv`、混音 | 系数表 + 模态递归（动态范围大、模态多） |

## 2. 差异中真正要紧的三条

1. **舍入规则不兼容（必须统一）**
   我们 `term() = (a·m + 2^(s-1)) >>> s`；他们所有算子都是 `>>> s`（floor）。
   模态递归的极点精度对"每项是否舍入"很敏感 —— 之前的定点可行性分析里，每模态 22 位
   系数在**逐项舍入**下衰减率误差 0.03%，而换成整体/截断式处理误差升到 1.44%。
   ⇒ 若要合并，必须在 `fxp_pkg` 里**增加舍入变体**（`fx_shift_rnd` / `fx_mul_rnd`），
   而不是把我们的路径改成截断。

2. **移位是编译期还是运行时（影响资源与时序）**
   他们在 `fp_intf.sv` 里实测并记录：移位量是参数时 `LUT = 0`；是运行信号时 **LUT = 77..665**。
   我们的 `term()` 用的正是运行时 `shift`（每个模态不同）⇒ 我们一直在为桶形移位付 LUT，
   而且它就在关键路径上（PnR 显示最差路径收敛在 `term_q` 那一级）。
   ⇒ 这是**合并能带来的实质收益**：若能消掉运行时移位，面积与时序都会改善。

3. **算子形态不同（不能直接互换）**
   他们的 `sfp_mul/sfp_mac` 是**模块**：调用一次实例化一份乘法器。放进我们的 TDM bank
   会变成 7 个乘法器 ⇒ 违背"一条乘法通路跑 N 个模态"的前提。
   ⇒ bank 内部继续用包函数 + 单乘法器；`sfp_*` 只用于"本来就并行"的数据通路
   （腔体滤波器、混音、音频输出）。

## 3. 映射关系（能对上，但有一处不可参数化）

我们的一个常量 `(mant 24 位有符号, shift)` 恰好等价于他们的一个定点数：

```
值 = mant · 2^-shift    ≡    sfp #(.iw(24 - shift), .qw(shift))     // 24 = iw + qw
```

所以**数值语义完全一致**，不存在"两种定点"的深层冲突。问题只在 `shift` 是**每个模态
不同**的（状态归一化 `sq = 2^QF/peak_q` 逐模态变化，跨模态跨度约 60 dB）⇒ 等价于要给
48 个模态 × 7 个系数各写一个 interface 实例，不可接受。这就是我们必须用"运行时指数"
的原因，也是他们那套用不上的地方。

## 4. 合并方案（分三层）

**L1 算术库（建议立刻做）**
把 `fxp_pkg` 作为唯一算术库，补两个舍入变体：

```systemverilog
// 四舍五入的移位：d>0 时加 2^(d-1) 再算术右移
function automatic logic signed [63:0] fx_shift_rnd(input logic signed [63:0] a, input int d);
    fx_shift_rnd = (d <= 0) ? fx_shift(a, d)
                            : ((a + (64'sd1 <<< (d-1))) >>> d);
endfunction
// 定点乘 + 舍入到 fout
function automatic logic signed [63:0] fx_mul_rnd(...);   // = fx_shift_rnd(a*b, fa+fb-fout)
```

`modal_step_pkg::term()` 改为调用 `fxp_pkg::fx_mul_rnd(...)`（或保留现实现但注明等价），
这样两边共用一份算术、黄金向量不受影响（数值不变）。

**L2 静态格式数据通路（建议做）**
状态/激励/音频输出/腔体滤波器这些**格式固定**的信号，改用 `sfp`/`ufp` interface 声明，
按 `fp_intf.sv` 的 `(iw, qw)` 记法。收益：移位全部常量化 ⇒ LUT=0，且语义自解释
（`sfp #(.iw(3), .qw(29))` 比"32 位状态 + 某处移位"清楚）。

**L3 系数表（保留现状）**
`coeff_t`（24 位尾数 + 6 位移位）保持不变。理由如上：跨模态 60 dB 跨度必须靠逐条指数。
可以补充约定：`coeff_t.shift` 就是 `fp_intf` 里的 `qw`，`24 - shift` 就是 `iw`。

## 5. 逐字段定 Q 的实验结果（已实测，取代原先的推测）

问题：能否把"每条目自带指数"换成"每个字段共用一个编译期 Q"（所有移位变常量、
桶形移位消失），代价是尾数加宽。

### 5.1 精度：极点半径相对误差（21 个音 40–80、2 bank、1322 个模态）

脚本 `_analysis/_fpga_field_q.py`（`modes_of` 取每模态 2×2 更新矩阵，`poles` 求特征值）：

| 方案 | max \|Δr\|/r | 中位 \|Δr\|/r | max 衰减率误差 (dB/s) |
|---|---|---|---|
| entry24（现状：24 位尾数 + 逐条指数） | 4.03e-08 | 8.70e-09 | 0.02 |
| fieldQ24（逐字段 Q，24 位） | 1.24e-07 | 3.99e-08 | 0.05 |
| **fieldQ32** | **5.20e-10** | 1.48e-10 | **0.00** |
| fieldQ36 | 3.00e-11 | 9.39e-12 | 0.00 |
| fieldQ40 | 1.88e-12 | 5.73e-13 | 0.00 |
| plainQ22（全表一个 Q，反面教材） | 5.12e-03 | 2.19e-04 | 2133 |

- **逐字段 Q 在 32 位时就比现状精确 78 倍**；36 位约 1300 倍；40 位约 2100 倍。
- 逐字段 Q 用 24 位也够用（0.05 dB/s，远低于可闻阈）；真正被打死的是"全表共用一个 Q"。
- 字段量程比预想小：`a11/a22 ≈ 1`、`a12` 最大 2.08e-5、`a21` 最大 8.73e4 —— 同字段内跨模态
  只差几个 bit（`a12` 随 1/f，40–80 号音约 3.3 bit），所以"逐字段"几乎不掉精度。

> 口径说明：上面用**未缩放**的 2×2 矩阵元。硬件存储的**缩放后**域里，四个矩阵元被状态
> 归一化压到 O(0.1..1)、跨模态范围更小 ⇒ 逐字段 Q 只会更容易。受影响的是三个增益
> （`gq/gv/wo` 带 `sq`，跨模态约 60 dB），但它们只决定**电平**而非音高/衰减，10 bit 损失
> ≈ 0.1% 电平误差，不可闻。

### 5.2 器件：同一个"32 位状态 × W 位系数 + 舍入 + 固定移位"拍

探针 `_analysis/rtl_modal/fieldq_mul.sv`（两级流水、`SH` 编译期常量），四次综合：

| 尾数位宽 W | Logic | FF | **MULT27X36** | 备注 |
|---|---|---|---|---|
| 24（现状） | 45（1 LUT + 44 ALU） | 88 | **1** | 运行移位还在别处 |
| **32** | 122（84 LUT + 38 ALU） | 102 | **2** | |
| **36** | 122 | 102 | **2** | 与 32 完全相同 |
| **40** | 122 | 102 | **2** | 与 32 完全相同 |

- 24 → 32 位的增量：**+1 个 MULT27X36（≈2 DSP 单元）+ 约 77 LUT + 14 FF**；
  32/36/40 **一样贵**（27×36 的粒度吃掉了 40 位）⇒ **36 位是免费的精度**。
- 同时**减少**的开销：运行时桶形移位消失，而它此前既花 LUT 又在关键路径上
  （PnR 最差路径收敛在 `term_q` 那一级）。
- 系数表：210 bit/模态（7×(24+6)）→ 252 bit/模态（7×36）；32 模态下 6.7 kbit → 8.1 kbit，
  BSRAM 块数不变。

### 5.3 建议

**改用逐字段定 Q + 36 位尾数**：精度比现状好约 3 个数量级，移位全部常量化（可顺带啃掉
100 MHz 的剩余瓶颈），代价只有 1 个 MULT27X36，而器件有 298 个。后续"逐模态缩放"实验
可以简化成"验证 36 位在所有音上都留有余量"。

## 6. 不建议合并的部分

- 不要把 TDM bank 内部换成 `sfp_mac` 模块（会变成 7 个乘法器）。
- 不要把 CORDIC 路径改成舍入（`math.sv` 的截断是与其验证过的行为绑定的）。

> **关于 64 位载体（已实测修正）**：`fxp_pkg` 的 `CW = 64` 只是**载体**。把
> `modal_step_pkg::term()` 整个换成 `fx_mul_rnd(a, m, 0, 0, -s)` 后综合同一份 TDM bank：
>
> | 写法 | Logic | Register | MULT27X36 | Logic Level |
> |---|---|---|---|---|
> | 窄乘法（32×24）+ `fx_shift_rnd` | 1678（LUT 1362+ALU 316） | 381 | 1 | 17 |
> | `fx_mul_rnd`（64 位载体） | 1689（LUT 1373+ALU 316） | 381 | **1** | 17 |
>
> 差 +11 LUT（0.7%），**乘法器仍是 1 个** —— 综合器按实际使用的位宽把载体裁掉了。
> 所以 `term()` 直接用 `fx_mul_rnd`，整个"乘法 + 四舍五入 + 移位"只剩一个包调用；
> 三套黄金向量逐位不变。
