# 歌曲合成工程资源占用（v5，2026年10月9日整理）

> 历史归档：本轮独立资源报告已合并进[工程汇报](../../../../工程汇报.md)，不再作为并列当前入口。下文保留归档时的记录。

当前完整歌曲工程占用 **15,416个逻辑单元、8,911个逻辑触发器、52块块存储器、14个DSP资源单元和2个PLL**。资源容量尚有余量；目前更明显的限制是控制译码、扇出和布线时序，而非DSP数量耗尽。

本报告整理的是 **2026年10月7日已有v5真实构建**，不是今天重新综合的结果。资源数字与用户获准试验的歌曲文件对应，不取自旧84MHz工程或独立时钟/测试音工程。

## 工程范围

| 项目 | 配置 |
|---|---|
| 顶层 / 平台 | `board_top` / Tang Mega 138K Pro |
| 构建目标 | `GW5AST-LV138FPG676AES`，器件版本B |
| 工具 | Gowin V1.9.12.04 |
| 模态阵列 | 32声部 × 每声部最多48模态，最多1,536个模态状态 |
| 运算结构 | 四条共享运算通道，启动间隔II=3 |
| 数值 | Q2.30模态状态，64bit声部/混音累加 |
| 共鸣箱体 | `ENABLE_BODY=1`、`BODY_INSTRUMENT=0`，guitar混音后共享四节滤波器 |
| 时钟 / 输出 | 核心100MHz；音频参考12.5MHz；标准I2S、16bit单声道左右复制 |
| 统计范围 | 歌曲调度、系数装载、模态引擎、共享箱体、音频传输和两套PLL初始化逻辑的整机 |

实际采样率48,828.125Hz，不称精确48k播放；工程未引入AE350硬核CPU、DDR3或麦克风处理链。平台实际芯片完整尾缀/速度级仍待实物核实。

## 最终布局布线资源

来源：[原始布局布线报告](../../../../reports/evidence/song_core100_v5_20261007/pnr_report.txt)第38～103行。整机容量评价以此表为准。

| 资源 | 占用 | 目标容量 | 按数量计算 | 工具显示 |
|---|---:|---:|---:|---:|
| 逻辑单元合计 | 15,416 | 138,240 | 11.15% | 12% |
| 其中LUT | 13,866 | — | 已包含在逻辑单元中 | — |
| 其中ALU | 1,550 | — | 已包含在逻辑单元中 | — |
| 逻辑触发器 | 8,911 | 138,240 | 6.45% | 7% |
| 逻辑簇CLS | 11,687 | 69,120 | 16.91% | 17% |
| 块存储器BSRAM | 52 | 340 | 15.29% | 16% |
| DSP资源单元 | 14 | 298 | 4.70% | 5% |
| PLL | 2 | 12 | 16.67% | 17% |
| I/O端口 | 6 | 312 | 1.92% | 2% |
| 主时钟资源PRIMARY | 3 | 8 | 37.50% | 38% |
| 长线资源LW | 1 | 8 | 12.50% | 13% |

整数百分比沿用工具报告，精确比例另按占用/容量计算。工具的Register总容量为139,140，含900个I/O寄存器；本工程8,911个均为逻辑FF，I/O寄存器和锁存器均为0，因此上表逻辑FF以138,240为分母。资源类型相互关联，不能将LUT、ALU、CLS与Logic合计再次相加；PRIMARY按报告的资源计数列示，不把时钟区域覆盖数相加成资源占用。

块存储器分类：**16个SPX9、2个SDPB、34个pROM**，合计52。分布式存储器SSRAM和ROM16均为0。这是物理资源分配，不代表每块内所有位都存了有效系数。

DSP报告同时列出 **7个`MULT27X36`原语**。本次构建这7个原语对应总计14个DSP资源单元；“7个乘法原语”不能替代“14/298的资源占用”。综合网表保留四通道的4个乘法原语及箱体的3个乘法原语，配置地址上的两个`MULT12X12`已消除。

进一步看综合表：模态bank为5,862 FF、11,531 LUT、1,097 ALU、4个乘法原语及16个存储计数；其中四条lane分别有一个乘法原语、四个存储计数。这些是引擎行的子模块，**不能再与引擎行叠加**。装载器的33个存储计数对应模态系数/索引ROM。

## 模型检查与实板试验分别记录

| 项目 | 已有结果 / 当前状态 |
|---|---|
| 普通setup / hold | 原v5报告各0违例；异步第一级hold例外及保留max_delay经独立核对 |
| 核心时序 | 工具Fmax100.007MHz，最坏setup裕量+0.001ns |
| 最小脉宽模型 | 最坏slack−0.612ns；模型actual0.288ns、required0.900ns，不是示波器实测 |
| bank功能 | 独立真实综合网表3/3用例通过，满载最大1,506周期；engine既有测试最大1,508周期 |
| 完整生产网表功能 | 两个首音启动/reset阶段共34个I2S帧与黄金一致，不冒充整首歌曲验证 |
| 修复歌曲实板 | 用户已获准有限SRAM试验；尚未收到明确出声、整曲循环和≥60s稳定性结果 |
| 100MHz引脚观测 | 独立工程已提供，B21/J26针12；尚未收到高低脉宽实测数字 |
| 独立持续测试音 | 用户已确认出声，只证明该测试设计及接线可用 |

按用户决定，采用**先实板验证、模型分析继续作为报告**的推进方式；当前试验不因模型疑点停在纸面分析。报告仍保留负MPW及源路径相关性疑问，不修改source latency、名义占空比或门槛来求绿色结果。

实板通过应注明板卡、供电、温度、测试时间和版本，只覆盖测过的条件。官方800MHz例程的输出送给AE350硬核CPU，不能按本工程DSP/RAM的脉宽要求套算并判其必然失败；也不能据该例程证明本工程违例全部是假警报。资源统计不受这项判断影响。
