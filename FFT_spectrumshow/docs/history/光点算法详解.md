## 零、时钟与扫描架构（复查补充，此前文档完全遗漏）

### 0.1 时钟与分辨率

```verilog
// top.v: PLL 50MHz → 33.33MHz 像素时钟（周期 30ns）
Gowin_PLL(... .clkout0(pix_clk), .clkin(clk));   // 33.33M
// lcd_timing.v: 800×480 LCD，含消隐
parameter H_Pixel_Valid = 800;  H_FrontPorch = 210;  H_BackPorch = 182;
// 一整行 = 800+210+182 = 1192 个时钟
parameter V_Pixel_Valid = 480;  V_FrontPorch = 45;   V_BackPorch = 8;
// 一整帧 = 480+45+8 = 533 行；帧率 ≈ 33.33M/(1192×533) ≈ 52.4 Hz
```

### 0.2 【漏洞A】pix_x / pix_y 在有效区外并不归零（lcd_timing.v 第50-51行）

```verilog
assign pix_x = (H_PixelCount >= H_BackPorch) ? (H_PixelCount - H_BackPorch) : 10'd0;
assign pix_y = (V_PixelCount >= V_BackPorch) ? (V_PixelCount - V_BackPorch) : 10'd0;
//                  ^ 只处理了"行首消隐→0"，没处理"行尾消隐→超界"！
```

| 扫描区 | H_PixelCount | 实际 pix_x | 应该是 |
|---|---|---|---|
| 行首消隐(182拍) | 0..181 | **0（重复）** | 0 |
| 有效区(800拍) | 182..981 | 0..799 ✓ | 0..799 |
| **行尾消隐(210拍)** | 982..1191 | **800..1009（越界！）** | 0 或 799 |

pix_y 同理：帧尾消隐 45 行里 pix_y = **480..524**（越界）。

**后果**（光点更新逻辑每拍都在跑，不管 lcd_en）：
- 每扫描行 1192 拍中，**bar 0 被更新 ~188 次**（行首消隐 182 次 + 有效区 6 次）；
  正常柱只有 6 次。bar 0 的光点下落速度是别人的 ~31 倍。
- pix_x=800..1009 → bar_idx_raw=133..168 → clamp 后**全部砸到 bar 127**：
  **bar 127 每行被更新 ~248 次**（行尾消隐 210 + 有效区尾 32 + 自己 6）。
- 目前碰巧无害：bar 0 始终有 bass≥40 压着；bar 127 恰好没有任何音符覆盖（最远谐波
  在 148 柱）。**但这是隐性炸弹**——以后把音符挪到 bar 110+ 就会炸。

### 0.3 光点的"每柱更新时隙"概念（理解下落速度的钥匙）

光点 always 块每个 pix_clk 都在跑，但 `bar_idx` 由当前 pix_x 决定——
**一根柱只有在扫描线扫过它那 6 列时才被更新**：

```
每根柱每行获得时隙 = 6 拍（+0.2 节的消隐异常）
FALL_PERIOD=60 → 每行攒 6 拍 → 每 10 行落 1px → 每帧(533行)落 ~53px
```

所以你看到的"快速下落"≈每帧 53px，从 116 高度落到底约 2.2 帧（~42ms）——**是设计值，不是 bug**。

## 一、假数据生成 data_source.v（柱高的来源）

### 1.1 屏幕常量（顶部）

```verilog
parameter SCREEN_W = 10'd800;   // 屏幕有效列 0..799
parameter SCREEN_H = 10'd480;   // 屏幕有效行 0..479
parameter MID_Y    = 10'd240;   // 垂直中线（屏幕高度一半）
```

### 1.2 FFT 柱几何（柱号计算）

```verilog
parameter FFT_BINS  = 10'd128;   // 显示 128 根柱
parameter BAR_W     = 10'd6;     // 每根柱宽 6px（128×6=768px）
parameter MAX_BAR_H = 10'd400;   // 柱高上限（未实际用满）

wire [9:0] bar = q_x / BAR_W;    // 当前像素属于第几根柱
// ⚠ 注意（见 0.2 节）：q_x 实际会冲到 1009（行尾消隐）→ bar 最大 = 168，
//   超过 127 的柱号查谐波表全空 → q_y=0。越界靠"查表天然为空"兜底，而非显式保护。
```

### 1.3 音符调度（模拟一首歌）

```verilog
// 8 个音符循环，每个音符 = {基频所在的柱位置, 该音符的幅度}
// 幅度都 ≤200（柱高约半屏，给光点超调留空间）
localparam N0_BAR = 8,  N0_AMP = 10'd200;
localparam N1_BAR = 26, N1_AMP = 10'd160;
localparam N2_BAR = 42, N2_AMP = 10'd180;
localparam N3_BAR = 60, N3_AMP = 10'd140;
localparam N4_BAR = 78, N4_AMP = 10'd170;
localparam N5_BAR = 96, N5_AMP = 10'd130;
localparam N6_BAR = 112,N6_AMP = 10'd150;
localparam N7_BAR = 120,N7_AMP = 10'd110;

// 音符索引：每 32 帧换一个音符，8 个循环 = 256 帧一圈
reg  [9:0] song_cnt;
wire [7:0] note_idx = (song_cnt / 10'd32) % 8'd8;   // 当前音符 0..7
always @(posedge clk) begin
    if (!rst_n) song_cnt <= 0;
    else if (frame_pulse) song_cnt <= song_cnt + 1;  // 每帧+1
end
```

### 1.4 包络（音符的音量随时间变化）

```verilog
// 一个音符持续 32 帧：
//   0~5 帧   起音(attack)：音量从 0 冲到 360
//   5~24 帧  持续(sustain)：音量保持 360
//   24~32 帧 衰减(decay)：音量从 360 掉下来
wire [9:0] note_phase = song_cnt % 10'd32;   // 音符内部进度 0..31
wire [9:0] env = (note_phase < 10'd5)  ? note_phase * 10'd72 :      // 起音
                 (note_phase < 10'd24) ? 10'd360 :                  // 持续
                                         (10'd32 - note_phase) * 10'd45;  // 衰减
```

### 1.5 谐波结构（一个音符 = 基频 + 2倍频 + 3倍频 三个峰）

```verilog
// d0 = 当前柱到"基频位置"的距离
wire [8:0] d0 = (bar >= note_pos) ? (bar - note_pos) : (note_pos - bar);
// h0 = 基频峰：距基频≤4的柱有值，最近=280，越远越小
wire [9:0] h0 = (d0 < 9'd4) ? (10'd4 - d0) * 10'd70 : 10'd0;

// d2 = 当前柱到"2倍频位置"(基频+14)的距离 → 第二峰
wire [8:0] d2 = (bar >= note_pos+9'd14) ? (bar-(note_pos+9'd14)) : ((note_pos+9'd14)-bar);
wire [9:0] h2 = (d2 < 9'd4) ? (10'd4 - d2) * 10'd45 : 10'd0;   // 最大180

// d3 = 到"3倍频位置"(基频+28)的距离 → 第三峰
wire [8:0] d3 = (bar >= note_pos+9'd28) ? (bar-(note_pos+9'd28)) : ((note_pos+9'd28)-bar);
wire [9:0] h3 = (d3 < 9'd4) ? (10'd4 - d3) * 10'd25 : 10'd0;   // 最大100
```

### 1.6 柱高合成（最终输出到绘制层）

```verilog
// note_h = (h0+h2+h3) × env × note_amp / 172800
// 实测最大 = 116，来历：柱高上限其实由"单峰"决定——
// 三个峰位置相距 14 柱、每峰宽 ≤7 柱(±3)，**永不在同一根柱上重叠**，
// 所以单柱 harm_sum 最大 = h0 = 280（不是三者之和 560！原注释有误导）
// 280 × 360(env峰值) × 200(N0_AMP) / 172800 = 116.67 → 截断 = 116 ✓
wire [11:0] harm_sum = ({1'b0,h0}+{1'b0,h2}+{1'b0,h3});   // 同一柱上实际 ≤280
wire [23:0] hp1 = harm_sum * {2'b0, env};                  // ×包络
wire [35:0] hp2 = {12'b0, hp1} * {2'b0, note_amp};         // ×音符幅度
wire [9:0]  note_h = hp2 / 24'd172800;

// 低频底座（一直存在，像鼓点）—— 最大 40
wire [8:0] dlow = bar;
wire [9:0] low_h = (dlow < 9'd24) ? (9'd24 - dlow) : 9'd0;
wire [9:0] bass = (low_h * 10'd5) / 10'd3;

// 最终柱高 = 取 note_h 和 bass 的较大值
wire [9:0] bar_h_dyn = (note_h > bass) ? note_h : bass;

// 页面选择：FFT 页面输出柱高
always @(*) begin
    case (page_sel)
        2'b00:   q_y = bar_h_dyn;   // FFT: 柱高
        2'b01:   q_y = wave_y;      // 波形
        default: q_y = 0;
    endcase
end
```

## 二、LED 灯阵 + 光点 lcd_fft.v

### 2.1 柱号（含越界保护）

```verilog
// pix_x/6 = 柱号。注意：不仅 799/6=133，行尾消隐里 pix_x 会冲到 1009 → 168！
// 必须 clamp 到 0..127，否则访问 dot_ram 数组越界
wire [7:0] bar_idx_raw = pix_x / 10'd6;   // 0..168（含消隐期越界值）
wire [6:0] bar_idx = (bar_idx_raw > 7'd127) ? 7'd127 : bar_idx_raw[6:0];
// ⚠ 副作用：消隐期 168-127=41 个柱号全部砸到 bar 127（见 0.2 节后果）
```

### 2.2 柱体判定（是否在柱子内部）

```verilog
// 柱高 q_y，柱体从底部(y=479)向上长到 (479-q_y)
// in_bar = 当前像素在柱体内
wire in_bar = (q_y > 0) && (pix_y >= 10'd479 - q_y);
```

### 2.3 LED 灯阵效果（柱子由小方块灯组成）

```verilog
// 垂直：从柱顶往下每 5 行一组，4 行灯 + 1 行黑缝
wire [9:0] dist_top = pix_y - (10'd479 - q_y);   // 距柱顶的距离
wire [2:0] yg = dist_top % 10'd5;                // 组内位置 0..4
wire led_v = (yg <= 3'd3);                       // 0~3 是灯，4 是缝

// 水平：柱内 6px，灯占中间 4px，左右各 1px 黑缝
wire [2:0] xm = pix_x % 10'd6;                   // 0..5
wire led_h = (xm >= 3'd1) && (xm <= 3'd4);       // 1~4 是灯

// 一个亮起的 LED 灯
wire in_led = in_bar && led_h && led_v;
```

### 2.4 物理小球光点（核心：超调 + 下落）

```verilog
// 超调目标 = 柱高 × 1.2，钳位到屏幕顶 479
parameter OVERSHOOT_NUM = 10'd12;   // 12/10 = 1.2 倍
parameter OVERSHOOT_DEN = 10'd10;
wire [15:0] ov   = q_y * OVERSHOOT_NUM;   // 柱高×12
wire [15:0] ov_d = ov / OVERSHOOT_DEN;    // 柱高×1.2
wire [9:0]  ov_c = (ov_d > 10'd479) ? 10'd479 : ov_d[9:0];  // 钳位

// 每根柱一个光点高度 + 一个下落计时器
reg [9:0] dot_ram[0:127];    // 光点高度（0~479）
reg [9:0] fall_ram[0:127];   // 下落计时器（每柱独立）

always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        for (pi = 0; pi < 128; pi = pi + 1) begin
            dot_ram[pi]  <= 0;   // 复位清零
            fall_ram[pi] <= 0;
        end
    end
    else begin
        // 【顶起】柱高明显超过光点（+12 回滞，防抖动闪烁）
        if (q_y > dot_ram[bar_idx] + PEAK_HYST) begin
            dot_ram[bar_idx]  <= ov_c;    // 光点跳到 柱高×1.2（超调）
            fall_ram[bar_idx] <= 0;       // 重置这根柱的下落计时
        end
        // 【下落】光点高于柱高时，重力把它拉下来
        else if (dot_ram[bar_idx] > q_y) begin
            if (fall_ram[bar_idx] >= FALL_PERIOD - 1) begin
                fall_ram[bar_idx] <= 0;
                if (dot_ram[bar_idx] - PEAK_FALL > q_y)
                    dot_ram[bar_idx] <= dot_ram[bar_idx] - PEAK_FALL;  // 落1px
                else
                    dot_ram[bar_idx] <= q_y;   // 停在柱高上（不低于柱）
            end
            else
                fall_ram[bar_idx] <= fall_ram[bar_idx] + 1;   // 计时中
        end
    end
end
```

### 2.5 光点绘制（独立于柱子，超调也能看到）

```verilog
// 光点当前高度
wire [9:0] peak_h = dot_ram[bar_idx];
// 光点在"柱的横向范围(6px)"内 + 在"光点高度的那4行"内 → 显示
wire in_bar_col  = (pix_x >= {3'b0,bar_idx}*10'd6) && (pix_x < {3'b0,bar_idx}*10'd6+10'd6);
wire is_peak_dot = in_bar_col && (pix_y >= 10'd479-peak_h) && (pix_y <= 10'd479-peak_h+10'd3);

// 颜色优先级：光点(青色) > LED灯(柱色) > 黑缝
assign fft_r = is_peak_dot ? TOP_R : in_bar ? (in_led ? c_r : 6'h00) : 6'h00;
assign fft_g = is_peak_dot ? TOP_G : in_bar ? (in_led ? c_g : 6'h00) : 6'h00;
assign fft_b = is_peak_dot ? TOP_B : in_bar ? (in_led ? c_b : 6'h00) : 6'h00;
```

## 五、漏洞揭示（2026-09-28 复查，含 P&R 时序报告实锤证据）

### 5.1 🔴【漏洞B·实锤】q_y 组合路径 87ns vs 时钟周期 30ns → 光点顶飞的真凶

**P&R 时序报告**（`impl\pnr\800_480_screen.timing_paths`）最差路径：

```
SETUP  slack = -50.515 ns（负 50 纳秒！数据路径 87.087 ns，周期只有 30 ns）

起点:   lcd_timing_inst/H_PixelCount（寄存器）
中间:   → pix_x（减法）
        → data_source_inst/q_y（除以6 → 绝对差 → 36位乘法 → ★24位组合除法÷172800★）
        → lcd_draw_inst/u_fft/ov_0_s（★再乘12 → ★再组合除法÷10★）
        → n16133..n16141（÷10 除法器的纹波链，一路 70→87ns）
终点:   lcd_draw_inst/u_fft/dot_ram[104]（光点写入！）

全部 25 条最差路径 slack ≈ -49.5 ~ -50.5 ns，起点全是 H_PixelCount，
终点全是 dot_ram 的写数据/写使能。
```

**机理**：`q_y` 是纯组合输出，路径要走 87ns（≈3个时钟周期），但 lcd_fft 的光点
always 块**每个时钟沿(30ns)都在采样它**——采到的是**除法器纹波未稳定的中途值**，
可以是 0..1023 中的任何垃圾值：
- 采到垃圾 q_y=300 → 顶到 ov_c=1.2×300=**360 = 屏幕 3/4 高度** ← 你看到的现象！
- 采到垃圾 q_y≥400 → 钳位到 **479 = 从顶部落下** ← 你看到的现象！

**为什么 RTL 仿真测不出来**：仿真除法零延迟，87ns 路径瞬间完成——时序违例是
纯硬件现象。我之前的 glitch_tb/instant_tb 测出 max=116 只证明"逻辑正确"，
不证明"时序收敛"。**这就是仿真全过、上板乱飞的教科书案例。**

**为什么柱子本身看起来正常**：柱体绘制是组合的，垃圾 q_y 只影响当拍那 1 个像素
（人眼看不见）；但 dot_ram 是**寄存器**，把垃圾值**记住并保存好几秒**——
所以只有光点飞，柱子不飞。

### 5.2 🔴【漏洞C·实锤】光点"死区"——光点永久卡在柱体里

2.4 节的两个分支之间有个缝：

```
顶起分支: q_y > dot + 12     （柱高超出光点 12 以上才顶）
下落分支: dot > q_y          （光点高于柱才下落）
────────────────────────────────────────────
死区: 0 ≤ q_y - dot ≤ 12     ← 两个分支都不命中，什么都不做！
```

**场景**：光点停在柱顶（dot = q_y），之后柱子每帧缓慢升高 <12px（比如包络
起音阶段，d0=1~3 的侧峰柱每帧只涨 ~7~22px 中较小的那些）→ 光点被柱体
**淹没并冻结在柱里**，直到柱子大跌或大涨 12px 以上才解脱。
→ 这就是"**极少数光点有时候还在光柱里面**"的真凶。原观察点 4 说它是
"下落穿柱的正常现象"是**错的**——穿柱是暂态，这个是永态。

### 5.3 🟡【漏洞D·推测】"细小裂缝"的两个来源

1. **设计缝隙**：LED 灯阵每 6px 有 2px 黑缝（水平 1px + 垂直每 5 行 1 行黑）——正常。
2. **时序裂缝（推测）**：`lcd_r/g/b` 是**无输出寄存器**的组合输出（top.v 直接引到引脚），
   颜色路径同样穿过 q_y 那条 ~60-87ns 的超长组合链。LCD 面板在 lcd_clk 沿采样 RGB
   时颜色还没稳定 → 柱边缘/颜色边界处出现 1-2px 的撕裂——和 5.1 同根同源。

### 5.4 修复方向（只列方案，未动代码，留给你决策）

| 方案 | 改动 | 效果 |
|---|---|---|
| **A. 给 q_y 打一拍**（data_source 里把 bar_h_dyn 寄存后再输出） | 1-2 行 | **治本**：87ns 路径被切成两截，光点顶飞+裂缝一起消（如果 D 也是这个原因） |
| B. lcd_timing 的 pix_x/pix_y 行尾消隐也 clamp | 2 行 | 消漏洞A（bar0/bar127 时隙不均） |
| C. 光点逻辑加第三分支 `else if (dot < q_y) dot <= q_y`（或把顶起条件去掉对 dot<q_y 情形的 +HYST） | 1-3 行 | 消死区（光点卡柱内） |
| D. lcd_r/g/b 加输出寄存器 | 3-5 行 | 消 LCD 采样裂缝（若 5.3-2 成立） |

**推荐顺序：A → C → B → D**。A 是唯一"上板才暴露"的问题，其余仿真就能验证。

### 5.5 旧观察点勘误

| 原观察点 | 勘误 |
|---|---|
| 2. "怀疑音符切换瞬间组合逻辑毛刺" | **方向对，机制错**：不是切换瞬间才有毛刺，是 q_y 路径**每一拍都时序违例**（-50ns），只是大部分采样恰好落在稳定值上 |
| 4. "光点在柱体内是下落穿柱的正常现象" | **错**：那是死区卡死（见 5.2），不是穿柱 |
| 1.2 表 harm_sum "最多560" | 单柱实际 ≤280（三峰永不重叠，见 1.6 节修订） |
| 参数表 FALL_PERIOD "每60时钟落1次" | 实际 ≈53px/帧（见 0.3 节） |

## 六、从零梳理（完整链路，2026-09-28）

```
50MHz → PLL → 33.33MHz pix_clk（周期30ns）
        │
   lcd_timing（每拍推进 H/V 计数，1192×533）
        │  产出 pix_x(0..799←但行尾冲到1009)、pix_y(0..479←帧尾冲到524)、
        │        lcd_en、frame_pulse
        ▼
   data_source（核心问题源）
        │   .q_x = pix_x（所以 q_x 也冲到1009）
        │   FFT页: bar=q_x/6 → 谐波d0/d2/d3 → h0/h2/h3(条件乘)
        │          → harm_sum → ×env → ×note_amp → ★÷172800(组合除法)★
        │          → bar_h_dyn → q_y
        ▼
   lcd_fft（受害者1：光点）
        │   bar_idx=pix_x/6(clamp) → ★q_y×12→÷10(组合除法)★ → ov_c
        │   → 与 dot_ram[bar_idx] 比较 → 顶起/下落 → dot_ram 写
        │   → peak_h=dot_ram[bar_idx] → is_peak_dot 绘制
        ▼
   lcd_draw → top（受害者2：输出）
        │   lcd_r/g/b 纯组合直连引脚（无输出寄存器）
        ▼
   LCD 面板在 lcd_clk 沿采样
```

**整条链的地雷**：`data_source` 的 ÷172800 + `lcd_fft` 的 ÷10 两个**组合除法器**，
加上 36 位乘法，拼出一条 **87ns 组合路径**塞进 30ns 周期——这是光点顶飞、裂缝、
一切怪象的总根源。

### 修复的关键约束（为什么不能简单"给 q_y 打一拍"）

`q_y` 被柱体绘制（`in_bar`）和光点更新**同时使用**。若只给 q_y 打一拍：
- 光点更新用（延迟 q_y, 延迟 bar_idx）能对齐；
- 但柱体绘制用实时 pix_x 配延迟 q_y → **柱子的列正确、高度错**（画的是前几列的柱高）→ 柱体左右出现锯齿错位。

所以**不能打一拍**，必须把重计算挪到**帧级预计算**，让像素路径只剩查表。

## 七、没考虑到的因素（反思总结）

| # | 没考虑到的 | 后果 |

## 八、解决方案计划（2026-09-28 定稿）

### 阶段0：加"时序门禁"（最先做）
每次改完 → 重新综合 → **查 `impl\pnr\*.timing_paths` 里最大 slack 必须 >0**。
这是本次所有 bug 的验收标准。确认 flow.tcl/SDC 里有 33.33MHz 时钟约束。

### 阶段1：治本——架构重构（核心，改动约40行）
**思路：把"重的乘除法"从"每像素实时路径"挪走。**

- `data_source` 增加 `reg [9:0] bar_h[0:127]` 和 `ov_h[0:127]`：
  - 每帧 `frame_pulse` 后，用一个 128 步的小状态机串行算 128 根柱的 `bar_h` 和
    超调 `ov_c`（乘除法链照旧，但**结果寄存**、**流水2-3拍无所谓**，反正一帧 63 万拍，
    128 步算完只占 ~200 拍）；
  - 像素路径改为 **`q_y = bar_h[bar]` 查表**（异步读，几个 ns 就稳）+
    **`ov_c = ov_h[bar]` 查表**——像素路径上彻底没有除法器！
- `lcd_fft` 的 `ov` 计算一并删掉，直接用查表值。光点更新逻辑变短路径。
- **为何不能简单给 q_y 打一拍**：见第六节约束——柱体会画歪，必须帧级预计算。
- wave 页的 q_y 仍实时算（路径短，量测后若也超时序再流水）。

### 阶段2：修死区（漏洞C，3行）
`lcd_fft` 光点 always 加第三分支：
```verilog
else if (dot_ram[bar_idx] < q_y) dot_ram[bar_idx] <= q_y;  // 光点低于柱顶→贴到柱顶
```
保留 +12 回滞只用于"超调顶起"，光点永远不会再被淹没在柱体里。

### 阶段3：修消隐越界（漏洞A，2行）
`lcd_fft` 光点 always 加使能门控：只在 `lcd_en`（有效区）内更新 → 每柱每行稳定 6 拍，
bar0/bar127 不再被消隐期狂砸。同时 `data_source` 的 `bar = q_x/6` 也 clamp 到 0..127
（RAM 读不越界）。

### 阶段4：修输出（漏洞D，4行）
`top.v` 里 `lcd_r/g/b` 各打一拍输出（数据提前一个 pix_clk，LCD 在 lcd_clk 沿采到稳定值）。
**上板验证**裂缝是否消失；若面板采样相位不对，微调一拍方向。

### 阶段5：回归验证（每阶段都做）
1. RTL 仿真：`lcd_pages_tb` 必须 PASSED；补一个 tb 验证死区修复（柱缓慢升时光点贴柱顶不沉底）。
2. 重新综合 → **slack > 0**。
3. 上板：光点不再顶飞、不再卡柱内、柱边缘干净、bar0/bar127 行为与其它柱一致。

**执行顺序：0 → 1 → 2 → 3 → 4**。阶段1 是唯一治本项，做完 5.1 顶飞和 5.3 裂缝（一半）
自动消失；2/3 是 1-3 行的补丁；4 需上板确认。

## 十、二次回归修复（2026-09-28 晚，上板后反馈）

烧录上一版后发现两个新问题，均已修复：

### 10.1 光点"粘在光柱上"（死区分支过激）
- **现象**：光点紧贴柱顶，超调动画消失。
- **根因**：死区分支 `else if (dot < q_y) dot <= q_y` 每拍把光点拖到柱顶，
  使 `q_y > dot + HYST` 永不成立 → 超调永不触发。
- **修复**：移除死区分支，回到"超调(>+12) or 下落"二元逻辑。光点停在柱顶后，
  柱子缓升会被柱子追上（不拖光点），柱子涨过 +12 才重新超调——物理感正确。
- **验证**（dot_tb）：快升 0→100 → 光点跳 120；缓升 100→108 → 光点不被拖；再大涨 108→200 → 跳 240。

### 10.2 最右侧越界 bug 复活（数据源 clamp 到 127 喂错了数据）
- **现象**：右边 32px（768..799）重新画出 bar127 的柱子/光点。
- **根因**：这次把 `data_source` 的 `bar` clamp 到 127（防 RAM 越界），
  越界列（bar_raw 128..133）因此读到 `bar_h_ram[127]` 的真实高度（40）→ 右边有图。
  第一次修复时数据源越界列谐波为 0（q_y=0），所以右边是黑的。
- **修复**：越界列输出 0：`q_y = bar_val ? ram[bar_ok] : 0`，`bar_val = bar_raw<=127`。
- **验证**（verify_tb）：pix_x=770..794 → q_y=0，bar127(762) → 40 ✓。

### 10.3 附带：÷172800 组合除法器改乘法近似（时序余量 0→5ns）
- 二次综合时 `note_h_pipe` 路径 -0.839ns（除法器在 30ns 拍内差 0.8ns）。
- 用 `hp2 × 97 >> 24` 替代 `hp2 / 172800`（误差 0.12%，最大低估 0.5px），
  移除组合除法器 → 时序最差 **+5.012ns**，25 条 setup 全正。

## 十一、三次回归修复（2026-09-28 晚，上板后反馈2）

### 11.1 最右三列固定光柱（calc 流水越界写入）
- **现象**：bar 125/126/127 出现高度恒为 100 的光柱。
- **根因**：`calc_bar` 带越界钳位 `(calc_cnt<128)?calc_cnt:0`，
  但写 RAM 用 `bar_h_ram[calc_cnt-4]`。当 `calc_cnt=128..131` 时
  `calc_bar` 被钳成 **0** → 这 4 拍写入 index 124..127 时用的是 **bar0 的数据**
  （bar0 的 bass=40，放大×2.5=**100**）→ 最右 3 列恒显示 100 高度。
- **修复**：`calc_bar = {2'b0, calc_cnt}`（0..131），去掉钳位。
  写 index `calc_cnt-4` 天然 ≤127，无需防越界；流水对齐保证值正确。
- **验证**（frame_tb）：修复前 barh[125..127]=100 恒定；修复后全 0（当前音符无柱）✓
