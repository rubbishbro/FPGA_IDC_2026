## 一、系统全景：数据流

```
[50MHz晶振] → PLL → 33.33MHz pix_clk（像素时钟，每拍画一个像素）
                                    │
                     lcd_timing（扫描控制器）
                     │  每拍推进 H/V 计数器，产生：
                     │    pix_x(0..799), pix_y(0..479)   ← 当前画到哪
                     │    lcd_en(有效区=1)               ← 该不该显示
                     │    frame_pulse(每帧末尾1拍)       ← "一帧结束了"
                     ▼
                     data_source（数据源）
                     │  输入 q_x(列号) → 输出 q_y(柱高) + q_ov(超调目标)
                     ▼
                     lcd_draw（页面选择器）
                     │  page_sel=00 → FFT柱状图（lcd_fft）
                     │  page_sel=01 → 波形（lcd_wave）
                     ▼
                     top 输出寄存器 → lcd_r/g/b 引脚
```

**核心思想**：像素时钟每拍画一个像素，所有"该像素是什么颜色"必须在 30ns 内决定。
**任何重的计算都不能放在像素路径上**——这是整套设计最重要的原则。

## 二、lcd_timing.v：扫描控制器

```verilog
reg [15:0] H_PixelCount, V_PixelCount;
always @(posedge lcd_clk) begin
    if (H_PixelCount == 1192) begin V_PixelCount++; H_PixelCount = 0; end  // 一行结束
    else if (V_PixelCount == 533) begin V_PixelCount = 0; H = 0; end      // 一帧结束
    else H_PixelCount++;
end
```

- **一行 1192 拍** = 800 有效 + 210 前肩 + 182 后肩（LCD 协议消隐）
- **一帧 533 行** = 480 有效 + 45 + 8
- `frame_pulse = (V==533 && H==0)`：帧末尾最后一行发出。全局"换帧时钟"——音符、颜色、柱高重算全用它触发
- `pix_x = H - 182`：有效区 0..799，**消隐期冲到 800..1009**（踩坑来源，见六）

**手写要点**：计数器 + 比较器，注意 `H==1192` 先切行再清零的顺序，避免丢拍。

## 三、data_source.v：数据源（重构核心）

### 3.1 设计转变：从"每像素算"到"每帧算"

**原设计（bug 源头）**：每像素实时算柱高——
```
q_y = (h0+h2+h3) × env × note_amp ÷ 172800
```
36 位乘法 + 24 位组合除法器链到 87ns >> 30ns。光点每拍采样到未稳定中间值 → 乱飞。

**新设计**：柱高每帧算一次存 RAM，像素路径只查表：

```
每帧 frame_pulse 到来：
  calc_cnt 从 0 数到 131（128 柱 + 4 级流水延迟）
  每拍算一根柱高 → 存 bar_h_ram[0..127] 和 ov_ram[0..127]
像素路径（每拍）：
  q_y = bar_h_ram[bar]   // 一次 RAM 读，几个 ns 稳定
```

**为什么可行**：柱高由音符决定，音符每帧才变一次 → 柱高一帧内恒定 → 完全可预计算。
**"数据变化慢 → 预计算存 RAM"是通用技巧。**

### 3.2 音符系统（假数据）

```verilog
song_cnt      // 每帧 +1
note_idx = (song_cnt/32) % 8   // 每 32 帧换音符
note_pos     // 基频柱（8,26,42,60,78,96,112,120）
note_amp     // 幅度（200..110）
env = attack(0-5帧) / sustain(5-24帧) / decay(24-32帧)
```

**谐波结构**：基频峰(bar) + 2f峰(bar+14) + 3f峰(bar+28)，各 ±3 柱衰减，模拟多峰频谱。

### 3.3 4 级流水线（除法器的替代）

```verilog
级1:  hsum_pipe   <= h0+h2+h3              // 加法
级2a: hp1_pipe    <= hsum_pipe × env       // 12×10 乘法
级2b: hp2_pipe    <= hp1_pipe × note_amp   // 24×12 乘法
级2c: note_h_pipe <= hp2_pipe ÷ 172800     // ★除法在这
```

**除法改乘法近似**（关键技巧）：
```
hp2/172800 ≈ hp2 × 97 / 2^24   （97/2^24 = 5.78e-6 ≈ 1/172800）
```
乘法 ~10ns，右移 24 位免费。误差 0.12%，最大低估 0.5px，视觉无感。
**时序从 -0.8ns → +5ns。**

**手写要诀**：
- 除法 → `×常数 >> 移位`，先算 `2^n/除数` 得近似乘数
- 乘法链太长 → 拆寄存器流水
- **流水线索引要对齐**：N 级延迟，第 N 拍输出对应第 N-4 拍输入，写 RAM 索引必须 `cnt - N`

### 3.4 超调目标预计算

光点要"柱高×1.2"，同样每帧算好存 `ov_ram`：
```verilog
c_ov_c = clamp(c_bar_h_g × 12 / 10, 0, 479)
```
光点路径连乘法都没有，直接查 ov_ram。

### 3.5 像素路径：查表 + 寄存器输出

```verilog
bar_raw = q_x / 6              // 0..168（含消隐越界）
bar_val = (bar_raw <= 127)     // 越界列标记
q_y_c   = bar_val ? bar_h_ram[bar_ok] : 0    // 越界→0，右边黑
always @(posedge clk) q_y <= q_y_c;          // 寄存器输出
```

**两个关键决策**：
1. **越界列输出 0 而非 clamp 到 127**——否则最右 32px 显示 bar127（三列固定柱 bug 的另一来源）
2. **寄存器输出**（同步读）——128 项 RAM 异步读是大 mux（~10ns），寄存器摘掉它；1 拍延迟用 lcd_fft 打拍对齐补偿，且落在 LED 黑缝上不可见

## 四、lcd_fft.v：绘制层

### 4.1 柱体几何
```verilog
bar_idx = pxx / 6                      // 0..127（clamp）
in_bar  = q_y>0 && pxy >= 479-q_y      // 像素在柱体内（从底往上长）
```

### 4.2 LED 灯阵（颗粒感）
```verilog
dist_top = pxy - (479 - q_y)    // 距柱顶距离
yg  = dist_top % 5;  led_v = (yg <= 3)    // 4行灯+1行缝
xm  = pxx % 6;       led_h = (xm>=1)&&(xm<=4)  // 中间4列+两边黑缝
in_led = in_bar && led_h && led_v
```
这就是"光颗粒"。**"光点嵌入第 N 颗粒"= 光点停在柱顶以下第 N 组 LED。**

### 4.3 颜色：旋转彩虹
```verilog
// 每8帧 hue_shift+1，192步一圈 ≈ 29.5秒
color_idx = (bar_idx + hue_shift) mod 192
// 192 项 case 查表：红→蓝紫→青→黄→红
```

### 4.4 光点物理（小球超调+下落）——见第七节专讲

### 4.5 dot_en 门控
```verilog
dot_en = lcd_valid && (page_sel == 2'b00)
```
只在有效区 FFT 页更新光点，挡掉消隐期 pix_x 冲到 800+ 砸 bar127。

## 六、踩坑总结的设计原则（手写护身符）

1. **组合 vs 时序分清楚**：每拍都要的结果，若计算 >~15ns 就拆流水或预计算。像素路径只放比较/加法/RAM读/查表。
2. **除法器是毒药**：组合除法（大除数）30-50ns。换 `×常数>>位` 或移到帧级预计算。
3. **RAM 查表 = 免费加速**：数据变化慢 → 预计算存 RAM。
4. **异步 RAM 读是大 mux**：128 项 `ram[addr]` 是 128 选 1，~10ns。用寄存器读摘掉，打拍补偿延迟。
5. **流水线索引要对齐**：N 级流水，写 RAM 索引 `cnt - N`。错一拍 = 错一根柱（bar0 数据写进 bar124 的 bug）。
6. **越界列要么 0 要么明确处理**：clamp 到 127 会显示该柱数据。要"右边黑"就让它输出 0。
7. **位宽宁大勿小**：中间量用足够宽 reg（hp2 36位），`reg[6:0]` 装不下 130 是 bug。
8. **永远查时序报告**：RTL 仿真零延迟测不出时序违例，综合后必查 `timing_paths` slack >0。

## 七、光点算法详解（专题）

### 7.1 物理模型：手抛球
柱子 = 上升的手，光点 = 落在手上的球：
- 手追上球 → 把球抛到 1.2× 柱高（超调）
- 球被抛高后重力拉它下落（每 FALL_PERIOD 拍落 1px）
- 球落到手的位置停住（不低于柱顶）

### 7.2 状态机

```verilog
if (q_y > dot_ram[bar_idx])            // ① 柱高超过光点 → 抛到超调目标
    dot_ram[bar_idx] <= q_ov;
else if (dot_ram[bar_idx] > q_y)       // ② 光点高于柱高 → 下落
    if (fall_ram >= FALL_PERIOD-1) begin
        fall_ram <= 0;
        dot_ram <= (dot-1 > q_y) ? dot-1 : q_y;   // 不低于柱顶
    end else fall_ram <= fall_ram + 1;
    // ③ dot==q_y：停柱顶，不动
```

**三种状态**：顶起（有超调动画）/ 下落（重力）/ 停顶（静止）。
每柱一个 `dot_ram` + `fall_ram`，互不干扰。

### 7.3 为什么方案B（HYST取消）
原逻辑 `q_y > dot + 12` 才抛：柱高涨 1~12px 时球既不抛也不落，卡在柱体里
（视觉 = "光点嵌在 LED 颗粒里"，且高度相仿的柱"一半起跳一半不起跳"——
取决于上一拍状态）。改成 `q_y > dot` 就抛：球永远贴顶或在上方，不卡体。

副作用：attack 期柱子猛涨，球贴顶上升（物理合理，视觉可接受）。

### 7.4 参数

| 参数 | 作用 | 当前值 |
|---|---|---|
| `FALL_PERIOD` | 下落周期（越大越慢） | 1000（~19px/帧→很慢，可调）|
| `PEAK_FALL` | 每次下落 1px | 1 |
| `q_ov` | 超调目标 = 1.2×柱高（预计算） | — |
| `dot_en` | 只在有效区 FFT 页更新 | — |

### 7.5 光点绘制（独立于柱体）

```verilog
peak_h = dot_ram[bar_idx]
in_bar_col = (pxx 在 bar_idx 的 6px 列内)
is_peak_dot = in_bar_col && (pxy 落在 peak_h 的 4 行内)
// 优先级：光点(青白) > LED灯(柱色) > 黑缝
```
超调时光点在柱顶上方也能看到（不被 in_bar 门控）。

## 八、真 FFT 接口对接（专题）

**问：柱高是 source 里算的，是 bug 源头。如果换成真 FFT 输出，还有这个问题吗？**

**答：没有。真 FFT 的输出天然就是"帧级预计算"结构，正好符合重构后的架构。**

### 为什么

真 FFT 的工作流程：
```
音频采样(如48kHz) → 攒够一帧(如1024采样) → 跑 FFT(蝶形运算)
→ 得 512 个频率 bin → 映射到屏幕 128 根柱 → 更新柱高
→ 下一帧重复
```

关键点：**FFT 结果在"一帧采集+计算完成"后才变化**，频率 bin 是**帧级慢变数据**，
不是每像素变的。所以：
- FFT 计算（重的蝶形运算）发生在慢节奏的批量计算里，不占像素路径
- 像素路径只需要 `bar_h_ram[bar]` 查表——跟现在的架构一模一样

**现在假数据源把柱高算好存 RAM，这个 RAM 就是真 FFT 的输出缓冲。**
接真 FFT 时，只需替换 data_source 内部"计算柱高"的部分，用真 FFT 结果填充
`bar_h_ram` 和 `ov_ram`，**像素路径、光点、绘制完全不用动**。

### 真 FFT 需要额外处理（都在帧级做，不影响像素）

1. **对数缩放**：音频功率动态范围大（60dB+），用 dB 缩放后柱高才好看
2. **归一化**：FFT 原始 bin 值 × 系数 → 0..479 柱高
3. **峰值保持/衰减**：真 FFT 输出抖动大，可加平滑（每帧对旧值做泄漏积分）
4. **频段合并**：512 bin 合到 128 柱（每柱 4 bin 取 max/平均）
5. **超调目标**：同样每帧算 `1.2×柱高` 存 ov_ram

### 关键架构不变式

> **数据源输出 = 每帧更新一次的 RAM，像素路径 = 只查表。**

只要守住这个，光点、绘制、时序全部稳定。这正是这次重构的真正价值——
把"假数据"做成了"真 FFT 的接口形态"。
