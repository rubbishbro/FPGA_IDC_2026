## 0. 一页结论

1. **核心递推不用重做，L0 可以完全不改模态 bank 的算术。** B 与 A 共用
   `y[n] = G·x[n] − a1·y1 − a2·y2`；B 的差别在激励、包络、调制和生命周期。
   L0（静态 B）可以继续用 72-bit 系数 word、Q2.30 状态、4 lane、32×48 工作缓存和现有
   装载格式，只替换 `x_vec` 的来源并增加每声部控制。
2. **+29.6 音分是“全局移调”，不是“每音失谐”，前提是 A/B 用同一个采样率基准。**
   当前 A 用 48 kHz 系数、48.828 kHz 时钟，所有音一起高 29.6 音分、速度一起快 1.725%；
   只要 B 的 NCO 周期 `T` 和系数都按 48 kHz 基准确认，B 与 A 仍然同调。
   **千万不要**用 48.828 kHz 的 `T` 配 48 kHz 系数，也不要把 B 单独重生成到 48.828 kHz
   而与 A 混奏——前者让驱动/模态失谐，后者让 A/B 相差 29.6 音分。
3. **真正需要解决的是整数周期音准误差，而且它不只在“极高频”。**
   48 kHz 基准下：flute 42 个键中 17 个 >10 音分（最大 36.95），violin 37 个中 16 个
   （最大 36.95），oboe 35 个中 9 个，trumpet 32 个中 6 个，cello 49 个中 3 个。
   MIDI 81–103 是一个明显的“坏键簇”。L0 的 demo 应避开这些键；L1 的分数 NCO 是
   flute/violin 高音区的必要修复，不是可选优化。
4. **B 的尾音比想象中短：模态尾 0.6–3.7 s，含 release 的总尾 0.8–3.9 s，不是几十秒。**
   B 的 γ 在 2.3–50.6 s⁻¹，到 −74 dB 的模态尾音最慢也只有 3.70 s（cello）。
   因此 **12 声部的 B 控制池就够一个中等密度的 demo**；L0 用“每音定时器”回收即可，
   不需要每模态 quadrature 包络。32 声部不是 L0 的必需项。
5. **L0 比“完整 B”便宜得多：约 26–28 BSRAM、2 DSP 单元、3–4k FF/LUT。**
   因为 L0 不需要 a1 影子表、颤音/AM、粗糙度、噪声 FIR；B ROM 仍是 72-bit/模态，
   可以直接复用 A 的 72-bit 装载/工作缓存。**L1 也不再需要 96/120-bit 表**：
   `c1/c2` 已删除，a1 刷新用 `θ/r` + cos LUT，所以 L1 约 32–34 BSRAM、3–5 DSP 单元；
   L2 扩到 5 种全动态约 60–64 BSRAM。
6. **a1 刷新不是带宽问题，是原子性和 cos 精度问题。**
   每 96 采样更新 1,536 个 a1 = 16 个/采样（每 lane 约 1 个/采样），每次一次
   cos LUT + 1 mul；a1 影子 16 次写/采样。这些都在 1% 量级。真正要设计的是
   “每声部 48 个 a1 一次性生效”的 burst/影子表，以及低音模态的 cos 精度。
   **不再存 c1/c2**：note-on 从 a1/a2 反解 `θ/r`，tick 上直接算
   `-2r·cos(ratio·θ)`，任意 ratio 都成立，没有 ±50 音分的 Taylor 范围假设。
7. **当前 A 装载器的 216 周期/音和“装载/计算互斥”是实时 B note-on 的最大集成障碍。**
   540 周期的空闲窗口只够 2 个当前格式的音；B 需要 burst 装载（约 72 周期/音，7 个/窗口）
   或 4-word 并行装载（约 24 周期/音，22 个/窗口），或者 L0 直接预装固定 demo。
   L0 建议预装；L1 再做后台装载/抢占。
8. **“466 周期余量”不是 B 稳态的正确框架。**
   模态 bank 仍占 1508 周期；控制/刷新/噪声如果各自用独立 DSP/RAM，可以并行，
   不挤进这 466 周期。真正的共享串行资源是 **工作缓存的单端口**：1508 + 48×同时 note-on
   数。10 个同时 note-on 用 burst 装载是 1508+480=1988 < 2048，工作缓存端口刚好过；
   若 body 不能与装载并行，则 1508+74+480=2062，差 14 周期，9 音（2014）更稳，
   4-word（1628）则有余量。用当前 216 周期/音则是 1508+2160 > 2048，过不了。
   **能过的是装载带宽，不是乘法。**
9. **完整 B 的资源估算与汇报的 +40–50 BSRAM / +4–8 DSP 同量级，但那是含 120-bit ext 的旧口径；删掉 c1/c2 后 L1 更低。**
   我的自底向上：L0 约 26–28 BSRAM / 2 DSP 单元；L1 约 32–34 / 3–5；
   L2（含噪声、5 种全动态）约 60–64 / 5–10。整机 BSRAM 从 52 到 78/85/114，
   都远低于 340；**DSP/BSRAM 都不是瓶颈，时序才是。**
10. **最大风险仍是时序：当前 setup 最坏只有 +1 ps。**
    L0 的新逻辑基本在音频路径之外，但 32 组 `x_vec` 的扇出/布局会影响 bank；
    L1 的 a1 影子读是唯一进入模态递推关键路径的新逻辑（22-bit 2:1 mux），必须单独综合检查。
    不要用“DSP/BSRAM 还有余量”推断时序能过；每一级都要重新综合/P&R。

## 2. 物理层计算

### 2.1 采样率、周期与音高基准：29.6 音分的真相

硬件实际采样率：

\[
f_{s,hw}=48{,}828.125\ \text{Hz},\qquad
\frac{100\ \text{MHz}}{f_{s,hw}}=2048\ \text{周期/采样}.
\]

当前 A 的系数按 48 kHz 生成，硬件按 48.828 kHz 播放，因此：

\[
1200\log_2\frac{48828.125}{48000}=29.63\ \text{音分},
\qquad
\frac{48828.125}{48000}=1.01725\ (+1.725\%).
\]

这 29.6 音分是**全局移调**：所有音一起高，速度一起快 1.725%，音与音之间的相对关系不变。
它不是“每音失谐”。当前 A 歌曲接受这一点，是因为它单独播放时只是整体偏高。

B 的额外约束是：**驱动和模态必须用同一个基准**。

| 方案 | 系数基准 | NCO 周期 T 的基准 | 实际音高 | 每音音准误差 | A/B 同调 | 评价 |
|---|---|---|---:|---|---|---|
| **L0-48k（推荐）** | 48 kHz | 48 kHz | +29.6 音分全局 | ≤36.95 音分 | ✅ | 复用 A 表；最简单；音准误差是整数周期固有的 |
| L0-48.828k | 48.828 kHz | 48.828 kHz | 0（音乐会音高） | ≤52.88 音分 | ❌（A 仍 +29.6） | 高音整数周期误差反而更大；A/B 混奏会差 29.6 音分 |
| L1-分数 48.828k | 48.828 kHz | 48.828 kHz | 0 | ≈0（平均） | 需同时改 A | 音准最好；要新参考、重生成 A/B |
| 48k 音频时钟 | 48 kHz | 48 kHz | 0 | ≤36.95 音分 | ✅ | 需要 12.288 MHz 音频时钟/板级改动 |

**结论**：
- L0 用 **48 kHz 基准**：`T = round(48000/f0)`，`f_drive = 48000/T`，系数也按 48 kHz 生成。
  硬件 48.828 kHz 播放时整体 +29.6 音分，但与 A 同调；这是最省事、也最不容易出错的方案。
- 绝不能“系数 48 kHz、NCO 用 48.828 kHz 的 T”：驱动在目标音高、模态高 1.7%，
  稳态增益校准失效，音色会坏。
- 若 A/B 要同时存在，**B 不能单独搬到 48.828 kHz 音乐会音高**，否则 A/B 相差 29.6 音分。
  要搬就 A/B 一起搬（重生成 A 表或改音频时钟），这是系统级决定，不是 B 局部决定。

### 2.2 整数周期音准：逐乐器实测（48 kHz 基准）

`T = max(2, round(48000/f0))`，`f_drive = 48000/T`；误差
\[
e=1200\log_2(f_{drive}/f_0).
\]

| 乐器 | 键数 | 中位 \|e\| | p90 | 最大 | >10 音分 | >20 音分 |
|---|---:|---:|---:|---:|---:|---:|
| flute | 42 | 6.35 | 21.72 | **36.95** | 17 | 6 |
| oboe | 35 | 5.80 | 18.85 | 23.26 | 9 | 2 |
| violin | 37 | 6.31 | 24.26 | **36.95** | 16 | 7 |
| trumpet | 32 | 4.90 | 14.39 | 19.35 | 6 | 0 |
| cello | 49 | 2.49 | 6.50 | 16.35 | 3 | 0 |

坏键集中在 **MIDI 81–103**（A5 以上），与乐器无关，只由 `f0` 和 `48000` 决定。
例如 MIDI 81（880 Hz）固定 −14.4 音分，MIDI 88（1318.5 Hz）固定 +19.4 音分。
所以“低音通常 <5 音分、高音才差”这个说法要修正：**A5 以上就进入 >10 音分的区域**，
flute/violin 的常规高音区已经受影响。

如果改成 48.828 kHz 基准（重生成表），高音误差反而更大：

| 乐器 | 中位 | p90 | 最大 | >10 音分 |
|---|---:|---:|---:|---:|
| flute | 5.98 | 22.95 | 47.92 | 16/42 |
| oboe | 2.83 | 14.19 | 23.30 | 8/35 |
| violin | 6.29 | 28.14 | **52.88** | 16/37 |
| trumpet | 2.31 | 12.60 | 17.90 | 7/32 |
| cello | 1.56 | 8.35 | 15.25 | 5/49 |

原因：`Δf/f ≈ 1/(2T)`，而 `T = fs/f0`；同样的 `f0` 在更高的 `fs` 下 `T` 更小，
舍入误差更大。这就是为什么“L0-48k + 接受 29.6 音分全局”在音准上反而比
“L0-48.828k”更好：**全局移调是常数，整数周期误差才是音与音之间的错误。**

L0 的 demo 建议选 **cello 36–80、trumpet 51–80、flute 60–80** 这些 <10 音分的键；
高音留给 L1 的分数 NCO。

### 2.3 模态数、键数与 ROM 规模

| 数据集 | 乐器数 | 键数 | 模态词 | 说明 |
|---|---:|---:|---:|---|
| A（现有） | 4 | 250 | 5,483 | guitar/piano/banjo/mandolin |
| B 3 种 forte | 3 | 123 | **3,849** | flute/trumpet/cello；L0/L1 主预算 |
| B 5 种 forte | 5 | 195 | 5,519 | 加 oboe/violin |
| B 5 种全动态 | 5 | 288 | **7,624** | 含 mezzo-forte；L2 上界 |

每键模态数：flute 中位 17.5 / 最大 48；oboe 20/48；violin 17/48；trumpet 31/48；cello 48/48。

**ROM 组织建议**：
- A/B **分表**。A 5,483 < 8,192、B 3,849 < 8,192、B 5 全 7,624 < 8,192，
  所以 13-bit offset 在分表下仍够用；合并成 9,332/13,107 才需要 14-bit。
- B index 独立：3 种时 3×128×2=768 项；5 种时 5×128×2=1,280 项。
  3 种可以用 2-bit 乐器字段，和 A 的 index 格式相同；5 种需要 3-bit。
- B 的 72-bit 系数 word 与 A 完全同格式；L0 的 loader 只需换 ROM 源。
- L1 **不加宽 word**：a1 刷新在 note-on 从 `a1/a2` 反解 `θ/r`，之后用 cos LUT 算
  `a1=-2r·cos(ratio·θ)`；不存 c1/c2，也不需要 ext loader。

### 2.4 阻尼、尾音与声部占用

B 的 γ 比 A 的持续音大得多（B 是被持续激励的，自由衰减很快）：

| 乐器 | γ min..max (s⁻¹) | 模态尾到 −74 dB min..max | 含 release 的总尾 min..max |
|---|---:|---:|---:|
| flute | 3.45..32.2 | 0.62..2.47 s | 0.76..2.61 s |
| oboe | 4.60..50.6 | 0.93..1.85 s | 1.06..1.99 s |
| violin | 3.45..27.6 | 0.74..2.47 s | 0.88..2.61 s |
| trumpet | 3.45..32.2 | 0.93..2.47 s | 1.06..2.61 s |
| cello | 2.30..18.4 | 1.48..3.70 s | 1.62..3.89 s |

其中：
\[
t_{-74\,\text{dB}}=\frac{\ln(10^{74/20})}{\gamma}=\frac{8.52}{\gamma},
\qquad
T_{60}=\frac{6.91}{\gamma}.
\]
“总尾”按 Python 当前语义 `release_s` 直接当时间常数估算，并夹到 ≥0.02 s
（`_start` 的 `max(release_s, 0.02)`）：`6.9·max(release_s,0.02) + 8.52/γ_min`。
如果改成“90→10 时长 / ln 9”作为 τ，release 部分会短 2.2 倍，总尾主要由模态决定。

**声部占用公式**：
\[
N_{\text{voice}}\approx \text{note rate}\times \text{tail}.
\]
8 音/秒 × 1.5 s ≈ 12 声部；4 音/秒 × 1.5 s ≈ 6 声部；最坏 cello 3.9 s 时，
12 声部支持约 3 音/秒的持续释放音。对一个中等密度的 B demo，**12 声部足够**；
32 声部只有在密集和弦/长尾叠加时才需要。

**L0 回收建议**：每音在 key metadata 里存 `tail_samples`（按 `γ_min` 和 release 预算），
note-off 后倒计时，到 0 清状态、回收槽位。这个判据是保守的（不会提前回收），
代价是可能多占一点时间；以 B 的尾音长度，12 声部池完全承受得起。
不需要每模态 quadrature 包络的 1536 次开方/除法；那是 L1 如果要做更激进回收时才考虑。

### 2.5 稳态增益与定点格式

B 的增益不是 A 的脉冲增益，而是“单位冲激串的稳态幅度”：

\[
A_{\text{peak}}(k)=\max_j r_k^j\left|\operatorname{Im}
\frac{e^{i\theta_k(j+1)}}{1-R_k e^{i\phi_k}}\right|,\quad
R_k=r_k^{T},\ \phi_k=\theta_kT,
\]
\[
G_k=\frac{w_k}{A_{\text{peak}}(k)},\qquad
w_k=\frac{a_{0,k}}{\max_j a_{0,j}}.
\]

用户已做的静态校准（关颤音/AM/粗糙度/噪声）中位误差 0.03–0.17 dB、最大 1.24 dB（oboe），
说明这个增益推导和整数周期驱动是对得上的；这是“静态校准”，不是音色验收。

本次只读复核的定点范围（3 种 forte，3,849 词；全 5 种 7,624 词同量级）：

| 项 | 范围 | 格式 | 结论 |
|---|---:|---|---|
| G | 1.67e-6 .. 1.01e-2 | Q2.24 | 最小 28 LSB，不会量化为 0；最大相对误差 1.75%（p99 0.44%） |
| a1 | −1.99969 .. 0.99976 | Q2.20 | 最大 \|a1\| < 2，留 0.00031 余量；低音 cello 的静态量化 ≤2.6 音分，±22 c 调制后 ≤3.8 音分 |
| a2 | 0.997893 .. 0.999904 | UQ0.24 | 不接近 1 的上界；最大相对衰减误差约 2.6e-4 |
| 量化后极点 | 全部共轭、\|z\|<1 | — | 用户 7,624 条扫描 0 条不稳定 |
| G 的 dB 误差 | ≤0.15 dB（p99 0.038 dB） | — | 对主导模态可忽略 |

（汇报里 3 种 B 的 G 约 4.23e-7..9.09e-3，来自另一候选集；两边都未量化为 0，
结论不变。）

**B 不需要新的 a1/a2/G 格式**；沿用 A 的 72-bit word 即可。L0 的静态 B 只需把
`G` 换成 B 的 `G`、`a1` 按整数周期 `T` 生成，其余位宽不动。

### 2.6 包络：attack / release、Q 格式与 3.8 s 异常

Python 的包络是一阶指数趋近：

\[
e[n+1]=\text{target}+(e[n]-\text{target})\,\alpha,\qquad
\alpha=e^{-1/(f_s\tau)}.
\]

- gate 开：target=1，α=α_attack；
- gate 关：target=0，α=α_release；
- **release 只乘在驱动上，不乘在模态输出上**；note-off 后模态按 γ 自由衰减。
  这是当前参考语义，不是“输出淡出”。要改就是算法选择，必须重新对拍。

逐乐器 attack/release 分布（3 种 forte 候选）：

| 乐器 | attack 中位/最大 | release 中位/最大 |
|---|---:|---:|
| flute | 48 ms / **3.799 s** | 4 ms / 28 ms |
| oboe | 12 ms / 287 ms | 4 ms / 30 ms |
| violin | 51 ms / 1.469 s | 11 ms / 73 ms |
| trumpet | 29 ms / **2.841 s** | 3 ms / 16 ms |
| cello | 212 ms / 546 ms | 11 ms / 86 ms |

表中是原始提取值；引擎把 release 夹到 **≥0.02 s**，所以多数键的实际 release 是 20 ms，
不是 3–11 ms。硬件整数参考要复现这个夹取，否则尾音/回收会比 Python 短。

3.799 s（flute G♯6 `very-long`）和 2.841 s（trumpet E4 `very-long`）是极端值，
很可能是“长音渐强/起音检测”而不是真实 attack；L0 如果用到这些键，需要先复核提取。
**这不影响 Q 格式**：env 用 UQ0.32，LSB 2.33e-10；3.8 s attack 的 `1−α=5.48e-6`
在 env 增量里约 23,534 LSB，慢起音不会卡在 0。α 用 UQ0.24，LSB 5.96e-8，
`1−α` 仍有 92 LSB，也够。原始 release 可能只有 0.001 s，但引擎夹到 ≥0.02 s；
0.02 s 的 `1−α=0.00104`，Q 格式更没有问题。

**Q 格式建议**：
- env：UQ0.32（32-bit unsigned）；α：UQ0.24（24-bit unsigned）。
- 更新用 `env += (target-env)*(1-α)`；`target-env` 是有符号 32-bit，
  `1-α` 是 UQ0.24，64-bit 积右移 24，四舍五入，饱和到 [0,1]。
- 不要用 16-bit α；慢 attack 的增量会被舍成 0，正是之前 Python 注释里警告的坑。

### 2.7 颤音 / AM：更新率、Taylor 展开与误差

当前 Python：颤音 5.2 Hz、22 音分、AM 0.14；`coef_interval=96` 采样（约 2 ms，500 Hz 更新）；
LFO 每采样推进，AM 逐采样，音高系数每 96 采样采样保持。硬件要对齐这个语义：

| 量 | 硬件做法 | 代价 |
|---|---|---|
| LFO 相位 | 每声部 24/32-bit 相位累加器，每采样加 `f_vib/fs` | 32 次加法/采样 |
| sin | 1024×16 LUT + 线性插值（或 2 阶多项式） | 32 次读/采样，1 BSRAM |
| cents → δρ | `δρ = cents·ln2/1200`，一次乘常数 | 32 次/控制 tick |
| NCO 增量 | `inc = base_inc·(1+δρ)` | 32 次/控制 tick |
| a1 刷新 | `a1 = -2r·cos(ratio·θ)`（θ/r 在 note-on 反解） | 1 模态/采样/lane：cos LUT + 1 mul |

**关键简化：a1 不需要 CORDIC，也不需要存 r/k 现算 cos。** 在标称 ρ=1 处 Taylor 展开：

\[
a_1(\rho)=-2r\cos(\rho\theta),\qquad
a_1\approx a_{1,0}+c_1(\rho-1)+c_2(\rho-1)^2,
\]
\[
c_1=2r\theta\sin\theta,\qquad c_2=r\theta^2\cos\theta.
\]

本次扫描的误差（相对精确 `-2r cos(ρθ)`，换算成频率音分）：

| 颤音深度 | 一阶最大 | 二阶最大 | Q2.20 量化最大 |
|---|---:|---:|---:|
| ±10 音分 | 0.036 c | 0.0002 c | ≤0.2 c（cello 最低音 3.5 c） |
| ±22 音分 | 0.17 c | 0.0027 c | ≤0.37 c（cello 最低音 3.75 c） |
| ±50 音分 | 0.92 c | 0.033 c | ≤0.63 c（cello 最低音 3.2 c） |

（cello 的 3.75 c 来自调制后 a1 的 Q2.20 量化，不是 Taylor 的错；
这与 A 类低音 a1 量化的既有误差同源。）

**更新（v0.3）：不再存 `c1/c2`。** 上面的 Taylor 展开只用于误差评估；L1 改为在 note-on 从 `a1/a2` 反解 `r = sqrt(a2)`、`θ = acos(-a1/(2r))`，每次控制 tick 直接算：

\[
a_1(\rho)=-2r\cos(\rho\theta),\qquad \rho=2^{\text{cents}/1200}
\]

`a2 = r²` 不变。这样任意 `ratio`（颤音/滑音/弯音）都成立，不再有 ±50 音分的 Taylor 范围假设；新增的是 `θ/r` 缓存（或每 tick 反解）和一个 cos LUT，删掉的是 48-bit/模态的 ext ROM。

| 字段 | 格式 | 说明 |
|---|---|---|
| a1_nom | Q2.20 | 仍从 72-bit ROM 读 |
| θ | UQ2.14 16-bit | note-on 反解一次，或每 tick 反解 |
| r | UQ0.24 24-bit | note-on 反解一次 |
| ratio | UQ1.16 16-bit | 表情层输出 |
| a1_new | Q2.20 | `-2r·cos(ratio·θ)`，四舍五入、饱和到 ±(2−2⁻²⁰) |

**原子性**：一个声部的 48 个 a1 必须在它下一帧之前全部换成新值；不能“前 20 个新模式、后 28 个旧模式”地混一个采样。做法见 §5.1。

### 2.8 粗糙度：控制率实现，成本被高估了

Python 的粗糙度不是每模态独立噪声，而是每声部 10 个随机低频正弦的和，
乘到**整个声部输出**上：

\[
y_{\text{out}}=y\cdot \exp(\text{roughness}\cdot r(t)-\tfrac12\text{roughness}^2),
\qquad r(t)=\frac{1}{\sqrt{K/2}}\sum_{k=1}^{10}\sin(2\pi f_k t+\phi_k).
\]

关键点：
- 10 个 LFO 在 `coef_interval=96` 才更新一次，不是每采样。
- 增益是**声部公共**的，可以加在声部求和之后，不需要每模态乘一次。
- 因此硬件代价不是“32 声部 × 10 LFO × 每采样”，而是：
  - 10 个 LFO/声部 × 32 / 96 ≈ 3.3 个复乘/采样；
  - 声部输出增益 32 次/采样；
  - 一个 32×10 的频率/相位表（约 10 kbit，1 BSRAM）。

这比“每声部 10 个随机 LFO 很贵”的直觉低一个数量级。L1 可以先做 1–2 个 LFO/声部
（更省表、听感接近），L2 再做 10 个。真正需要冻结的是 RNG/表：Python 用
`np.random.default_rng(seed)`，硬件要用可复现的 LFSR/表，否则无法逐位对拍。

### 2.9 噪声：最大的频谱差距，但资源没有想象中可怕

用户已有的整模/录音对比（15 个音）：

| 指标 | 结果 |
|---|---|
| 1/3 倍频程中位误差 | 12/15 个 ≤1.2 dB；violin G7 5.1 dB、flute F7 16.2 dB |
| 谐波幅度误差（>−45 dB） | 正常音域中位 0.0–2.3 dB，p90 ≤5.7 dB |
| 2–8 kHz 噪声底（模型−录音） | −4.9 .. −68.8 dB，多数 −10 .. −35 dB（模型更干净） |
| 包络起伏 CV | 模型 0.10–0.52，录音 0.06–0.77 |
| 单声部峰值 | 约 2–5（cello A3 完整表情 5.07） |

flute A4 把 `noise_gain` 从 0 调到 1.0：1/3 倍频程中位误差 1.29→0.58 dB，
噪声底差距 −29.5→−6.2 dB。**噪声是 B 最大的音色缺口**，但 G6 已决定默认关闭；
L0/L1 不做，L2 再评估。

资源上要纠正一个容易吓人的数字：3 种乐器 × 257 tap = 771 MAC/采样，
但：
- 噪声流是**每乐器一条**，不是每声部一条；
- FIR 可以对称折叠：129 MAC/乐器，3 种 = **387 MAC/采样**；
- 可以放在**独立 DSP + 独立 BSRAM**，不挤模态 lane 的 466 周期余量；
- 3 条并行时每条 129 MAC/采样（约 6.3% 占空比），或 1 条共享 387 周期/采样（约 19%）。

存储：折叠系数 3×129×24 ≈ 9.3 kbit，历史 3×257×32 ≈ 24.7 kbit，合计约 34 kbit
≈ 2–3 BSRAM（未折叠系数 18.5 kbit，合计约 4 BSRAM）。所以 L2 的噪声是
**约 2–3 BSRAM + 1–3 个 DSP 原语 + PRNG/分布定义**，不是“吃掉大部分时序余量”。
真正的风险是 PRNG/高斯分布/对齐（Python 用 `standard_normal` 和居中卷积），
需要按整数参考逐位验，再按谱形/RMS 对浮点。

### 2.10 驱动：整数计数器 vs 分数 NCO + 脉冲整形

| 方案 | 音高 | 实现 | 适用 |
|---|---|---|---|
| 整数计数器 | `f=fs/T`，整数周期误差 ≤36.95 c（48k） | 每声部一个 down-counter，到 0 发脉冲并重装 T | L0 |
| 分数相位累加 | 平均频率精确，但脉冲落在最近采样，有 ±0.5 采样抖动 | 24/32-bit 相位，wrap 发脉冲 | L1 颤音（必须能连续改周期） |
| 分数 NCO + 脉冲整形 | 平均频率精确，谐波增益平坦 | 相位 + 分数延迟 δ + 4/6/8-tap Lagrange/sinc | L2 高保真 |

L0 用整数计数器，和 Python 的 `T=round(48000/f0)` 完全一致；首脉冲在开音后
第 **T−1** 个采样（0 基），因为 Python 是 `phase += 1/T` 后判 `>=1`。这个细节要写进
整数参考和 RTL 测试，否则会差一个采样。

L1 的颤音必须连续改周期，所以要用分数相位累加。这里有一个容易忽略的坑：
**单采样冲激 + 分数相位 = 脉冲位置抖动**。对高次谐波，抖动会引入
`cos(πkδ)` 类的幅度/相位调制，δ 接近 0.5 时某些谐波会被抵消。
L1 如果只做“分数 NCO + 最近采样冲激”，必须用频谱/听感验收高次谐波；
L2 用 6–8 tap 分数延迟整形把谐波增益拉平（目标 ±0.05 dB 到 16 kHz），
再用 `G` 的离线校准吸收残余。整形器每个周期只算一次脉冲，平均 MAC
≤ 8·f0/fs ≈ 0.5 MAC/采样/声部，代价很小；代价在设计和验证。

## 3. 算力、带宽与时序预算

### 3.1 每采样周期账

100 MHz / 48.828 kHz = **2048 周期/采样**。当前 engine 最坏 1508，body 约 74，
串行余量 466。B 的稳态各块如下（**不是全部相加**，见 §3.5）：

| 资源 | 稳态 B 占用 | 说明 |
|---|---:|---|
| 4 条 modal lane（DSP+RAM） | **1508 周期** | 与 A 相同，B 不改递推 |
| B 控制 DSP | **约 144–176 MAC/采样** | env 32 + env·vel 32 + ·amp 32 + roughness 32 + refresh 16（cos+mul） + sin 插值 0–32 || B 控制周期（若 1 MAC/cycle） | 160–192 周期/采样 | 只占 7.8–9.4%；可独立 DSP |
| a1 影子读 | 1536 次/采样 | 每模态 1 次；4 lane 各 384，与 72-bit 读并行 |
| a1 影子写 | 16 次/采样 | 每 96 采样 1536 次 |
| B ROM 读（刷新） | 16 次/采样 | 每次 72 bit（a1/a2） |
| B ROM 读（装载） | 48 次/音 | burst 1 word/cycle |
| 工作缓存写（装载） | 48 次/音 | 与 lane 读共享单端口 |
| 噪声 FIR（L2） | 387 MAC/采样（折叠） | 独立 DSP；不占 lane |
| body | 74 周期 | 只处理 A 和 |

### 3.2 乘法账

- 模态核心：`3 × 1536 = 4608` 乘/采样 = 225 M 乘/秒。
  4 条 lane、每条 1 乘/周期 = 400 M 乘/秒峰值，占用 **56%**。
- B 控制（不含刷新）：约 128 乘/采样 = 6.25 M 乘/秒 = 0.0625 乘/周期（按 100 MHz 算）。
- a1 刷新：16 更新/采样 × 2 MAC = 32 乘/采样 = 1.6 M 乘/秒。
- 噪声（L2）：387 乘/采样 = 18.9 M 乘/秒 = 0.189 乘/周期；一条 DSP 约 19% 占空比。
- 合计新增（不含噪声）：128+32 = **160 乘/采样 = 7.8 M 乘/秒**；若 sin 用 LUT+插值
  再加 32，最多 192 乘/采样 = 9.4 M 乘/秒，仍**不到 0.1 乘/周期**。
  纯算术上，B 控制只需要 1 条 100 MHz 乘法通道的 8–10% 左右。

### 3.3 存储访问账

- 工作缓存：1536 模态 × 3 访问（系数读、状态读、状态写）= 4608 次/采样。
  4 lane 各 1152 次/采样；每 lane 一个单端口，2048 周期里占 56%。
- a1 影子：每模态 1 次读 = 1536 次/采样（4 lane 各 384），加 16 次写/采样。
  读与 72-bit 系数读**并行**（不同 RAM），不占同一端口。
- B ROM：刷新 16 次/采样 + 装载 48 次/音；1 次/周期够用，占用 <1%。
- B index/key metadata：只在 note-on 读，摊薄后可忽略。
- 结论：**存储带宽不是瓶颈；单端口工作缓存的冲突只发生在 note-on 装载**。

### 3.4 Note-on 装载：当前 216 周期/音，B 需要什么

当前 `coeff_loader` 的 `4n+24`：n=48 时 **216 周期/音**。B 在一个采样内可能同时来多个
note-on（和弦）。三种装载方式：

| 方式 | 周期/音（n=48） | 540 周期窗口可装 | 10 音和弦 | 评价 |
|---|---:|---:|---:|---|
| 当前 4 周期/模态 | 216 | 2 音 | 2160 > 2048 ❌ | 只适合启动预装 |
| burst 1 word/cycle | 48+24 ≈ 72 | 7 音 | 720 ✅ | 推荐 L1 |
| 4-word 并行（4 lane） | 12+12 ≈ 24 | 22 音 | 240 ✅ | 更稳，改动稍大 |
| L0 启动预装 | — | — | 无实时装载 | 推荐 L0 |

L0 的固定 demo（≤12 个同时声部、≤12 个不同键，一槽一键）可以在启动时预装，播放期间只做
gate/包络/回收，**完全避开实时装载**。这是 L0 最重要的简化。
L1 再做后台 burst 装载：利用 bank 每个采样的 540 周期 IDLE 窗口，写非活动 voice 的槽；
写完置 `coeff_loaded`，控制再激活。10 音和弦的 480 次写 < 540，刚好过；11 音 528 也过；
12 音 576 需要分两个采样（延迟 40 µs，听感无影响）或 4-word 并行。
注意：540 是 bank 的 IDLE 窗口；body 与 loader 不共享 RAM，通常可并行。
如果按最保守“body 也占窗口”的串行预算，可用窗口是 466 周期，10 音 burst（480）
差 14 周期，9 音（432）刚好；4-word（120）在任何情况下都过。

### 3.5 最坏帧与“周期不能直接相加”

B 的稳态各块跑在不同资源上：
- 4 条 lane 的 1508 周期是**并行**的 4 条，不是 4×1508；
- 控制 DSP 的 160–192 MAC、刷新引擎的 32 MAC、噪声 DSP 的 387 MAC 是**不同乘法通道**；
- a1 影子读/写是**不同 RAM 端口**；
- 只有工作缓存的单端口是 lane 读和 note-on 写共享的。

因此正确的 worst case 是：

| 场景 | 工作缓存端口 | B ROM 端口 | 结果 |
|---|---:|---:|---|
| 稳态 1536 模态 | 1508 | 16（刷新） | ✅ |
| 稳态 + 10 音和弦 burst | 1508+480=1988 | 16+480=496 | ✅ 工作缓存端口余 60；若 body 串行则 2062，差 14 |
| 稳态 + 10 音和弦 当前格式 | 1508+2160=3668 | — | ❌ |
| 稳态 + 10 音和弦 4-word | 1508+120=1628 | 16+480=496 | ✅（余 420） |
| 稳态 + L2 噪声 | lane 不变；噪声独立 DSP 387 | — | ✅（不共享 lane） |

**结论**：B 的稳态能过 2048，前提是：
1. 控制/刷新/噪声不挤进 modal lane 的乘法器；
2. note-on 用 burst/4-word/预装，而不是当前 216 周期/音；
3. 10 音以上的同时装载要么分采样，要么预装。

### 3.6 时序：+1 ps 基线下真正的风险

当前 v5 的 setup 最坏 **+0.001 ns**，hold 0 违例。这意味着：
- **没有任何余量吸收新增的组合逻辑/扇出/布线拥塞。**
- L0 的新逻辑（NCO、env、tail、event、x_vec mux）大部分在音频路径之外，
  但 `x_vec` 是 32×32 的宽 mux，扇出到 bank 的 32 个 voice 选择；布局不好会影响 bank。
- L1 的 a1 影子读是**唯一进入模态递推关键路径的新逻辑**：72-bit 系数读之外再加一个
  22-bit RAM 读，然后在 ph1 前与 packed a1 做 2:1 mux。它不增加 RAM 访问周期
  （两个 RAM 并行），但增加一级 mux；必须单独综合确认。
- 刷新/装载/LFO 都可以多周期/流水，不在音频关键路径。
- **不要**用“DSP 14/298、BSRAM 52/340”推断时序能过。当前瓶颈是控制译码、高扇出、
  实际布线，不是面积。

建议的时序门：
1. L0 控制单独综合，看 Fmax；
2. L0 + bank 集成，B 关闭，确认 A 逐位不变且时序不低于基线；
3. L0 + bank，B 开启，测最坏帧和 Fmax；
4. L1 加 a1 影子后再重复 2/3；
5. 每一步都用真实 Gowin P&R，不用“资源够”代替。

## 4. 资源估算

估算假设：
- BSRAM 18,432 bit/块；
- pROM 效率沿用当前 A ROM 的约 **63%**（5,483×72=394,776 bit / 34 块）；
- 1 个 `MULT27X36` 原语按 **2 个 DSP 资源单元**计（当前 7 原语 = 14 单元）；
- 不包含布线/控制逻辑的最终优化，实际以综合报告为准。

### 4.1 BSRAM

| 项 | 计算 | 块数（@63%） | 适用 |
|---|---:|---:|---|
| B ROM 72-bit（3 种 forte） | 3,849×72=277 kbit | **24** | L0/L1 |
| B ROM 72-bit（5 种全动态） | 7,624×72=549 kbit | 47 | L2 |
| B index（3 种，768×32） | 24.6 kbit | 3 | L0/L1 |
| B index（5 种，1,280×32） | 41.0 kbit | 4 | L2 |
| B key metadata（123×80） | 9.8 kbit | 1 | L0 |
| B key metadata（288×80） | 23.0 kbit | 2 | L2 |
| a1 影子（4 lane × 384×22） | 33.8 kbit | 4（每 lane 1 块） | L1 |
| sin LUT（1024×16） | 16.4 kbit | 1 | L1 |
| roughness 表（32×10×32） | 10.2 kbit | 1 | L1/L2 |
| 噪声系数（折叠 3×129×24） | 9.3 kbit | 1 | L2 |
| 噪声历史（3×257×32） | 24.7 kbit | 2 | L2 |

**汇总**：

| 级别 | B 增量 BSRAM | 整机（52+） | 说明 |

L0 的 26 对应 20-bit index（1 块）+ 紧凑 key 表；28 对应 32-bit index（3 块）+ key 表。
L1/L2 的区间来自 index/key 表的打包方式，实际以综合报告为准。L1 不再有 96/120-bit 表：`c1/c2` 已删除，a1 刷新靠 `θ/r` + cos LUT。

### 4.5 与汇报的 +40–50 BSRAM / +4–8 DSP 对照

- 汇报的 **+40–50 BSRAM / +4–8 DSP / 整机 92–102** 对应的是**含 120-bit ext 的旧 L1/L2**。
  删掉 `c1/c2` 后，L1 的 BSRAM 降到 **32–34**，整机约 **84–86**；L0 仍是 26–28 / 78–80。
- **L0 只需要 26–28 BSRAM / 2 DSP**，因为 L0 不做 a1 影子、LFO、噪声。
- 5 种全动态在新口径下是 60–64 块（不是 93–97），整机约 112–116；容量更宽松，
  但建议 L0/L1 先 3 种 forte，L2 再扩 5 种全动态。

## 5. 架构取舍

### 5.1 a1 刷新：22-bit 影子 vs 72-bit 双缓冲 vs 原地写

三个方案：

| 方案 | 做法 | BSRAM | 音频路径影响 | 原子性 | 评价 |
|---|---|---:|---|---|---|
| **S1 22-bit 影子（推荐）** | 每 lane 一块 22-bit×384 的 SDP RAM；lane 读 a1 时 class 选择影子/packed；刷新引擎写影子 | **4** | 加一个 22-bit 2:1 mux | 每声部 48 个写完再让下一帧读 | 最省；A 路径不变 |
| S2 72-bit 双缓冲 | 工作缓存深度×2，bank 选择位；刷新写非活动 bank，控制 tick 翻 bank | +6~7 | 地址多 1 位，读路径不变 | 翻 bank 原子 | 干净但更贵；改工作缓存 |
| S3 原地写 | 刷新直接改 packed word 的 a1 字段 | 0 | 无 | 需要暂停该声部或容忍混代 | 不推荐；单端口冲突/混代 |

S1 的细节：
- 影子每 lane 384×22 bit（32 voice × 12 local mode），4 lane 共 33.8 kbit；每 lane 一块
  512×36 BSRAM，4 块（每 lane 独立读口）。影子只存**刷新后的 a1**；`θ/r` 另存
  （见下）或每 tick 从 a1/a2 反解。
- 读：lane 在 ph0 读 a1 影子，与 72-bit 系数读并行；ph1 捕获 `ctx_a1`；ph2 用。
- 写：刷新引擎每个控制 tick 对一个声部做 48 次写；loader 在 note-on 时写 48 次
  a1_nom。两个写源用优先级仲裁。
- 刷新算式：`a1 = a1_nom·cos(δθ) + s·sin(δθ)`，`δθ=(ratio−1)·θ`，`s=sqrt(4a2−a1²)`；
  `ratio` 来自表情层。`θ` 用 14-bit mini-float（4-bit 指数 + 10-bit 尾数）放在 a1 影子
  的剩余位宽（512×36 里 22-bit a1 + 14-bit θ）；`r` 不存，由 `sqrt(4a2−a1²)` 现算。
  ρ=1 时 δθ=0，`a1` 精确等于 `a1_nom`，没有 acos→cos 的往返误差。
- 原子性：刷新任务在该声部当前帧结束后启动，deadline 是下一采样该声部的帧开始
  （约 2048 周期后）。48 次写 + 48 次 cos/sin 在 96 周期内完成，余量 >1900 周期。
- 读写碰撞：同一地址同拍读写时读旧值；当前采样继续用旧 a1，下一采样用新 a1，
  与“控制更新在帧边界生效”一致。不同声部地址不同，不会互相影响。
- class mux：A 走 packed a1，B 走影子；B 关闭时 A 路径逐位不变。这是 S1 相对 S2 的
  最大优势。

**状态跳变补偿**：暂不做。a1 换值时 `y[n]` 会多出 `(a1_old−a1_new)·y1`；小颤音听不出，大滑音可能有台阶。保持现状的好处是 Python 参考不用改、T-B03 仍可逐位；将来要补时，用“换值那个采样仍用旧 a1、下一采样再用新 a1”的延迟一代切换，或每模态加一次补偿，并同步改 Python。

**刷新调度**：32 个声部、每 96 采样一次，平均每 3 采样一个声部 burst；每个 burst
48 次更新。cos LUT 吞吐足够（1 次/采样/lane），1 mul/cycle 时 48 周期/burst；
平均 16 周期/采样。影子 48 次写/burst。都在 2048 周期内绰绰有余。
**不需要“每个采样 16 个 a1 均匀散开”**；每声部一次性 burst 反而更简单、原子性更好。

### 5.2 音高：整数 vs 分数

见 §2.1/§2.2/§2.10。建议：
- **L0**：整数计数器，48 kHz 基准，接受 +29.6 c 全局和 ≤36.95 c 每音误差；
  demo 避开 MIDI 81–103 的坏键。
- **L1**：先只加颤音（分数相位），不承诺音乐会音高；如果 A/B 要同调，保持 48 kHz 基准，
  颤音只做相对音高变化。
- **L2**：分数 NCO + 6–8 tap 整形，A/B 一起搬到 48.828 kHz 或改 48 kHz 音频时钟；
  这时才谈“准确平均音高”。

如果只做 B-only demo，L1 可以直接用 48.828 kHz 分数 NCO 得到音乐会音高；
但一旦和 A 混奏，必须回到同一基准。**这是系统级冻结项，不是 B 模块内部能决定的。**

### 5.3 包络与回收：定时器 vs quadrature

| 方案 | 代价 | 优点 | 缺点 |
|---|---|---|---|
| **每音定时器（L0 推荐）** | 每声部 20-bit 计数器 + key metadata 的 tail | 简单、确定、不会提前回收 | 保守，可能多占尾部 |
| 每声部输出峰值检测 | 32 abs/比较 + hold | 便宜 | 过零点/拍频可能低估 |
| 每模态 quadrature E（Python 当前） | 1536 次/采样的乘/除/开方（或降到每 96 采样 64 MAC/采样） | 相位无关的严格上界 | 贵；时变颤音下不是严格未来界 |

B 的尾音只有 0.8–3.9 s（含 release），12 声部池足够；L0 用定时器即可。
定时器的 `tail_samples` 按 `6.9·max(release_s,0.02) + 8.52/γ_min` 预算，存在 key metadata 里；
note-off 后倒计时，到 0 发 clear。阈值可以用 −60 dB 代替 −74 dB，尾音再短约 30%，
但要以听感/对拍为准。

### 5.4 声部池：12 vs 32；是否抢占

| 方案 | FF | 可支持 | 适用 |
|---|---:|---|---|
| 12 声部 B 控制池 | 2–4k | 8 音/秒 × 1.5 s ≈ 12；最坏 cello 约 3 音/秒 | L0/L1 demo |
| 32 声部 B 控制池 | 6–9k | 21 音/秒 × 1.5 s | 密集和弦/L2 |

B 控制池不需要等于 bank 的 32 个槽；可以用 12 个 B 控制项映射到 32 个 bank 槽。
L0 固定 demo 用 12 个预装槽，满池拒绝/丢弃，不抢占。
12 声部 demo 的 bank 周期约为 1508×12/32 ≈ 566（线性估计；1508 是 32 声部最坏），
所以 L0 的时序/装载余量比 32 声部最坏情况更宽；实际以仿真测量为准。
L1 再加软抢占：优先抢已 release、包络最低的槽；8 ms 淡出；同采样先 off 后 on。
A/B 共存时，bank 的 32 槽要预留 B 的 N_B 个；如果 A 歌曲占满 32，B 无法插入。
这是 L1 的系统调度问题，不是 B 控制单方面能解决的。

### 5.5 Note-on 装载：预装 vs 后台 vs 4-word

见 §3.4。建议：
- **L0**：固定 demo，启动预装，播放期间不装载。
- **L1**：后台 burst（1 word/cycle，约 72 周期/音），利用 540 周期 IDLE 窗口；
  10 音和弦 480 次写，刚好过；12 音以上分采样或 4-word 并行。
- **L2**：4-word 并行（4 lane 同时写，约 24 周期/音），留足余量给 A+B 同时装载。

当前 `coeff_loader` 的 `4n+24` 要改成 burst 模式；这是 L1 的一个明确 RTL 任务。
另注意当前 `modal_poly_bank` 的 `cfg_ready = idle && !clear_valid`，`busy` 覆盖整帧；
后台装载必须在 IDLE 窗口内完成，或者改成“允许写非活动槽”的并发 cfg。
L0 预装不需要改这个；L1 需要。

### 5.6 粗糙度：关 / 1–2 LFO / 10 LFO

- L0：关。
- L1：1–2 个 LFO/声部，控制率更新，乘到声部输出；听感接近，表和乘法都省。
- L2：10 个 LFO/声部，按 Python 语义；32×10 表 + 3.3 复乘/采样，代价可接受。
无论哪级，都要冻结 RNG/表，不能用 `np.random` 直接对拍。

### 5.7 噪声：G6 关闭 vs L2

- L0/L1：**保持 G6 关闭**；这是当前决定，且 L0/L1 的目标是先把整数链跑通。
- L2：再评估。资源不是主要障碍（约 2–3 BSRAM + 1–3 DSP 原语）；
  主要工作是 PRNG/高斯分布/对齐，以及“每乐器一条 FIR、max-env 调制”的架构。
- 如果 L2 不做噪声，要明确“当前 B 不是全保真”，不要用 1/3 倍频程指标掩盖
  2–8 kHz 的噪声底差距。

### 5.8 Body bypass、增益与限幅

B 不应该过 guitar body。建议：

```text
A voices (class 0) --> A_sum --> body_filter -->\
B voices (class 1) ---------------------------> + --> master gain/limiter --> I2S
B noise (L2) ---------------------------------/
```

- bank 已经逐 voice 输出 `voice_sum`；top 按 class mask 分两路累加。
- B 关闭时 `A_sum` 必须与现 `mix_sum` 逐位相同；body 输入不变；master gain=1、
  限幅旁路，保证 A 逐位不变。
- B 单声部峰值 2–5（cello A3 5.07）。12 声部叠加 24–60，32 声部 64–160。
  64-bit Q2.30 混音不会溢出，但 16-bit 输出必须定增益/限幅。
- 固定增益 `g_B < 0.9/(5.07·N_B)`：N_B=12 时 g_B<0.0148，单声部输出约 0.075（−22.5 dBFS），
  相对 A 太轻；所以**固定增益 + 硬饱和不能同时满足单声部响度和 12 声部不削顶**。
  需要：
  - 软限幅/压缩（`x/(1+|x|)` 或 3 段折线），或
  - 把 B 复音限制到 4–6 并接受较低的单声部电平，或
  - 按最大复音数定增益 + 硬饱和，牺牲单声部动态。
- 这是 L0 之前就要冻结的系统项；demo 的 tanh/整段归一化不能直接上板。

### 5.9 A/B 共存与音高基准

- A 和 B 共用 32×48 bank；B 用 class bit 区分，输出分路。
- **A/B 必须同音高基准**：A 现在 48 kHz 系数 + 48.828 kHz 时钟（+29.6 c 全局）；
  B 的 L0 也要 48 kHz 基准。B 如果单独重生成到 48.828 kHz，A/B 会差 29.6 c。
- A/B 同时 note-on 时，bank 的 32 槽和 cfg 口要仲裁；L1 需要预留 B 槽和装载优先级。
- B 关闭时 A 逐位不变，是每个阶段的回归门槛。

  相对误差约 0.1%，只影响调制量（22 c 颤音约 0.02 c），不是精度瓶颈；`ratio` 的 1.53e-5
  约 0.026 c，可接受。
- `ratio` 的 Q 格式：UQ1.16 与 UQ2.14 都是 16 bit，寄存器/乘法器/面积完全一样，**没有资源差异**；
  1.16 范围 `<2.0`（+12 半音刚好卡边界），2.14 范围 `<4.0`（±2 八度有余），代价是 LSB 从
  0.026 c 变 0.106 c——仍远细于 a1 Q2.20 的量化（cello 低音约 3.8 c），所以 2.14 的分辨率
  不是瓶颈。当前冻结 16-bit 字段、写 1.16；滑音/弯音范围确定后若 >12 半音，切 2.14 只改
  常量和饱和，不动 RTL。
- env 的 3.8 s attack `1−α=5.48e-6` 在 UQ0.32 是 23,534 LSB，在 α 的 UQ0.24 里是 92 LSB，不会卡 0。

## 附录 A：公式与计算口径

- 采样周期：`2048 = 100e6 / 48828.125`。
- 整数周期：`T = max(2, round(48000/f0))`，`f_drive = 48000/T`；
  误差 `1200 log2(f_drive/f0)`。
- 全局移调：`1200 log2(48828.125/48000) = 29.63 c`。
- 极点：`r = exp(-γ/48000)`，`θ = 2π k f_drive/48000`，
  `a1=-2r cosθ`，`a2=r²`。
- 稳态：`A_peak = max_j r^j |Im(e^{iθ(j+1)}/(1-R e^{iφ}))|`，
  `R=r^T`，`φ=θT`，`G=w/A_peak`。
- Taylor：`a1(ρ)≈a1_0+c1(ρ-1)+c2(ρ-1)²`，
  `c1=2rθ sinθ`，`c2=rθ² cosθ`（**仅用于误差评估**；实现用直接 `-2r·cos(ρθ)`）。
- 尾音：`t(-74dB)=8.52/γ`，`T60=6.91/γ`。
- 包络：`α=exp(-1/(fs τ))`；UQ0.32/UQ0.24 的 `1-α` 分辨率检查。
- BSRAM：`块数 ≈ raw_bits / 18432 / 0.63`（pROM 效率沿用 A 表）。
- 声部占用：`N ≈ rate × tail`。
- 混音：`peak_B ≈ 5.07 × N_B × g_B`；`g_B < 0.9/(5.07 N_B)` 才能不削顶。
