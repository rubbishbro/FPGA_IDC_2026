# 演奏录制

2026-10-31。按最新需求重新明确方向：把本机演奏读回 PC，停止录制后生成新的可编辑 MIDI 轨道，再通过已有走带发送给 FPGA 自动演奏。本文前文为设计说明，最新实施范围见文末“首版实施记录”；硬件实测结果与仿真结果分别报告。

## 1. 目标与现状

主路径为：

```text
压力垫演奏
 → FPGA 实际采用的起音 / 松键 / 力度 + 时间戳 + 音高映射
 → 事件采集 FIFO → 有线 UART 回传
 → PC 演奏录制器 → 新 MIDI 轨道
 → 钢琴卷帘编辑 / 力度 / 量化 / MIDI 导出
 → 已有 Playback → UART MIDI → FPGA 自动演奏
```

PCM/WAV 是另一种产物：它记录真实数字声音，适合试听、导出和检查音色，不能直接作为当前卷帘的音符数据。把多音 PCM 自动转成 MIDI 还需要音高/起音/时值识别，此需求没有必要经过这条路径。优先实施演奏事件录制，PCM 留作后续可选的同步音频参考。

已核对当前代码：

- `protocol-v2.mjs` / `serial-v2.mjs`：会话握手、心跳、配置、恢复；尚无录音器或板端演奏事件消费者。
- `comm_top.sv` / `transport_v2_link.sv`：蓝牙可选 v2，有线仍 v1。不能根据 PC 有 v2 选项就认为板端有线也已支持 v2。
- v2 TYPE=81 是 CONTROL_REPLY，旧 PCM 草案的 TYPE81 仅能在明确的 v1 分支下解释，不能复用到 v2。新增事件类型需正式分配，禁止直接把81解释成音频或演奏事件。
- `voice_router.sv` 已暴露 pad_keys_down，并有实际提交的 gate / strike_level / retrigger / clear；`performance_input_mux.sv` 定义 PAD/MIDI 选源与提交时序。
- `model.mjs` 已支持轨道 notes、beat、duration、velocity、通道、tempoMap；现有播放/导出链可复用。缺少的是板端回传与按时间戳构建轨道，不必重写编辑器。

## 2. 录什么，在哪录

首版录本机 PAD 实际生效的演奏，不从 ADC 原始噪声重复判断起音，不从 PCM 识别音高，不仅镜像 UART 输入。

在已有演奏链的实际采样提交边界观察：

| 变化 | 回传含义 |
|---|---|
| 生效门控 0→1 | NOTE_ON，携带该次 strike 力度、真实 MIDI 音高与绑定通道 |
| 生效门控 1→0 | NOTE_OFF，结束按键时值，不等声音衰减到零 |
| 门控保持1但显式 retrigger | 结束此前实例并开始新实例，按确定次序回传 OFF→ON |
| 维护 / 清理 / 配置切换 | 结束旧实例；首版将本 take 标记停止 / 中断，避免一条轨道混入未描述的资源身份 |
| 变化的持续压力 / 调音量 | 首版可保存原始诊断，但不宣称标准 MIDI 轨能无损重现 |

采集点应复用现有的生效快照与实际提交脉冲。pad_keys_down 可作状态观测参考，但不能脱离实际选源 / 维护 / 引擎准入直接把其每个变化当已演奏事件。采集只观察，不阻塞合成；记录排队失败必须标记缺失，不悄悄拖慢 DAC。

每次 ON 锁存真实音高与通道；OFF 按此前归属结束，不能按当前新映射重新计算。上送的是资源表中的实际 MIDI 音符，不只是矩阵槽0..15。PAD 音色到 MIDI 通道采用当前固定映射反查；不支持的映射明确拒绝 MIDI 录制。

力度首版用实际起音 strike_level 转7bit，非零最小1，建议固定量化函数 `(level*127+127)/255` 向下取整，具体实现必须与黄金向量一致。该映射是有损量化：PAD 的持续压力包络、压力调音与 MIDI 力度路径不同，回放保证音高/按键时值/起音力度语义，不承诺声音逐样本相同。

## 3. 时间基准与身份

以 FPGA 音频帧计数作时间戳，不能用浏览器收到 UART 包的时间作为音符起止。每次生效事件携带相对于本次录制起点的 frame_index；帧率携带分子/分母（当前12,500,000/256）。

START 在明确采样边界生效，回复包含本 take 的 recording_id、实际音色/通道、音高清单或资源身份及帧率。录制从 PC 当前光标开始插入，保留用户按下录制到第一个音符的等待时间，不默认删掉前导空白。

换算使用冻结的工程速度图：

```text
eventSeconds = frame_index * rate_den / rate_num
projectSeconds = beatToSeconds(insertBeat, tempoMap) + eventSeconds
projectBeat = secondsToBeat(projectSeconds, tempoMap)
duration = offBeat - onBeat
```

录制期间冻结 tempoMap / 插入位置，不允许改速度导致已收事件时间漂移。结束后才能整体量化；保留未量化起止，避免默认破坏真实演奏节奏。录制上限首版600秒并限制总事件数。

记录身份包括 recording_id、事件流水号和每次起音的 note_instance_id。即使同槽/同音重触发，OFF也能准确结束对应实例。PC 同次串口连接不复用 recording_id，重连不能把旧 take 追加到新 take。

## 4. 回传协议与通信适配

先沿用实际接板的有线 v1 做显式扩展，独立增加演奏录制的 START / STOP 和设备→主机事件帧；不修改已有 MIDI_DATA、REPLY 含义，不自动将有线切换为 v2。命令号、类型号实施前统一登记到权威协议，本文暂不冻结数值。

事件帧至少表达：recording_id、事件序号、音频帧时间戳、事件种类、source、note_instance_id、channel、note、velocity。一次和弦可有多个相同时间戳的事件，不能因为按字节串行发送而把它们录成琶音。按包长预算拆包，不能为套用32字节上限丢掉时间/身份字段。

另需 STARTED 元数据和 END：END 给出最终时间戳、最后事件序号、事件总数、溢出/中断原因。STOP 在生效边界切断采集，排空此前事件再发END并完成回复。回复与事件流按完整帧仲裁，不交错字节。PC arming 起即安装接收器。

新 v2 会话层可作为后续双向事件上送的基础，但它当前只完成会话/下行业务，不自动提供此能力。若扩展到 v2，应在其 session 下增加独立的上行流序号与记录身份；不能使用下行 MIDI expected_seq 或 epoch 代替录制流序号。

演奏事件远小于连续 PCM；不再把3Mbps和96KiB PCM FIFO作为此功能前置条件。115200是否足够应按实际事件帧长度、最快16键交互/和弦、控制回复和最坏SLIP转义测试。首版不每个音频采样点上传压力；持续压力后续按确定控制率合并，并为NOTE_OFF和END保留服务能力。

## 5. PC 录制器与轨道提交

新增独立 `performance-recorder.mjs`：

- 状态 idle → arming → recording → stopping → finished / incomplete。
- 以 note_instance_id 维护未结束音符，匹配ON/OFF；忽略重复事件，校验序号、非倒退时间戳、通道/音高范围和最大事件数。
- 录制中在临时新轨绘制增长的音符；收到OFF才确定完整时值，避免每包创建撤销快照或保存整个工程。
- 正常STOP时，仍按住的音符在END最终时间戳封口，表示录制窗口结束；不要求物理松键，不向设备发panic，不改变当前PAD演奏。
- END后将完整take一次提交到History，自动选中新轨；用户一次撤销即可移除本次录制。按需扩展工程小节长度，不覆盖已有轨道。
- 保存notes到现有JSON，导出.mid复用writeMidi；回放复用compileEvents / Playback / SerialLink.send。
- 录制时长按设备时间/事件进度显示，DOM约10Hz刷新，不逐样本刷新。

UI：顶部增加“录制演奏 / 停止录制”，左侧出现“演奏录制01”新轨；右侧显示实际来源、音色/通道、时长、已收音符、完整性。默认首版单独录制PAD，禁止一边向同一FPGA播放伴奏一边录PAD：当前是单活动来源，PAD/MIDI无法凭UI叠加同时发声。未来叠录要另定义来源混合和声部策略。

停止录制后用户可直接调音高、拖动、改时值/力度、量化、复制和再次演奏。自动回放前仍执行已有资源准入；板端须切到有线MIDI、相同音色/音组。当前录制回传扩展本身不意味着已有远程切源/音色/音组配置命令，不自动伪装配置成功。

## 6. 异常和回放保真边界

- 事件丢失不能像PCM一样补零修复。检测缺口后标记take不完整；若后续OFF具有独立实例ID可结束对应音符，但缺失ON不可猜测。首次版本可停止录制并保留已收部分。
- 断线时以最后可信设备时间结束未闭合音符并标记截断；浏览器墙钟不能当作已确认的精确停止时间。
- CRC错误可丢帧计数，事件序号负责发现语义缺口；MIDI不自动重发。是否实现板端短历史重传属于额外协议功能，首版不默认拥有。
- 多键同拍、OFF→ON重触发、力度1/127、长按、加载/清理、停止时按键仍按下、旧录音帧迟到均须测试。
- 持续压力 / 变调若要编辑并重现，需要扩展工程控制曲线，以及FPGA真实压力/弯音消费者。仅把压力写成CC11既不等同现有压力路径，也不能证明DSP已支持。
- 音色/效果身份可随take保存元数据，但不把元数据当成可远程配置的能力；声音逐样本一致需要额外PCM对拍和完整控制记录。

## 7. 实施顺序

1. 先确定生效演奏快照出口、资源身份与录制事件合同，增加黄金向量。
2. PC实现纯事件录制器及模拟回传测试：变速换算、和弦同拍、重触发、正常收尾、缺口/断线、生成轨道可撤销、MIDI导出再导入一致。
3. RTL增加生效事件采集、小FIFO、起停/结束屏障及有线帧仲裁；保持当前调制/I2S改动独立，录制不反压合成。
4. 端到端验证“真实PAD → 新轨 → 编辑 → MIDI回放”，对比音符清单/时值/力度，再验收资源切换与听感；PCM/WAV可之后独立加上作为音频参考。

## 8. 首版实施记录（2026-10-31）

已接入有线v1的CONFIG12/13与TYPE82事件上送，正式字段/结果以[PROTOCOL_V1 §10](../rtl/drivers/analyzer/PROTOCOL_V1.md)为准。新增performance_capture、performance_frame_tx；使用现有comm_fifo的128项同步RAM队列与已有REPLY的帧级仲裁；voice_router只增加生效快照观察出口，midi_voice_top向板级透传。起停对齐audio_sample_tick，时间戳为32bit帧计数，600秒范围内不回绕。

首版每槽仅一个PAD按键实例，因此用take ID + slot配对，并保留上次起音音高，未实现前文更通用的note_instance_id。前文额外重传/持压曲线/实时临时轨显示均未实现：界面在收尾后一次提交新轨，录制期间显示计时与音符数量。保留按下录制前已按住的键，在首个有效快照建立ON。停止仍按住的键在END处封口，不清PAD声音。

上位机新增performance-recorder.mjs / recording-ui.mjs，有线SerialLink支持独立CONFIG序号和最终回复匹配、保留控制队列不被MIDI取消清空。新轨复用现有编辑/导出/回放，包含录制来源和采样率元数据；若新轨超出循环末尾，扩展循环范围覆盖录制。蓝牙v2不支持此录制入口，未改变其握手/心跳合同。

```bash
python3 sim/run_board.py --test record --out build/performance_record/board_record
node web/midi-editor/tests/check-rtl-take.mjs
```
