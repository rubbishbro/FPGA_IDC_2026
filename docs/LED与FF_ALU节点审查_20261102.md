## LED的FF到底存了什么

按FF的Q端网名分组，逐项加和与模块总数一致。综合器把多个字段合并为带RAMREG名字的寄存器组，下表使用合并组归属，不伪造各字段单独的优化后位数。

| 存储/节点 | RTL声明位数 | 实际FF | 源码 |
|---|---:|---:|---|
| 灯效framebuffer，64×RGB24 | 1536 | 1536 | pad_led_effects.sv:161、265–269 |
| pending_phase/age/travel，16项 | 896 | 880 | pad_led_effects.sv:65–66、85–89 |
| wave_pad/colour/birth_age/birth_travel，16项 | 800 | 744 | pad_led_effects.sv:105–108、122–127 |
| snap_pad/colour/age/radius，16项 | 640 | 505 | pad_led_effects.sv:157–159、205–212 |
| 灯效控制、计数、流水等其余 | — | 374 | pad_led_effects其他寄存器 |
| **pad_led_effects合计** | — | **4039** | 无子模块 |
| 驱动gram，64×RGB24 | 1536 | 1536 | pad_driver.sv:62、94–100 |
| 驱动预取/串行控制自身 | — | 50 | pad_driver.sv:105–145等 |
| 驱动子模块shift_timer | — | 3 | pad_driver.sv:80 |
| **led8x8完整子树** | — | **1589** | 包含timer |
| **LED系统合计** | — | **5628** | **占整板FF15.4%** |

两份像素缓存合计3072FF，占LED系统FF的54.6%；三组事件/波纹/快照记录合计2129FF，占37.8%。绝大部分是数据存储，不是FSM编码浪费。去掉这些数据的reset并不会把FF本身删掉。先前已取消gram等数据复位，因此继续只盯reset不是主要面积优化方向。

ROM已映射为13个RAM原语；“把灯效查表改ROM”不是当前首要动作。剩下1390个级联MUX主要应结合这些动态读取的寄存器表分析。

## LED的768个ALU来自哪里

按ALU原语的COUT→CIN连接追踪完整进位链，再根据操作数网名对应RTL表达式。总计43条链，覆盖全部768个ALU，无重复加和。

| 功能 | 实际ALU | 比例 | 对应表达式 |
|---|---:|---:|---|
| 16路半径快照减法 | 360 | 46.9% | `snap_radius[i] <= travel_acc-wave_birth_travel[i]`，210行 |
| 16路年龄差，退休/快照复用 | 254 | 33.1% | `age_clock-wave_birth_age[i]`，136、209、234行 |
| phase/travel/age三个公共累加器 | 64 | 8.3% | 50–51行 |
| 事件相位+命中偏移、像素相位+空间偏移 | 32 | 4.2% | 144、239行 |
| RGB三通道叠加背景 | 24 | 3.1% | 267–269行 |
| 当前波纹lag减法 | 16 | 2.1% | 186行 |
| 半径/距离比较进位链 | 12 | 1.6% | 244行相关比较 |
| 最强波纹幅度比较 | 6 | 0.8% | 257行 |
| **合计** | **768** | **100%** | |

半径链为14条23ALU、2条19ALU，共360；年龄链为14条16ALU、2条15ALU，共254。低位常量传播、进位结构及不同输出消费使其不必恰好等于RTL名义位宽。

关键判断：灯效已经串行扫描每个像素的16个波纹，但**生成整帧快照时仍一次展开16路半径减法与16路年龄减法**。这两类合计614ALU（80%）。不是颜色乘法器占满，因为当前灯效没有DSP原语，颜色/增益已经用ROM。

136行的退休年龄检查是每core拍并行执行，不只在frame_tick执行。综合器共享了同一个年龄差的多个消费者，不能把136、209、234三处表达式各自再按16路累加一次，也不能直接删除退休检查而让年龄时钟回绕后复活旧波纹。

## 优先改动建议与收益边界

### 1. 先将framebuffer与gram变成真正同步存储

灯效framebuffer写入是逐pixel_idx，R_FILL读取也是逐fill_idx，本身适合独立同步读写口。当前217行的组合读以及带复位主always中的写控制，应整理为无数据reset的RAM写/同步读模板，利用R_READY/R_FILL前置预取。在cr.clk_en消费时必须已有正确像素，首尾像素及BOOT_FILL不能错位。

驱动gram目前为1536位packed union，串行时按idx动态选位，PIPELINED_READ只是拆成两级选择，并未变成RAM。可改为64×24像素RAM，读出一个24位GRB移位寄存器，逐bit发送。只在像素边界换字，保持WS2812位序、400ns节拍、高低电平长度和reset/latch间隔。

两块RAM有3072FF的迁移容量，但新实现需要RAM输出寄存器、24位串行寄存器和预取控制，所以不能承诺净省3072FF。两份缓存分别隔离渲染与发送，先保留两份并改变实现，不要直接删一份而破坏并行工作。实际节省以新综合为准。

### 2. 共享半径减法，比先折腾颜色逻辑更有效

每帧锁存一次`frame_travel=travel_acc`；快照数组保存`wave_birth_travel`，在已经逐wave_idx执行的渲染FSM中，用`frame_travel-snapshot_birth_travel[wave_idx]`计算当前半径。保持同一帧所有波纹都使用相同frame_travel，不可直接使用随时间继续增加的实时travel_acc。birth数据仍在原frame_tick同拍快照，避免事件E_COMMIT期间读到混合版本。

这样有机会把当前16路360ALU变成一条约24位减法链，**粗估可省约330个ALU（灯效约43%）**；新增frame_travel寄存器和可能的流水/选择逻辑，必须由新综合确认。不得省略会影响模运算/比较的低位，也不能将帧内半径改为实时值而声称等价。

### 3. 年龄计算放第二阶段，保留退休语义

年龄差254ALU分布在16个记录上，并被实时退休和帧快照共享。改为扫描式退休需要证明在age_clock变化、事件写入、同槽替换、snapshot边界和计数回绕附近行为一致；不能只将for改为多拍循环。若采用新增年龄计数器，亦需考虑新增FF及每槽递增器，未必省面积。优先处理半径后再单独评估。

### 4. pending表不要直接硬套单口RAM

pending的880FF虽然很大，但16个PAD可能在同一拍同时起音，目前能同时写16条pending记录。直接换单写口RAM会丢失并发捕获能力。可研究“同时捕获16bit位图+公共命中时间/相位、随后排队展开”，但必须处理不同批次未消费期间再次命中、同键重击覆盖及phase_for_hit时刻语义。wave表可逐项写，但并行退休又需要多读，二者要一起设计。

## 与之前结论的差异及交付

前一轮只指出LED总计5628FF以及多层记录/缓存；现在已确认：FF主要是3072位像素缓存+2129位记录，ALU主要是614个快照/年龄减法原语。优化次序应是**同步化像素缓存 → 共享半径快照减法 → 再处理年龄/事件表**，并非先删FSM或改颜色ROM。

以上为当前综合网表的可复核统计与源码方案审查，未宣称优化已实施、未给出新PnR结论。数据文件位于`build/resource_review_20261102/`：`direct_rankings.json`、`pad_led_effects_detail.json`、`led8x8_detail.json`、`led_alu_chains.json`。模块名是综合后的层次节点，不能把模块LUT/ALU数量直接当作具体未布通网络的归因。

## 后续实施：同步像素缓存与共享半径计算

本节更新此前“尚未实施”的状态；上面的数值保留为优化前基线。

已修改`pad_driver.sv`的led8x8：1536位packed gram改为64×24同步RAM，按tx_pixel读取整像素，由tx_bit选择GRB线序位；原idx、协议FSM、位脉宽及frame_done时刻保留。PIPELINED_READ参数保留兼容，两种设置现在均使用同步RAM。

已修改`pad_led_effects.sv`：framebuffer改为独立正常写口/同步预取读口，R_READY提前读像素0，R_FILL接受一笔写入时提前读下一像素，即使clk_en连续为1也不会重复旧像素。保留BOOT_FILL和渲染/发送各自的缓存，不合并两者。

半径快照保存原始birth_travel及同拍frame_travel，在现有R_WAVE_ADDR状态用一套减法生成radius寄存器，R_DISTANCE再做lag/比较。不改变FSM拍数，不使用实时travel_acc替代帧时间。年龄退休、多键pending写入和波纹发布均未重构。

新增`sim/run_led_storage.py`，从固定提交`99762fbef7eec1fdce90fa52971379ddeadc7e80`生成原版模块，用`tb_led_storage_equivalence.sv`对照最终实现。三种使能周期1/4/20分别逐周期比较像素写入、dat/busy/frame_done，覆盖同拍16键、随机重击、travel/age回绕附近、渲染中复位和发送中复位，均通过；不是形式等价证明。

正式板级runner的led、led_protocol、led_effects三项也已通过，覆盖3072个随机线端bit、256种灰度+独立RGB线序、完整16波纹生命周期。板级测试中的缓存层次探针已改用pixel_ram地址；没有放宽线端验收。

日志与综合产物集中在`build/led_optimization_20261102/`。早期两轮综合试跑因增加半径寄存边界、修正声明顺序而停止；最终资源只采用`verified_synthesis`。单独LED探针证明framebuffer已映射SDPB，ALU为431；最终整板资源对照见后续补充。本轮未烧录、未运行新PnR。
