## 判断

- `part_tick` 同拍复制、声部分组是首个实验；其次是 exc/env 内部复位分组；core 域更广的分区另做一轮。
- core 复位不是 ENG1 本体复位，需要按实际区域分区，不能只在 voice 内部复制。
- 现有最差 setup 路径是 `event_fifo/out_data → guide/notes → hold_count`；次差包含 `voice/state → input/note_on → note_pend`。复位/CE **不是**已证明的最差 setup 路径。
- 复制可能增加 FF/LUT 和不同控制组合，影响 CLS 打包；目标是控制网负载/跨度，不是显著减少全局 Logic。

## 已实施

- `voice_router` 保留原协议 `part_tick`，另两个并行寄存器从相同 `smp_tick_q` 取数，分别驱动激励和包络；无新增数据流水延迟；用 `syn_keep`/`syn_preserve` 保留副本。
- `child_reset` 从 7 条扩为 15 条，同样异步断言、两拍释放；分离通用激励控制、小号、mod0/pitch、两路 eng0/eng1。包络保留原有独立复位，parts 算法模块不修改。
- wrapper 默认 `SPLIT_RESET=0`，原有独立使用方式保持；仅 `voice_router` 显式打开分组复位。
- 状态机、激励/包络算法、系数以及音频资源 BIN/MEM 不变；`resources.json` 只更新 `exc_router` 源文件 SHA。

## 验证

`python3 sim/run_control_fanout.py` 通过。测试用冻结的修改前 wrapper/parts 生成 reference，与当前实现逐周期比较：

- SLOTS=4、7、16，各 60,000 时钟，覆盖不同声部数、六种旋律乐器、门控、重触发、清槽、弯音输入及热复位。
- 完整 `voice_router` 的 QSPI 表加载、失败、加载中复位、中止与重试；包含非零音频，逐周期比较输出/状态，并检查真实 tick 副本与复位分支同拍。
- `sim/check_performance_resources.py` 通过；资源镜像 SHA256 为 `e9de9737735eda50f03853c959d162868949b2a80ec202dce992d3924c3ca900`。
- 当前板级源码使用仿真 PLL、ADC 占位模型完成 elaboration/lint；不是板级行为仿真。

三阶段综合：控制优化前 74,239；`part_tick` 复制 74,239（0）；模块级复位拆分 74,206（-33）。后续 ENG1/`pad_driver` 修改使当前到 73,954，不应把 -252 算作复位收益。
