## 增长来源（11-03）

相对小号 TDM 后版本，整板净增 **4,993 Logic（+7.24%）**：

| 不重叠区域 | 基线 | 当前 | 变化 |
|---|---:|---:|---:|
| 两路 ENG1 核 | 876 | 3,438 | **+2,562** |
| 通用激励 `u_gen` | 11,528 | 12,263 | +735 |
| UI 整个子树 | 12,038 | 12,739 | +701 |
| pitch `modulation1` | 2,168 | 1,549 | -619 |
| 其余区域净变化 | — | — | +1,614 |
| 全板 | 68,961 | 73,954 | **+4,993** |

- ENG1 源码对比确认新增鼓噪声状态、双低通整形、包络、增益及调度，两条 lane 各实例化一次；这是明确的功能扩张。核内部差值不等于该功能的全部板级成本。
- 通用激励 `excitation.sv` 两版逐字一致，不能把 +735 直接归因于该模块新增算法；可能受上游取值范围、综合映射影响，需要固定上下文 A/B 才能隔离。
- UI +701 是子树净变化，尚未隔离为单项功能成本。
- `modulation1` -619 与 aftertouch 修正/重构有关，不能简单当作“优化收益”。

## LED 子树

- LED 的 4,039 FF 不是“灯本身”的寄存器，主要来自 framebuffer、gram 以及波形/距离流水；`led8x8` 自身另有 1,586 FF。
- LED 的 768 ALU 来自逐像素效果计算（色彩、距离、衰减等），不是存储。
- 11-02 的建议：把 framebuffer/gram 改成真正同步存储，减少异步复位与选择树；单独验证读延迟、帧预算和 WS2812 线序。该建议在 11-03 的 LED 等待 review 中已落到 `R_DISTANCE_WAIT`（见 [LED 等待](./2026-11-03_LED等待.md)）。

## 建议顺序

1. 先处理 ENG1 核的 `+2,562`：确认鼓噪声/双低通/调度里哪些是必需功能，哪些可共享乘法器/状态。
2. 激励 `u_gen` 的 +735 先做固定上下文 A/B，不要直接改算法。
3. UI +701 拆到具体页面/缓存；`sidebar_ctrl` 的冷启动缓存回归已单独记录在 [现场配置失败](../2026-11-03_现场配置失败.md)。
4. ALU 热点（激励、包络、混响）做复用/共享乘法器；LED 存储改同步 RAM 后再看 FF/CLS。
5. 高扇出控制优化按 [高扇出与复位](./2026-11-03_高扇出与复位.md) 的顺序推进，不把 Logic 增减当作唯一目标。
