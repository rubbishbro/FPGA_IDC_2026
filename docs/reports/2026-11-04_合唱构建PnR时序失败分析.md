## 7. 根因（代码层）

`rtl/platform/tang_mega_138k_pro/instrument_system.sv`（下述为失败构建时的代码；工作区已有未提交的
`keymap_wait_expired` 预计算改动，见 §10）：

```systemverilog
localparam int KEYMAP_WAIT_CYCLES = CLK_HZ*2/5;          // 50 MHz -> 20_000_000 (400 ms)
if (bridge_state==B_KEY_WAIT && keymap_waiting_release) keymap_wait_timer<=keymap_wait_timer+1;
assign keymap_cancel = bridge_state==B_KEY_WAIT &&
                       (quarantine[ctx_source] || !remote_permission[ctx_source] ||
                        (keymap_waiting_release && keymap_wait_timer>=KEYMAP_WAIT_CYCLES-1));
```

- 32 位计数器与常量 `20_000_000` 的全宽比较被综合成多级比较逻辑，计时器第 3 位
  （`keymap_wait_timer_3_s0`）成为最差路径的发射点，经 2 级 LUT 后进入 74 扇出网络。
- 比较结果 `keymap_cancel` 进入后端取消/回滚逻辑，在 `rtl/router/midi_voice_top.sv`
  中与 `keymap_validating` 和 `target_slot_map` 的写使能（共 112 位）合并，
  形成跨越 `u_system` → `u_sound` 的 74 扇出网络 `n15979_s1`。
- 该网络同时受 `cfg_state[2]` 驱动的一组 6 条路径（`u_guide/hold_count` 使能）影响，
  属于同一控制域的拥塞。

## 8. 可选修复方向（均未实施）

1. **给超时判定打一拍**：`keymap_wait_timer>=KEYMAP_WAIT_CYCLES-1` 的比较结果寄存后
   再驱动 `keymap_cancel`。400 ms 量级超时多 1 个周期无功能影响，但会改变取消当拍语义，
   需要 `tb_local_reverb`、keymap 回归与 `run_router_midi` 覆盖。
2. **拆比较链**：先比较高位（如 `timer[31:16]`）再与低位比较，或把阈值改为
   `timer == 20_000_000` 的单点相等（配合计数停止条件），减少比较级数。
3. **寄存器化写使能**：`target_slot_map` 的逐槽写使能改为“指针 + 寄存的使能”，
   避免 74 扇出网同时扇出到 112 位寄存器的 D/CE。
4. **只换 PnR 策略重跑**（place 4 / route 2）：无需改 RTL，但只影响 ±0.3 ns 量级，
   属于碰运气，不解决根因；可先试，失败再改 RTL。
