## 根因与最小对照

`rtl/router/midi_voice_top.sv` 原声明为 `input logic backend_source_valid=1'b1`，生产调用端传入组合产生的来源有效信号。在本版Gowin V1.9.12.04中，该默认值端口的动态接线综合结果与RTL语义不一致。

最小对照包含两个行为相同的leaf模块，差别仅为输入有无默认值，均连接同一组合valid：有默认值的版本被综合成CE=VCC，无默认值版本保留CE=valid。门级仿真在valid=0时运行三个有效时钟，有默认值输出翻转为1、无默认值保持0；直接连接顶层输入的对照则一致。这说明先前“省略端口与显式接常量1结果相同”的实验没有覆盖本故障所需的动态组合连接。

最小源码、综合结果及门级日志位于build/selection_recheck_76f0_20261103/default_dynamic。此处不推断综合器内部实现原因；以实际网表失真及去掉默认值后的对照为依据。最小例子中的恒高与本项目中的等效恒拒绝不是同一种常量结果，不能据此声称所有默认值端口都会被固定为同一个值；确认的是动态连接的语义在这些综合实例中失真。

## 修复

生产修改：将来源有效输入声明改为无默认值的显式net输入：

```diff
-    input logic backend_source_valid=1'b1,
+    input wire backend_source_valid,
```

板级已有显式动态接线，无需改变逻辑表达式。对11个此前省略该输入的仿真调用补`.backend_source_valid(1'b1)`，避免测试继续隐式依赖默认值。已显式控制来源的取消/混响夹具保持动态接线。

保留此前的两层来源映射（本地UI/外部仲裁来源与有线/蓝牙物理来源）、断连取消锁存和完整系数恢复逻辑，没有把检查固定成永远有效。
