# 鼓件映射与班卓琴、曼陀林腔体接入

- 鼓件资源索引按 GM 升序固定：36/kick→0、38/snare→1、42/hat→2、45/tom→3、49/crash→4、59/ride→5。RTL `router_pkg::drum_index_of` 与 Python `DRUM_INDEX_BY_GM` 一致；RTL 非法编号返回7。外部协议仍发送 GM Note，不发送内部索引。
- 本轮只定义查找表，未开放鼓后端、资源掩码或 MIDI 第10通道。未来加载地址选择须调用此表；历史试听音频播放顺序不构成资源顺序。
- 用户确认：鼓保留自身自然尾音。Note Off 结束按键/音符门控，不直接截断鼓声。仍需鼓专用到期淡出、状态清除和声部回收；噪声定点包络不能依赖自然精确归零。
- MIDI Note Off 本身不要求所有输出立即归零，音色可以进入 Release；效果器尾音是另一层处理。现有其它乐器 ADSR 不变。
- 班卓琴、曼陀林分别使用 `params.Patch(name).sos` 从对应 `FFT_results/params/*_body.npz` 拟合的四段腔体，归一化 a0 后按 `floor(c*2^27+0.5)` 转为 Q4.27，写入 `body_router`。第五段直通，复用现有共享腔体通道，换乐器清历史的机制不变。
- Python `router_eng1.body_coeffs` 同步解析这两种乐器的 RTL 常量；生产清单记录 `body_q27` 与模型来源，新增两个 body NPZ 来源哈希，资源检查器核对腔体记录。
- 模态 Flash 镜像字节保持不变（SHA256 `d7c73b46edfa1df726c049525133660579a1e703706a61a4c82d314de298d865`）。腔体属于 RTL 常量，需要重新综合/烧录 FPGA 才在板上生效。
- 本轮不改乐器增益。此前班卓琴、曼陀林的 -12dBFS 标定基于直通腔体，接入后该标定值需要重新核对；不能继续视为严格满足目标。

验证入口：`sim/check_body_connections.py` 对比原 Python SOS 的量化、极点及频响，并对两种乐器各1024个脉冲/随机/零输入样本核对实际 RTL 与整数模型，同时穷举256个 GM 输入。生产资源另由 `sim/check_performance_resources.py` 核对。

验证结果：Questa 2048个输出样本逐点一致，256个GM输入全部通过；两滤波器最大极点半径分别0.960083、0.973618，频响量化误差均小于0.000005dB，测试无饱和。生产资源22528条记录核对通过，资源检查器6项回归通过。未进行本轮板级烧录/听感验证。
