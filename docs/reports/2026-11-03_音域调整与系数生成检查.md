## 逐音试生成

使用 torch312 Python 环境，逐一调用现有生成接口检查44～75全部音符；结果存于 `build/range_44_75_resources/coverage.json`（构建产物）。

| 音色 | 生成入口 | 结果 |
|---|---|---|
| 钢琴 ENG0 | `rtl/router/tools/matrix_resources.py::matrix_note` | 32/32生成成功；优先保留原量化记录，其余量化源矩阵或离线移调 |
| 吉他 ENG0 | 同上 | 32/32生成成功；`sythsound/guitar_coeff_scaled.txt` 和 `guitar_param.txt` 覆盖新范围，包括72、73 |
| 钢琴 ABC | 同文件 `piano_abc`，由ENG0矩阵转ABC | 22/32成功，66～75均触发 `unstable ABC conversion` |
| 吉他 ABC | `python/modal_sim/guitar_refit_experiments.py::table_for`，由 `performance_resources.py::make_note` 调用 | 32/32生成成功；F版允许以选定源录音离线移调，来源记录在生成元数据 |
| 大提琴 | `rtl/router/tools/sustain_resources.py::make_note('cello', midi, False)` | 32/32成功，无需允许邻音移调；源为 `FFT_results/params/cello_sustain.npz` |

钢琴ABC首个失败是 MIDI66、mode44；其它失败模态见coverage.json。现转换器在挑选48个模态前即对所有候选检查ABC严格稳定性；不能据此断言最终必选模态均有问题，也不能直接跳过检查。需单独分析高频模态/量化问题后再生成。

完整生成命令：

```sh
/home/rubbishbro/micromamba/envs/torch312/bin/python rtl/router/tools/performance_resources.py --out build/range_44_75_resources
```

该命令在钢琴ABC MIDI66失败，输出目录中只有此前成功的部分分表，不是可部署镜像。正式 `rtl/router/tools/performance/` 下的BIN/MEM/JSON未覆盖，仍为旧音域；修改后的资源检查器会拒绝旧镜像。当前代码与旧镜像不能配套烧录。资源区步长仍为每乐器128KiB、每音4KiB，公共控制页仍为0x980000。

大提琴只改目标音域，未加入六音色生产生成循环或RESOURCE_MASK，未启用实板功能。未执行新音域RTL音频仿真、综合、烧录或听感验证；生成成功不代表音色/增益已验证。既有增益校准仍引用旧参考音（钢琴36），需在新范围另行复核。

## 后续试验：不稳定ABC候选置零

按用户要求，`piano_abc` 将量化后不满足严格稳定性/位宽要求的候选模态替换为 `G=a1=a2=0`。仍按替换前的矩阵响应峰值选48条，不以其它模态补位、不重新分配增益；源矩阵行列式不在(0,1)内的模态保持原有过滤逻辑。元数据记录静音来源、选中静音槽和实际发声数量。打包器及检查器只为全零三元组增加静音例外，非静音模态仍严格检查。

新范围六音色镜像已成功生成至 `build/range_44_75_muted/`，资源检查通过12288条记录，1576960字节，SHA256 `5f5d48d91840845286d797fe8689f803cea1f6cab6e3cae832bd9688a8a39ee2`。正式performance目录仍未覆盖，未烧录。

MIDI70六个报错源模态为54、56、59、60、62、63；按原峰值排名选出的48条中仅包含源模态54，其被置零，最终47个发声模态、1个静音槽。

复现试听：运行 `sim/render_piano_muted_compare.py`。输出 `build/piano_midi70_muted/AB_compare.wav`，先5秒ENG0原64模态参考，间隔1秒，再5秒ENG1静音版本。相同钢琴ABC激励、全力度、2秒按住、ADSR和body、无混响，使用同一整体增益，无单独归一化；这是离线模型比较，不是原先无法生成的旧ABC版本或实板录音。两条未经输出增益的全段RMS分别约0.009546和0.009557；转换相位与模态筛选仍会影响音色。附带验证：全零系数在残留非零状态及极端输入下输出均为0；非全零的a2=0记录仍被打包器拒绝。
