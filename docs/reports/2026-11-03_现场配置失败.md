## Flash 地址合同（未发现不一致）

构建资源合同：FLASH_BASE `0x800000`、FLASH_BYTES 16,777,216、FLASH_NOTES=32、NOTE_BANKS=1、RESOURCE_MASK=`110000101011`；资源 1,576,960 字节、SHA256 `e9de9737735eda50f03853c959d162868949b2a80ec202dce992d3924c3ca900`。

读取地址：

```text
0x800000 + instrument*0x20000 + note_offset + mode*64
低组 note_offset = slot*0x1000
高组 note_offset = (16+slot)*0x1000
公共控制页固定 0x980000
```

打包 BIN 没有 8MiB 前导空洞，必须从 `0x800000` 写入；固件从 0 写入。本轮没有在当前源码发现放置/读取地址不一致，也没有复现现场失败，因此不能宣布修复。未修改生产 RTL、未烧录、未读回实体 Flash。

## UI 冷启动缓存 P1（已复现）

位置：`rtl_FFT/src/ui/sidebar_ctrl.sv`，引入提交 `d3604c20`。

复位把 `scene.category/selection/edit_index` 及 `cat_q/sel_q/edit_q` 都设为 0，`changed_q` 也为 0。进入菜单 → 声音分类 → 编辑乐器不会改变这三个值，`scene_changed` 始终为 0；缓存从不填充，`limit_use` 保持复位值 0（正确应为 11），`count_use` 也保持 0（正确应为 2）。因此 DOWN 不能把乐器草稿从 0 改为 1，也无法在首次声音分类中向下选择音量。切换分类/选中项等操作可能偶然触发初始化，掩盖问题。

用优化前 `git show d3604c20^:rtl_FFT/src/ui/sidebar_ctrl.sv` 与当前模块并行接收相同复位/按键序列：2（打开）、2（声音）、2（编辑乐器）、1（下），旧版 draft=1、新版 draft=0；真实 `sidebar_system + dispatch + midi_voice_top` 集成夹具也复现 `limit=0/draft=0`。v2 综合网表确有 `count_q/limit_q/changed_q`，属于待核验固件中的实际逻辑范围。

建议：首次复位释放后强制填充缓存，或引入 `cache_valid` 并在有效前使用组合值；不要只依赖 scene 字段变化。加入“冷启动直入声音菜单”的定向回归，随机导航容易先触发缓存而漏检。该缺陷能解释“草稿不能变化”，但不能单独解释所有“配置已选到新值却返回失败”。

## 本地菜单混响（未复现）

`python3 sim/run_local_reverb.py --out build/local_reverb_review_20261103 --jobs 2`，夹具 `sim/unit/midi/tb_local_reverb.sv` 从真实按键输入进入 `sidebar_system`，经 `sidebar_ctrl → control_loop → config_dispatch → midi_voice_top → voice_router → weight_loader`；Flash 使用当前 1,576,960 字节资源 MEM，基址 `0x800000`，禁止读程序区；50MHz，内部供样模式（不含实体 ADC/UART/I2S）。

25.44 秒完成：7 次配置接受、7 次完成，检查请求 ID `0x0200` 及值、source=0 本地菜单、真实回复、`audio_state`、`active_values[2]`、`reverb_q` 和菜单 busy/result。

- 冷启动 → 打开菜单 → 效果 → 混响：NONE → HALL → BATHROOM → CHAMBER → NONE，四次全部成功。
- 持续 PAD 力度 100 时从 NONE 切 HALL 成功，松开后切回 NONE 成功。
- 将 `backend_source_valid` 置 0，菜单切 HALL 返回 6，`audio_state` 和 UI 提交值保持 NONE；这是显式注入门禁失效，不是通过实体/仿真 UART 制造隔离。说明来源门禁可以造成同类失败，但不能证明现场触发了这个条件或该未提交改动进入了用户 FS。
- `CHAMBER` 仍是占位直通，与 NONE 相同；提交成功但听感无变化是该预设当前设计行为，与菜单反馈失败不同。

未做模拟输出听测；未复现现场失败。

## 合并结论

- **Flash 代次/资源窗口**仍是独立风险：I05 记录的 0BFE 固件与 768KiB 旧资源窗口未关闭，见 [bugs.md](../bugs.md)。
- **UI 冷启动缓存**是已复现的功能回归，优先级 P1；需要修复并做定向回归。
- **来源门禁**可以制造“修改失败”，但现场是否触发未证；本地菜单混响本身在仿真中工作。
- 没有单一根因；下一步应带 UI 修复 + 明确固件/资源身份回板复测，并保留现场 `midi-link-diagnostic.json` 与菜单操作序列。
