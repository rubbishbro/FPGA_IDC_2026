## 一、逐乐器激励配置

2026-11-02：激励选择保持不变；小号已改为共享时分数据通路，验证和资源结果见小号时分复用优化（历史原文见 Git）。当时未做新版PnR或上板听音；当前交稿版本已完成PnR及用户整机功能验收，见[状态页](../status.md)。

| 乐器 | 激励生成 | 内部定标 |
|---|---|---|
| 吉他1 | 原2采样上升、单次拨弦 | 原幅度 |
| 吉他2 | 32采样上升、单次拨弦 | excitation_gen 内、输出 xmap 前固定右移3位（÷8） |
| 钢琴1 | 原32采样上升、4次击锤 | 原幅度 |
| 钢琴2 | 4采样上升、指数尾巴、4次击锤；PW+GAP=480 | 原幅度 |
| 小号 | 独立 trumpet_excitation；双极唇形、起音扰动、带限气流 | 离线三项移位增益校准基波 |
| 小提琴 | 原周期冲激 | 原幅度 |

吉他2的÷8属于激励模块内部，不在包络、混音、混响或声部增益处补偿。此前冻结系数的旋律对照中，32采样相对2采样的原始RMS增加约20.2dB；÷8抵消18.06dB，属于二进制近似定标，不是逐音等响校准。模态G/a1/a2与资源镜像字节保持原值。

钢琴2沿用试听时的计数行为：后续击锤上升比首锤多累加一次。因此PW+GAP虽为480，实际脉冲起点间隔为481/482采样；4采样档第二锤峰值约为最初目标的0.859375。此次没有将这一行为与激励选择一起修正。

### 小号独立模块

`exc_router.sv` 实例化并选择 `parts/trumpet_excitation.sv`，统一输出xmap和完成valid；voice_router等待整帧小号激励完成后再取快照。通用生成器在小号路径下保持清零。新增模块保留逐声部clear、重触发和Q24音高相位增量。

- 唇形：分段线性双极三角波，正开口长度为负闭口的4倍，负向斜率为正向的16倍；完整单脉冲的离散面积严格为零。不是旧实验的正弦波瓣。
- 基波定标：`tools/trumpet_excitation_rom.py` 离线计算，运行时仅三个有符号移位项求和。当前32个名义period的理论基波增益误差最大约0.23dB；这是波形系数的数学计算，不是RTL/音频验证结论。
- 起音扰动：23位LFSR产生有界三角分布，速率标准差约0.6%、幅度标准差约7.6%，采用移位反馈衰减，约28ms时间常数。不是原实验的高斯分布。
- 气流：移位缩放白噪声，稳态底噪叠加约40ms衰减的起音分量；一阶低通alpha=1/2和直流跟踪alpha=1/16形成约0.5–5kHz带限。与实验500–10000Hz二阶滤波不逐点等价。
- 运行时没有通用乘法、除法、正弦、指数、平方根运算。3位噪声缩放由条件移位与加法展开；包内移位表是综合期常量。

当前定标表只覆盖48kHz、MIDI51–82对应的32个名义period。音高调制通过相位增量持续作用；不要求对每个调制后频率另设period表项。未知名义period静音。改变音符窗口或采样率时需更新定标表。

源文件顺序已加入板级sources.f、公共sim/router_sources.list及独立前端入口。Python整数参考位于`modal_sim/trumpet_lip.py`；时分复用版已通过逐槽和完整声音链路对照，见上述验证说明。资源清单同步前端参数和来源哈希，BIN/MEM没有因本轮激励变化重新生成或烧录。

## 二、小号时分复用（TDM）实现与验证

2026-11-02。将 `trumpet_excitation` 的16路并行计算改成一套共享流水线，保留原整数唇形、随机序列、起音扰动、气流滤波和定标算法。

- 每个采样触发一次性锁存16声部的周期、音高增量、力度、门控、重触发和清音，计算期间不再读取变化中的输入。
- 同步状态RAM保存16份275位状态，以有效位实现清零／失效，不给RAM数据位增加复位网络。Gowin独立综合映射为8个BSRAM。
- 只有当前声部进入 `lip_config` 查表。三个定标项在TERM0/1/2串行执行，复用同一个32位可变移位器，不再每声部各复制三套。
- READ/LOAD/PREP/SCALE/PERTURB/TERM0/TERM1/TERM2/ADVANCE/WRITE/NEXT逐槽运行。16声部共177拍完成，整帧输出一次性发布，`xmap_valid`表示完成，不能再当作采样触发的直接复制。
- `voice_router`保留一笔待处理帧，等待小号完成后才启动模态引擎。小号的事件在输入提交时冻结，计算中禁止提交新的音高系数bank；通用激励仍保持原先的事件采样时序。
- 全局clear或禁用可在无采样tick时取消在途计算，失效全部状态且清空已发布输出。逐槽clear只作用于捕获的那一帧。

### 验证

`sim/run_trumpet_tdm.py`：独立Python整数参考，6500帧×16槽=104000输出比较；覆盖全部32项定标、非法周期、音高增量、逐槽清音、全局清音、计算中止、禁用、输入快照和原子发布。固定177拍完成。

`sim/run_performance_frontend.py`：六种音色共228000样本对照通过；测试按完成信号等待串行小号，不再假定一拍出结果。

`sim/run_trumpet_deadline.py`：真实部署Flash→16声部路由→48模态引擎→HALL混响，在50MHz、每帧1024拍下通过640个计时输出，最坏779拍，余量245拍；覆盖压力变化、计算期间的按键边沿、清音退休和重新起音。另用独立整数模型比较687帧的激励、包络、各声部和混音／混响输出，全部相等。

独立Gowin综合：3919 Logic（3320 LUT+599 ALU）、2766寄存器、8 BSRAM，无DSP；综合估算Fmax为82.657MHz，不能作为布线后时序结论。

整板最终综合：68961 Logic，已通过≤75000的资源门槛。证据为 `build/trumpet_tdm_20261102/board_final.log`、`board_final/instrument_board/impl/gwsynthesis/instrument_board_syn.rpt.html` 和 `verification.json`；输入哈希与最终源码逐项核对一致。

资源BIN/MEM字节未变，仅更新resources.json中的实现源码哈希。上述资源数字与暂停PnR的记录属于2026-11-02实施阶段；当前保留构建已通过整板PnR/时序，用户已确认全部功能验收通过，见[状态页](../status.md)。CLS等资源比例引用相应构建原始报告。
