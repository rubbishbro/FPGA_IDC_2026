# 本地合唱预设

`REVERB_CHORUS = 4` 为板端本地 UI 专用效果，菜单路径为“效果 → 混响预设 → 合唱”。内部枚举扩展到 3 位，原 NONE/HALL/BATHROOM/CHAMBER 的编号 0/1/2/3 不变。

本预设复用现有四路梳状延迟 RAM 和干湿混合流水，不增加独立效果器或 LFO。它是固定短延迟叠加的合唱近似，不包含动态失谐。

| 路 | 延迟样本 | 求和权重 | 反馈 |
| --- | ---: | ---: | ---: |
| 1 | 577 | 0.375 | 0 |
| 2 | 743 | 0.25 | 0 |
| 3 | 941 | 0.25 | 0 |
| 4 | 1193 | 0.125 | 0 |

干声 0.75，湿声 0.25；Q4.27 系数精确表示以上二进制分数。延迟容量仍为 2048。沿用现有预设切换、清空和输出有效时序。

合法值分为内部 `reverb_value_valid()`（0～4）和外部 `reverb_wire_value_valid()`（0～3）。共享 CONFIG 解析器、板级外部桥接、配置派发和音频后端均保留外部校验。外部传输格式、编号与返回码不变；通过有线或蓝牙发送预设 4，仍在配置解析阶段返回 OUT_OF_RANGE（线上结果码 03），不提交后端。本地选择合唱后，外部修改其它合法参数不会因此使音频快照失效。

UI 上限改为合唱，新增标签 128“合唱”与对应字体；原有字形 ID 保持不变。Web 上位机未增加该选项。

验证：

- `sim/check_reverb_tuning.py`：五种预设共 52,485 个采样，实际 RTL / 整数模型逐采样一致；检查原四种编号、默认干声直通、合唱参数、本地允许和远程拒绝。
- `sim/unit/comm/tb_chorus_wire_contract.sv`：真实共享解析器的有线/蓝牙两路 12 项检查；0～3 允许、4/255 拒绝且无后端提交。
- `sim/unit/midi/tb_local_reverb.sv`：真实菜单、派发器、音频配置状态机和资源装载链路，80 项检查通过；覆盖合唱的本地选择、外部拒绝、后续切换和失败保持。运行证据在 `build/chorus_ui_20261104/`。
