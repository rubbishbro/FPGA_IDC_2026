# 三分钟参赛视频脚本大纲

策划依据：2026-11-02 的 README、赛题要求、当前问题表、上板测试方案及合成引擎源码。本文是拍摄方案，不是功能验收记录。最终镜头以拍摄固件和资源配套后的实机表现为准。

暂定片名：**《指尖成乐——基于 FPGA 的实时模态合成电子乐器》**。

叙事主线：一次按压如何变成音乐。先听演奏，再解释交互和硬件合成，最后展示视听反馈与应用。

## 拍摄与剪辑约定

- 音频优先从板载 3.5 mm 输出接声卡采集，与相机画面同步；拍摄轻重力度对比时固定增益，关闭自动增益与归一化。
- 前 12 秒直接展示最成熟的演奏效果。全片不加盖过合成音色的背景音乐，技术解释段可使用轻声实机铺底。
- 至少保留一段手、键、屏幕同时出现的连续镜头，便于观察动作与反馈；肉眼观感不能作为毫秒延迟的测量依据。
- 每个演示镜头只突出一个结论。字幕用“力度控制”“模态合成”“实时频谱”等短词，框图只保留五个环节。
- 音色比较使用同一旋律、相近力度与固定录音增益；四音和弦与十六声部满载是不同演示，不能相互替代。
- 片长包含片头、片尾，目标恰为 180 秒；成片前计时朗读旁白，优先保留原声演示时间。

## 成片措辞与替换镜头

- 当前按 16 声部架构描述。两组 16 音音域不等于同时 32 复音；“16 复音实测”须另有实机证据。
- 延迟 ≤10 ms／≤5 ms、确定性无抖动、吞吐量等数字，取得对应实测后再加字幕。现有仿真与代码不能直接证明控制输入到模拟输出的总延迟。
- 当前六种已安装音色包含钢琴和吉他的不同引擎版本，不能说成“六类乐器”，也不能宣称六种音色同时混奏。
- 录音样本用于离线提取模型参数；正式演示音频从板端采集。Python 模型试听、网页三角波试听和 RTL 仿真音频应分别标注来源。
- 演奏事件录制不等于 PCM／WAV 音频回传。录制回传、蓝牙、手机 App、可调 EQ、持续压力调制等只在对应实机链路通过后安排镜头。
- 若 MIDI 引导尚未实板通过，将 2:15–2:35 替换为已通过的本机操作与演奏：10 秒菜单选音色，10 秒相同短句对比；旁白改为“通过本机菜单选择音色与效果，演奏者可以探索同一句旋律的不同表达。”
- 若混响或部分显示页未通过实机验收，使用已通过的波形／频谱和原声演奏填满对应时段，并删除相应旁白。
- 拍摄前核对固件身份与 Flash 资源配套，见当前问题 I05；按照上板测试完成选用音色、力度、复音、释放及显示的检查后冻结拍摄版本。
