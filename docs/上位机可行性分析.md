# 上位机工程可行性：连接、编排、试听与音频回传

整理：2026-10-29。本文维护电脑端实现边界、链路预算、模型试听、音频回传及后续实验；已实现首版与未来设计分别标明，具体软件操作/测试只在上位机README维护。早期公开资料调研为2026-10-22/23，本轮未重新验证外部产品、驱动或库版本。

目标用户/功能取舍/竞品只在 [产品文档](产品需求与竞品调研.md) 维护；线上字节合同只在 [PROTOCOL_V1](../rtl/drivers/analyzer/PROTOCOL_V1.md) 维护；MIDI状态/配置桥接见 [MIDI接入](MIDI演奏与通信接入.md)。旧稿的第二套命令表、host_link RTL和共享RAM资源/周期估算已移除，不再作为当前设计。

**2026-10-29 实施补充：** 本地 WebGL MIDI 编辑器、有线 Web Serial 与现有 v1 编码的首版已落地，入口和已验证范围见 [上位机 README](../web/midi-editor/README.md)。下面保留设计与后续能力分析；尚未进行物理 UART / FPGA 出声联调，电脑试听仅为三角波参考音源。

## 1. 分层与可行性结论

| 层 | 负责内容 | 当前依赖/边界 |
|---|---|---|
| 电脑编辑 | MIDI导入/导出、卷帘、力度、速度/循环、撤销/保存 | 首版已实现，范围见上位机 README；不宣称完整 DAW |
| 电脑连接 | 串口会话、协议编码、待回复请求、状态/能力展示 | Web Serial/v1事件发送已实现，板端MIDI消费者已有；能力查询/远程配置命令尚未定义 |
| 板端发声 | 输入/资源/状态/合成/效果/PCM输出 | 查架构与验收总表；不能由网页播放流畅推导硬件达标 |
| 电脑试听 | 本地模型渲染，或控制真实板端发声 | 两种模式明确区分；音色一致性需对拍 |
| 音频回传 | 真实PCM观测、分包、重组、录音/显示 | 当前v1无PCM命令，需正式扩展，先测实际链路 |

编辑与串口编码首版已完成，下一步优先验证实际串口/板端演奏闭环；多轨编辑不承诺多音色同时发声。全局音色/后级和槽预算由设备能力限制，UI播放前检查资源，不能用轨数代替声部数。

## 2. 连接与运行环境

电脑数据面采用UART，浏览器候选Web Serial；外接标准MIDI键盘可另用Web MIDI。板载USB串口桥不会因传MIDI字节自动枚举成系统MIDI设备。若希望使用系统MIDI口，另需虚拟端口/本地桥；不能把这层依赖隐藏在“浏览器即连即用”中。

早期资料指出Tang Mega Pro调试口经BL616桥接串口/烧录，桥固件与驱动会影响枚举、实际波特率和延迟。板卡管脚/资源只在 [平台资料](../reference_agent_readfirst/fpga_platform.md) 维护，连接前检查当前设备节点/USB枚举，不将历史VID/PID或“10Mbps上限”当实机保证。

| 方案 | 适用边界 |
|---|---|
| 本地网页+受支持浏览器+Web Serial | 首先验证安全上下文、用户授权、串口驱动及目标系统兼容 |
| 桌面壳+原生串口 | 需要离线安装、文件关联或受控调用烧录工具时再评估 |
| 本地串口桥+WebSocket | 需要支持缺少Web Serial的环境时的额外部署依赖 |

串口和烧录可能竞争同一桥/端口，烧录前释放串口。历史资料的驱动latency timer、udev解绑、固件实际速率异常仅作排查线索，按演示机器实际设置和测量判断。没有RTS/CTS的接线不能靠硬件反压保证无限突发不溢出。

## 3. 链路容量与延迟预算

8N1下每字节占10个串行bit，理论字节吞吐为 `baud/10`。以下仅以目标48kHz、16 bit计算**裸PCM负载**，不含头/CRC/转义/空闲，不是实测采样率或当前协议能力。

| 波特率 | 理论字节/s | 单声道96kB/s占用 | 立体声192kB/s占用 |
|---:|---:|---:|---:|
| 115200（comm默认） | 11520 | 833% | 1667% |
| 1M | 100000 | 96% | 192% |
| 2M | 200000 | 48% | 96% |
| 3M | 300000 | 32% | 64% |
| 4M | 400000 | 24% | 48% |

默认115200不支持上述实时PCM。SLIP在需要全部转义的极端数据下可接近翻倍字节数，还需计入每包开销和事件/回复/调度。选波特率以真实桥+驱动+RTL+协议持续有效吞吐为准，不能只看UART IP仿真支持的速率。若沿用历史48828.125Hz，按Fs重新计算，不能把它当当前固定采样率。

事件负载按实际v1编码长度、每秒消息量和最坏转义计算，不能再引用旧13B NOTE_ON包。候选音频扩展还应为事件/最终回复保留有界服务能力，避免录音流量阻塞松键/恢复。

延迟分解：主机事件/任务调度→串口写队列→USB桥→UART串行时间→设备队列/资源加载→采样调度/合成→PCM/FIFO/DAC。串行时间为 `编码字节数*10/baud`，其他阶段需实测；网页帧率、ACK往返或模型渲染时间均不能替代输入→模拟输出测量。本机压力和远程MIDI分别统计最坏值/抖动，不承诺旧稿估计的2–4ms。

## 4. 编辑、播放与数据模型

当前首版使用本地ES modules、DOM表单、WebGL卷帘与Canvas兼容绘制、Worker走带调度、localStorage草稿及JSON/MIDI导入导出，无需npm依赖或CDN。没有实现WASM物理模型、IndexedDB大工程库或完整DAW；这些若扩展应另按实测需求设计。

| 状态 | 责任 |
|---|---|
| 项目/轨道 | 音符、力度、速度、循环、音色/控制意图；撤销/重做作用于项目 |
| 走带 | 按音乐时间产生有序事件，不依赖requestAnimationFrame逐帧发送 |
| 连接/请求 | 保留SEQ和完整命令、待回复状态、实际成功/失败；显示设备确认值 |
| 播放准入 | 检查设备可用音高/音色、槽预算和支持控制器，不假装完整GM音源 |
| 显示 | 可跳过中间画面，音符/松键事件须保持顺序/语义 |

卷帘大量音符、回传频谱/波形可用GPU批绘，复杂表单不需要WebGL。先在目标机器测音符规模/交互帧时间，再决定优化，移除未经实测的“十万音符60fps”等保证。

停止/断连应清理已排队和已发出事件，真实消费者确认按MIDI接入合同执行；关闭浏览器定时器不等于设备静音。v1没有采样级远程时间戳；若后续确需调度字段，应先测抖动并正式扩展，不临时插入delay字段。

## 5. 本地模型试听与真实硬件试听

本地模型可放AudioWorklet/WASM等独立音频执行环境，界面任务不直接推进逐样本递推；迁移成本需实测。参考输入/参数、量化、采样率、激励/包络/效果/选核必须与所声称的目标一致。

[ENG1模型](ENG1_PY_MODEL.md) 负责整数契约和对拍；当前钢琴/吉他实际选eng0、激励也有更新，不能把eng1模型音频称为最新整机逐位一致的“数字孪生”。

三种结果分别标识：本地模型导出、RTL仿真导出、真实板端PCM录制。若验证模拟输出，还需DAC后采集；即便PCM回传正确，也不能直接证明模拟幅度/失真/延迟。

## 6. 音频回传与录制方案

| 档位 | 候选内容 | 开放条件 |
|---|---|---|
| 遥测 | 电平/声部/饱和/丢帧计数 | 定义统计与正式命令；电平不是频谱 |
| 监控 | 单声道16bit，或受控降采样 | 实测容量/队列/丢帧与播放隔离；降采样需抗混叠 |
| 全质量 | 与最终DAC输入一致的采样率/通道/16bit PCM | 连续吞吐和最坏协议开销均有余量 |
| 高位宽诊断 | 合成内部高位宽观测 | 单独说明量纲/带宽，不宣称DAC达到更高位深 |

抽头取后级之后、与DAC量化/缩放规则一致的位置，避免把64bit中间值当16bit音频。抽头FIFO/主机背压不能反压发声链；PCM命令、包长、计数和状态需要协议扩展，当前线上v1不支持。

候选包携带设备sample counter、样本数、通道/格式和会话标识。主机按设备计数拼接，缺口补静音并记录，不以主机到达时间冒充采样时间；复位/会话更换时重建时间基准。实时监听与长期录制分别处理时钟漂移/缓冲。

音频满队列时采用明确的有界丢弃策略并计数，不积压无限延迟；丢旧/丢新需按低延迟监听或顺序录制目标确定，不能声称丢最新天然消除积压。不自动重传实时PCM；停止/重连后不得拼接上一会话残留。

回传只观测声音，演奏通路仍由FPGA合成；模型/录音标签和延迟证据按验收总表维护。

## 7. 先导实验与实施阶段

| 阶段 | 实验/交付 | 判据 |
|---|---|---|
| E1连接 | 枚举实际桥/串口，打开/关闭/重连，验证115200与烧录互斥 | 节点/驱动/固件和接线可追溯，不依赖猜测VID/PID |
| E2容量/延迟 | 小回环/计数流bitstream，持续传真实编码数据，测多个速率/转义模式 | 记录净荷吞吐、丢包/错误、队列上界、往返分布；据此选择音频档位 |
| E3演奏闭环 | 最小网页→v1→真实MIDI消费者→合成/PCM/DAC | 独立起音/松键、同音重触发、压力/主机模式、停止/断线恢复可验证 |
| 编辑MVP | 导入/编辑/循环/撤销/保存，模型试听 | 项目可恢复，轨数与硬件槽预算分开显示 |
| 实际配置 | 接已支持目标/真实结果 | 错误/超时/重连无伪成功；未支持参数不发送虚构命令 |
| 回传 | tap、协议扩展、主机重组/WAV | 持续录制、计数一致、欠载/丢帧可见，不能影响发声 |
| 部署 | 目标机器彩排、离线/授权/串口释放、必要的桌面包 | 安装/重连/烧录/退出流程可重复 |

原按两人估计的工期不再作为当前承诺；协议/设备驱动已存在，真实MIDI消费者已存在，但物理UART与当前出声接线仍未闭环，应按依赖重新排期。32复音、同时多音色、每轨独立效果器和高规格回传都不能由编辑器功能推导为硬件能力。
