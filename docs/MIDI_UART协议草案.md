# MIDI / UART 通信协议草案

日期：2026-10-26。**仅设计讨论，不实现 RTL。** 本文区分用户已确定的功能范围和待讨论的传输／参数细节，编号及格式未冻结。

> 后续字节级设计与 MIDI 参考资料已放在 [`rtl/drivers/analyzer/`](../rtl/drivers/analyzer/README.md)。外层 header、SLIP、CRC 与样例以该目录的 [`PROTOCOL_V1.md`](../rtl/drivers/analyzer/PROTOCOL_V1.md) 为本次实现评审基线；本文件保留功能范围和此前讨论，不另维护第二套帧格式。尚未定案的音色／通道／DSP 参数不因文档落地而视为已实现。

## 1. 已确定的首版功能范围

### 1.1 MIDI 演奏消息

| 功能 | MIDI 1.0 消息 | 语义要求 |
|---|---|---|
| 音符、力度 | `9n note velocity` | velocity=0 按 Note Off 处理；非零力度保留原始 7-bit 值供适配层转换 |
| 松开按键 | `8n note release_velocity` | 释放对应音符；首版可忽略释放力度的数值，仍需消费该字节 |
| 弯音 | `En lsb msb` | 14-bit，中心 8192；范围待定；与颤音共用音高控制能力但不是同一参数 |
| 颤音深度 | `Bn 01 value` | CC1；具体深度映射和与当前颤音实现的接口待定 |
| 音量 | `Bn 07 value` | CC7；通道音量，不能与起音 velocity 混用 |
| 延音 | `Bn 40 value` | CC64（十六进制 40）；0..63 关闭、64..127 开启 |
| 音色选择 | `Cn program` | 只需一字节数据；标准 program 到本机音色的映射表待定，不直接强转本机枚举 |
| 全部松开 | `Bn 7B 00` | CC123；等价于该通道所有键松开，须与延音踏板／释放段区分于硬静音 |
| 紧急停止 | `Bn 78 00` | CC120；该通道 All Sound Off，不得仅置 fmap=0 后仍任由 release 发声 |
| 表情 | `Bn 0B value` | CC11；用户确定由线性调制模块实现；协议语义是独立振幅表情，不是 Pitch Bend |

`n` 是 0..15 的 MIDI channel。协议保留 channel 字段；首版合成器到底接收单个通道还是多通道，以及音色切换的作用域，尚未冻结。

### 1.2 私有配置

用户确定首版保留：

- **EQ 配置**。
- **混响配置**，包含本机 NONE / HALL / BATHROOM 预设选择；是否另带可调 amount 待定。

当前不自动增加 src_sel、bank、通道选择、波特率等远程配置命令。`src_sel` 已存在于顶层；是否由主机写入需另外确认。

### 1.3 暂缓清单

暂缓其功能实现，但解析器必须能正确识别长度并跳过，不得导致后续 MIDI 错位：

- Channel Pressure、Polyphonic Key Pressure。
- CC2 吹气、CC4 脚控等其他表情来源。
- CC5/65/84 滑音、CC68 连奏。
- CC66 选择延音、CC67 柔音、CC69 Hold 2。
- CC71/74 音色／亮度，CC72/73/75 包络时间。
- CC76/77/78 独立颤音速度／深度／延迟控制。
- CC10 声像、CC8 平衡及立体声控制。
- CC91 标准混响发送量、CC93 合唱发送及 CC92/94/95 等其他效果深度。首版混响通过私有配置控制，不将预设选择冒充 CC91。
- CC0/32 Bank Select、完整 GM 音色库。
- 通用 RPN/NRPN，包括经 MIDI 设置弯音范围、微调及粗调。
- 厂商 SysEx、GM/GS/XG 扩展配置；系统时钟／歌曲位置／传输同步。
- CC121 Reset All Controllers 及其他未列入首版的 Channel Mode 操作；不默认为已支持。
- 频率相关阻尼曲线。EQ 是幅频塑形，不等于改变模态 gamma。
- 音频回传、固件／系数下载、录音回传，不属于此次协议首版范围。

## 2. 两层协议，不把私有字节混进裸 MIDI

```text
UART / HC-05 透明字节流
  → 外层分帧、长度检查、校验、类型分流
    ├─ MIDI_DATA → 标准 MIDI 解析 → 演奏事件
    └─ CONFIG    → 私有命令解析 → EQ / 混响配置
```

ACK 是传输层回复，不是新增的一种演奏／配置功能。电脑和手机使用同一上层协议；两条物理 UART 若同时存在，应先明确会话／来源选择，不能把字节直接交错拼接。

MIDI 解析模块只收完整字节及 valid/ready，输出事件，不依赖 UART 波特率、HC-05 或外层帧。外层消息类型／配置命令也不塞进 MIDI parser。

## 3. 建议的外层帧（待确认）

建议采用二进制帧、SLIP 转义、CRC16：

```text
C0 | ESC(VER:u8 TYPE:u8 SEQ:u16 LEN:u16 PAYLOAD:LEN CRC16:u16) | C0
```

- 所有多字节整数小端；外层字段与本机 flash 大端格式无关。
- 分隔符为 `C0`；帧内 `C0 → DB DC`，`DB → DB DD`；其余原样传输。转义包含 header、payload、CRC。
- `LEN` 只计 payload 的未转义字节数；接收器必须限制最大长度，不按任意 u16 长度分配空间。
- CRC 覆盖 VER 至 PAYLOAD，排除分隔符和 CRC 字段；建议 CRC-16/CCITT-FALSE（poly=1021，init=FFFF，refin/refout=false，xorout=0000），结果按小端放入帧。
- 建议 VER=1；TYPE 暂拟 `01=MIDI_DATA`、`02=CONFIG`、`80=REPLY`，均非已冻结编号。
- MIDI payload 最多 32 字节；CONFIG 上限已确认收紧为 16 字节，并匹配具体命令长度，不补齐。共享帧缓存最大 payload 为 32 字节；具体 FIFO 容量和波特率需配合延迟预算确认。
- 先收到整帧、验证 CRC 和长度，才交付解析／执行；坏帧不改变音符或配置状态。校验失败时不信任其中的序号。
- 非法转义、超长、不完整帧都需恢复到分隔符边界；帧接收超时值待定。

首版不建议带音频时间戳：主机负责事件发送时刻，设备按接收顺序执行。此方案不能消除 UART 传输延迟和蓝牙抖动，不承诺采样级远程定时。

## 4. MIDI payload 与回复策略（建议，未冻结）

为降低错误恢复难度，建议上位机每帧放若干条**完整、带状态字节的短 MIDI 消息**，不把一条消息拆跨帧；不直接传 `.mid` 文件头、delta-time 或 tempo meta event。MIDI 文件解析和走带定时在上位机完成。

标准 running status、实时消息插入、SysEx 跳过等属于 MIDI parser 的边界能力，需单独确认测试合同。即使首版发送端不使用，也不能通过“把所有消息都按三字节切分”的方式解析。

建议：

- MIDI 帧不逐帧 ACK，不自动重发 Note On，避免重复触发和额外往返延迟；本机仍需正确处理合法的同音重复 Note On。
- CONFIG 必须回复 ACK / 错误；ACK 表示配置已实际提交，不是仅进入接收 FIFO。
- CONFIG 采用绝对设置值；同会话重发同一 SEQ、同一内容不得重复产生副作用。序号回绕、回复缓存与会话重建细节待定。
- 配置与演奏保序。如果前一配置需要等待加载／安全边界提交，后续 MIDI 不能提前越过它；队列和反压规则待定。
- EQ 滑杆连续变化可在主机合并为最新设置，避免大量配置阻塞紧急停止／松键消息；不在尚未发送完的一帧中间插入别的帧。
- 仅丢弃损坏 MIDI 帧可能丢失 Note Off 而挂音。断线、FIFO 溢出、丢包后的清音／会话恢复必须设计；超时和是否保持演奏尚未冻结。

## 5. 演奏事件到本机的语义边界

```text
Note On / Off / velocity / sustain → 音符状态管理 → fmap_ext
Pitch Bend / CC1 / CC7 / CC11     → 对应控制寄存器／调制接口
Program Change                   → program 映射／本机音色选择
EQ / Reverb CONFIG               → 后级配置
```

- CC7 与 CC11 分开保存；建议振幅控制 `gain = volume_gain * expression_gain`，CC11 使用用户指定的线性调制路径，不覆盖 CC7，也不靠改起音 velocity 实现。
- 不把 CC11 或 CC1 直接写成 fmap 压力：否则可能意外改变力度、触发门限或压力调音。
- sustain 关闭后对已松开的音符进入释放，而不是无条件清除所有按住的键。
- CC120 与 CC123 分开。CC120 标准作用于指定通道；若 UI 的“紧急停止”要全设备静音，可以对所有通道发送 CC120，但共享混响尾音是否清除还需本机策略。
- 全设备紧急停止若要求无残留，还要同时考虑排队事件与混响状态；单纯停止 sample tick 可能冻结而不是清除内部状态。
- 不支持的 program、超出 32 音清单、同音重叠、声部抢占、切换 src_sel 的处理由适配层规定，不由 MIDI 字节解析器擅自决定。

## 6. 私有命令的初步内容（待确认）

### EQ_SET

建议表达中心频率、增益、Q 和段使能，而非直接上传未校验的 IIR 系数。候选编码：Hz 用 u16，dB 用 signed Q8.8，Q 用 unsigned Q8.8；具体段数、增益／Q 范围和滤波器类型待定。多参数在安全样本边界一起提交，越界配置拒绝，不部分更新。

### REVERB_SET

建议先只选预设，显式规定通信编号，例如 `0=NONE / 1=HALL / 2=BATHROOM`。

**不可直接强转现有枚举**：当前 `rtl/router/pkg/router_pkg.sv` 顺序为 `BATHROOM=0 / HALL=1 / NONE=2`。通信编号需明确转换；上述 wire 编号仍为建议。

若首版还需要 amount，要另定参数与路由修改。现有 `reverb_router` 的干湿增益随预设固定，没有独立 amount 输入。不能只加一个协议字段就宣称已支持。

## 7. 接下来优先讨论的决策

1. 首版单 MIDI 演奏通道／单音色，还是需要多个通道同时使用不同音色？当前 router 是全局 `inst` 和共享后级，不能据标准带 channel 就宣称支持多音色。
2. 是否采用第 3 节的 SLIP + 类型 + 长度 + SEQ + CRC16 外层帧。
3. EQ 段数／形态、混响是否首版仅三个预设。
4. 弯音范围、CC1 最大深度、CC7/11 增益映射、断线／紧急停止策略，作为适配层与控制模块合同逐项冻结。

以上决策确认后，再按模块设计事件接口与测试用例；本文件不代表实现或验收完成。
