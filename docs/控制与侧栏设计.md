# 统一配置与侧栏设计

整理：2026-10-28。实现核对基线为 2026-10-27 的 `8e9d1cda` 及工作区。本页统一维护配置职责、参数字典、交互、control_loop、提交/结果、CDC 与整机接线；已实现和待接音频后端分别标注。原侧栏方案、实施说明、Loop 设计和控制调研的有效内容合并于此。

线上协议与演奏状态见 [MIDI 接入](MIDI演奏与通信接入.md)，音频实例树见 [代码架构](../CODE_ARCHITECTURE.md)，日期化测试结果只在 [工程评审与验证](工程评审与验证.md) 记录。

## 1. 职责和实现结构

```text
原始 X/Y + valid → joystick_adapter → sidebar_ctrl ─┐
双按键事件 ──────────────────────────────────────────┤
外部已适配统一请求（来源槽1） ────────────────────────┤
                                                    ▼
control_loop → config_dispatch
                  ├─ 显示目标快照 → sidebar_mailbox → 像素帧头应用 → 结果
                  ├─ 摇杆重校准 → 等 calibrated 恢复 → 结果
                  └─ backend 请求 → 等真实 tag/id 结果 → 实际值/结果
原 FFT/WAVE/FALL 底图 → 一拍对齐 → lcd_sidebar 覆盖 → RGB/DE
```

| 模块 | 拥有的状态与职责 |
|---|---|
| `rtl/config_pkg.sv` | 参数 ID/范围/默认值、64 bit 请求、72 bit 结果及显示快照类型 |
| `rtl/control_loop.sv` | 轮询指针、一项暂存、来源编号；不解释参数或确认生效 |
| `rtl/config_dispatch.sv` | 能力/范围校验、pending/active、消费者提交与最终结果 |
| `src/ui/sidebar_ctrl.sv` | 菜单、草稿、指针、请求和结果展示 |
| `src/ui/sidebar_mailbox.sv` | 整包显示快照跨域及应用确认 |
| `src/ui/sidebar_system.sv` | 摇杆、轮询、配置、CDC 和显示的集成 |
| `src/display/lcd_sidebar.sv` | 字模读取、侧栏覆盖、动画及像素对齐 |

表中 `src/` 位于 `FFT_spectrumshow/`。模块在各自系统时钟上响应事件/握手：router 推进采样/声部/DSP，comm 推进串口/帧/会话，配置端协调提交，像素帧节拍推进显示。loop 不轮询所有模块，也不调度声音或动画。实时压力、MIDI 音符和音频样本走各自通路。

`backend_supported[19:0]` 仅在真实消费者准备好、默认值一致时开放。显示位6..10始终由本地处理；校准位16随 HAS_JOYSTICK 开放，超时2s返回失败。未接项可以查看但不提交，外部请求返回 UNSUPPORTED。能力位不是资源存在证明，音色枚举也不是已交付音色清单。

样式不能截取低两位：未注册的256等编号返回 UNSUPPORTED。扩展时同时注册目录、菜单和绘制分发；不改变传输格式。默认值来自 cfg_defaults/display_defaults，避免 UI 与后端各自维护一份。

## 3. 交互与显示行为

实际采用分类→参数→行内下拉/数值编辑。主画面保持800×480全屏坐标，左侧288px侧栏覆盖底图，不缩放或停止FFT。中文/ASCII字库含180个16×16字形，侧栏按像素帧节拍用12帧 easing 开合，帧内宽度稳定。

| 状态 | 操作与防误触 |
|---|---|
| 主画面 | 连续dx/dy控制指针；进入左侧16px热区并保持180ms开栏 |
| 开栏/层级变化 | 等摇杆回中，避免开栏时仍左推立即退出 |
| 列表 | 上下选择并支持连发，右推进入，左推返回，根菜单左推收起 |
| 编辑 | 上下修改草稿；音量/深度步进1%；右推确认，左推取消且不发请求 |
| 斜向 | 只执行主轴；比较abs(dx)/abs(dy)，相等沿用上一主轴，首次优先Y |
| 应用中 | 可以查看其它菜单；同一来源已有未完成请求时不覆盖它 |
| 关栏 | 指针回到热区外，离开热区后才允许再次触发 |

进入/确认/返回只消费非连发事件。一次性动作经 UI 二次确认后只发送一次，不能被后续动作覆盖。动画不等待 FFT 新结果，也不以动画播完作为配置完成依据。

`ui_demo_top` 默认 SIDEBAR_UI=1；key0短按下/长按确认，key1短按上/长按返回，首次按键开栏；SIDEBAR_UI=0 保留旧tab。独立demo使用三音/扫频源，HAS_JOYSTICK=0，没有真实ADC引脚，只开放显示项。实物摇杆合同见 [适配器说明](../rtl/drivers/JOYSTICK_ADAPTER.md)。

## 4. 统一请求、结果与状态

```text
请求 64 bit：{tag[15:0], id[15:0], value signed[31:0]}
结果 72 bit：{tag[15:0], id[15:0], result[7:0], applied_value signed[31:0]}
result：0 OK，1 UNSUPPORTED，2 OUT_OF_RANGE，3 DENIED，4 FAILED
来源槽：0本地UI，1外部已转换请求
```

来源必须独立于ready提出valid，背压时保持整个载荷；正常完成只有valid&&ready同拍交付，复位为取消例外。tag由来源管理，在该事务完成前不得复用。结果码是内部配置合同，线上通信结果码须另行转换。

逻辑上区分草稿/desired、已接受的不可变pending与真实active。接收请求只是转交；只有实际提交成功才更新active，失败保留原值。结果持有到原来源接收，匹配tag/id；后端返回错误tag/id或非法成功值会报FAILED。动作结果不充当参数读回。

MIDI模式下，音色0100和绑定通道0501按同一事务提交（用户已确认），任何一项编辑都生成一致的音色/通道目标。不得先后发两笔独立请求；后端清理、装载、成功提交后，dispatch同拍更新两个实际值，显示mailbox发送同一份快照。PAD模式音色独立；切回MIDI时重新按通道映射联合确认。映射、失败静音与资源校验合同见[MIDI总体合同8.5](MIDI演奏与通信接入.md#joint-midi-configuration)。

现保留72bit标量结果，并在backend侧增加audio_config_t实际快照。AUDIO_BACKEND=1时，启动同步实际默认值，随后仅在匹配的成功事务上同拍更新音色/通道/来源/音区/混响；无效快照和错误结果不提交。具体能力、同域要求、资源限制和接线见[MIDI联合配置实施](MIDI演奏与通信接入.md#joint-config-backend)。

每来源最多一笔未完成事务；dispatch同时执行一笔，loop可额外暂存一笔。尚未发送的草稿/显示目标可以合并，已握手的事务不得覆盖或合并，音符事件更不能只留最后一个值。结果回传不等下个poll_tick。

## 5. control_loop 合同

| 接口 | 约定 |
|---|---|
| SOURCES / REQUEST_W | 通用默认1/32且均≥1；侧栏实例2/64 |
| clk / rst_n | 请求端口同域，异步低有效复位，同步释放由集成保证 |
| poll_tick | 单拍轮询使能；侧栏1kHz，空闲时最多接一条 |
| src_valid/ready/request | 分来源输入 |
| req_valid/ready/request/source | 一项暂存输出和原来源，source宽max(1,clog2(SOURCES)) |

从rr_next扫描，跳过空来源，显式回绕支持非二次幂；仅实际接受时推进优先级。满槽不接新请求，出队同拍不入队。poll_tick只限制入队，暂存交付不受tick限制。复位取消未交付项、起点回来源0，复位期间不给ready；交付后载荷可保留上次值，只有req_valid=1时有意义。

无积压且下游可接收时，轮询额外等待小于一个tick周期加少量时钟；1kHz约小于1ms。加载/安全点/结果背压和排队另计，不能把它当演奏总延迟或业务完成时间。

## 6. 消费者提交边界

| 目标 | 成功依据与后续设计 |
|---|---|
| 显示（已实现） | 更新目标/epoch，整包跨域，目的端帧头应用并返回匹配epoch后回复 |
| 校准（已实现） | 触发后先观察calibrated撤销，再等重新完成且不stale；超时失败 |
| 乐器（已接后端仿真） | 固定联合目标，等待真实加载/排空和错误结果；ready/done不直接当成功，资源位必须对应正式镜像 |
| 音区/来源/通道（已接后端仿真） | 先有序清理旧归属，再整组装载并提交实际快照；MIDI音色/通道联合更新 |
| 音量（待接） | 样本安全点接收目标，另定义短斜坡；接收斜坡目标与斜坡结束分别表达 |
| 混响（已接后端仿真） | 显式枚举转换，首版通过清理/重载后整体切换；未新增混响算法/实物听感结论 |
| 力度调制（待接） | 参数快照在后台更新边界应用，实际力度按声部独立计算 |
| 清音已接；会话/恢复默认待接 | 清音等待真实维护；会话重建与恢复默认能力继续关闭 |

同一时刻换参数不自动保证流水一致：已进入DSP的样本应继续使用对应参数。原子提交也不等于无爆音，仍需平滑、状态清理/保留或交叉淡化。voice_router已引出load_err/table_valid，pad_voice_top也已透出；reload内部取上升沿挂起，外层仍须维护事务上下文而非长期重发。

### 力度线性调制与音色塑形

每槽独立force来自压力值或MIDI消费者。建议定义 `f=clamp(force,0,255)/255`、`d=depth/1000`，`parameter=base+enable*d*f*allowed_delta`，再按资源范围限制。不是LFO速度/波形设置，也不使用16键平均力度。

新主引擎已增加持音压力变化触发的一阶调制；UI开关/深度仍未接，开放前需解决参数快照、同址读写和逐模态提交。两组16音loader及配置已接仿真，正式连续32音资源仍待统一；当前钢琴镜像仍为16个不连续MIDI音。

输出EQ、逐模态权重和按音高响度补偿有不同产品含义，定义见 [产品文档](产品需求与竞品调研.md#音色塑形语义)。实现上，腔体不等于用户EQ；模态权重改变幅度，不改变频率/阻尼。改激励增益可能只影响下次触发，C seed与eng0输出权重也不能机械套用同一G字段。新增DSP/系数写口须仲裁、量化/极点/峰值检查和安全提交，不默认线性插值IIR系数安全。

## 7. 整机端口与时钟

sidebar_system控制口属于ctrl_clk，读图/显示口属于pix_clk。独立demo控制50MHz、像素约33.333MHz，CTRL_HZ必须匹配实际；100MHz参数能力不等于已通过整机时序。

| 端口 | 接线合同 |
|---|---|
| joy_sample_valid / joy_raw_x/y | pad_voice_top成对原始14 bit坐标；不能接极坐标pad_pos |
| key_valid / key_event | 可选兼容事件：1下、2确认、3上、4返回；不用绑0 |
| ext_cfg_valid/ready/request | 已转换并检查权限的外部请求，槽1 |
| ext_rsp_valid/ready / ext_cfg_response | 最终结果，保持到握手；不是UART发送字节 |
| backend_supported[19:0] | 真消费者能力位图 |
| backend_valid/ready/request/source | 后端提交；source为UI=0/外部=1 |
| backend_rsp_valid/ready/response | 等真实结果，tag/id匹配，保持到握手 |
| backend_audio_valid/state/fault | AUDIO_BACKEND=1时接实际音频快照及故障；ctrl_clk须与音频clk同域 |
| frame_pulse / lcd_valid / pix_x/y | 像素扫描时序 |
| q_y/q_ov / wave_rd_* / curve_rd_* | 原real_audio_chain显示读口，保留地址窗口/缩放 |
| lcd_r/g/b / lcd_valid_out | 同步字模使坐标/DE延迟一拍；外层再寄存RGB时一起寄存DE |
| active_values / ui_scene / sidebar_width | 实际配置/场景/动画调试观察 |

两域共用异步复位断言，各域同步释放，不允许只复位一端。在途完整快照保持到跨域确认，目的端帧头应用；逐位打两拍不能替代整包合同。显示可按既定策略合并未发送目标，不能丢正式事务的结果。

`comm_top.cfg_shadow`不能截短为64 bit请求：物理source_id/SEQ/command/负载和回复上下文须保留，EQ等复合命令另适配。槽1无法区别有线/蓝牙，远程权限在保留物理来源处执行；细节归MIDI接入文档。

主合成PCM/FIFO/I2S与可视化音频跨域独立于配置mailbox，不能借此声称音频CDC已接通。若增加曲谱/伴奏/琶音，另由tempo/transport按音乐或样本计数调度，不扩大loop职责。
