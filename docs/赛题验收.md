## 1. 证据口径

源码存在、功能仿真、独立时序探针与当前整机上板分别记录。历史歌曲工程、Python WAV、LCD 测试音源均不能直接证明当前压力→合成→DAC 主链合格。

本页是要求→实现→验收证据的唯一总表，原架构检查表和设计报告底稿已并入。日期化测试数字见 [工程评审与验证](工程验证.md)，源码缺陷/复现/关闭条件见 [问题台账](bugs.md)，模块实例树见 [代码架构](../CODE_ARCHITECTURE.md)，不在多份总表重复更新。

## 2. 基础及总体要求

| 要求 | 已有实现 | 达标前还需什么 |
|---|---|---|
| 自研交互，至少 2 个独立可控维度 | 统一板级已接4×4压力、摇杆X/Y与菜单；压力缩放/滞回、逐轴死区及2×2 LED映射有功能仿真 | 真实 ADC/矩阵位置、独立演奏映射与多键稳定性；控制菜单的摇杆不自动等于第二个声音表情维度 |
| HDL 逐样本实时合成 | 双 bank voice_router、eng0/eng1、激励/包络/混音/腔体/混响 | eng1流水/空作业已修且本次256组对拍通过；持续音色已接周期冲激/ADSR并建立真实表整数对拍；混响数值、物理时序和实板仍待验 |
| 禁止预录 PCM 触发播放 | 当前核为系数/状态递推；Flash 保存参数；电脑 WAV 用于验证 | 审核最终综合源清单，现场演示通过同一输出链实时改变声音 |
| I2S→DAC 发声 | 统一板级已接PCM16/FIFO/I2S、真实三PLL及引脚约束，功能回归已有 | 既有3ED7包已通过PnR并烧录；合并后源码需重新签核，模拟出声/连续播放仍须实板验收 |
| 总延迟 ≤10ms | 独立模块/时序数据已有，尚无当前输入→DAC 测量 | 冻结计时起止，计入扫描/加载/排队/音频缓冲，测最坏值和抖动；平均吞吐不能代替延迟 |
| ≥4 路独立可闻声部 | 默认 16 槽，前后半 bank 并行；Flash 按 slot 独立音高，钢琴镜像 16 音 | 至少四个不同音高的独立起音/松键/控制、频谱/听音；四种B表已有16槽长测和线端PCM对拍，仍不能代替实物声学验收 |
| 单音实时变调 | PAD吉他后台调制已接，持音压力变化也挂请求；一阶近似只调最低4模态 | 整帧安全提交、独立UI开关/深度、音准/稳定性及最坏周期验证；ENG1 Bend/CC1已接；实际音准与时变稳定性仍需验收 |
| ADSR 包络调控 | 钢琴ADSR和压力dyn0模块已有（当前吉他已启用ADSR、满幅sustain和约600ms满幅release）；四种eng1持续音色已用逐槽A/R的ADSR | 持续音色松键/清理退休已建立回归；开放参数、真片和听感另验 |
| 多声部实时混音 | 逐槽乘 Q1.31 包络，再跨槽 64 位累加、腔体/混响 | 满力度溢出/削波、全槽独立性、连续供样与真实幅度定标 |
| 多音色/至少 2 音色自由切换 | 统一乐器编号、选核、待松键重载、逐槽资源布局 | 钢琴/吉他默认16音镜像已匹配当前表，联合配置与失败保护已接；正式资源、忙时panic、真片/实板验收待收口 |

赛题对包络的补充答疑可作为讨论依据，但不替代实际可控行为和验收口径。当前乐器枚举是目录；已安装六音色见音频设计，不能按枚举数计算已交付音色。

## 3. 拓展要求

| 拓展方向 | 当前进度 | 尚缺闭环 |
|---|---|---|
| ≥32 复音，或单音 ≥32 加法分量，或多条并行物理建模单元 | 默认 16 槽×64 物理模态、双 bank 并行；钢琴计算64/吉他20/eng1首版48，物理存储64，按顶层限幅 | 选择实际申报分支，统计有效且可闻的独立分量、谱峰、吞吐和满载；三个分支不要求同时满足 |
| ≥3 维表情、力度/滑音/颤音 | 压力参与激励/动态包络/吉他起音调制；摇杆原始双轴和 UI 已有 | 明确独立输入到声音参数的映射；同一个压力驱动多个参数不自动成为三维；持音变调待收口 |
| FPGA 效果器 | 五段腔体、四梳状混响和 NONE/HALL/BATHROOM | 本地与板级REVERB_SET已走真实提交；混响宽乘积、预设切换/听感仍需收口，EQ明确返回NOT_READY而无DSP |
| ≤5ms、确定性低抖动 | 未有当前整机测量 | 与基础延迟同一路径、同一定义，测最坏值；探针 Fmax 不代替此指标 |
| FPGA 可视化反馈 | 独立demo有FFT/BARS/WAVE/FALL；统一板级已接真实菜单、PCM抽头和像素域FFT/波形/极坐标 | 验证实板连续显示、与声音同源及切换稳定；合并后fmap叠加层另验 |
| 脱机 LED 曲目指引 | 统一板级已有压力格→2×2 LED映射，尚无曲谱指引 | 曲谱格式、键位映射、节拍/播放控制和实物指引 |
| 蓝牙+手机 App | HC-05 透明 UART、可选 STATE、双链路协议和会话协调已实现 | 实物HC-05、手机软件和物理链路恢复；MIDI消费者已有但尚未完成整机联机；HC-05 不应写成已经实现 BLE/GATT |
| 在线曲谱下载/自定义键位 | 产品规划，逐槽音高资源已有基础 | 来源/格式/缓存、映射保存/下发/冲突规则及应用闭环 |
| 演奏录音回传 | 有线TYPE82演奏事件录制已接入；PCM/WAV回传仍未实施 | 音频抽头/分包/主机存储/手机接收；MIDI 事件记录与硬件 PCM 实录分别验收 |

拓展项按最终选择实施，不把所有列举功能都算基础缺陷。电脑多轨编辑器与有线UART软件首版已有；WASM物理模型试听、精细频率塑形和跨端预设仍属规划。软件编辑能力不计为硬件复音/多音色验收。

## 4. 现场证明材料

1. 同一路主合成/DAC 链支持可选多频测试模式，展示独立谱峰；不能由 LCD 内置测试源替代。
2. 记录承诺的声部/模态数、有效音高/幅度、首帧/稳态/切换周期、实际采样率及 `数量×采样率`。
3. 通过演奏实时改变输出，并检查最终源清单，证明硬件生成。
4. 用约定输入/输出标记测延迟，保存重复次数、最坏值、抖动及测试条件。

## 5. 当前优先级

- 优先复核音量偏小及合并后的资源/标定身份；既有3ED7包的时序通过不覆盖此次新源码。忙时panic仍按独立合同处理。
- 四种eng1周期驱动、ADSR与释放退休已实施；冻结正式六种32音范围、配套资源及烧录清单。
- 解决混响乘积、调制表提交和真实控制消费者；完成真Flash、ADC键位与四路独立可闻声部验证。
- 现有PnR报告作为失败基线；重新通过时序后做DAC连续播放和≤10ms测量，第二阶段接独立PCM可视化抽头。
- 上位机优先做物理UART演奏联调；App、录音回传、WASM和LED指引按选定范围推进。

## 6. 设计报告素材与交付材料

报告可以围绕“离线参数准备、硬件逐样本合成、交互配置、通信接入、可视化反馈”组织，具体结构引用架构导读和各专题合同。录音只用于参数提取/对比，模型WAV、RTL仿真WAV、板级录音分别标明来源。正文按前表标注已有/待接/待测，不再维护一份容易漂移的完成勾选表。

可说明的设计取舍：参数化模态递推；双bank分离并行存储访问、复用混音后级和后台调制；配置区分接收与真实生效、显示帧头提交；通信分层并保留物理来源及恢复确认。这些是本项目采用的方法，不宣称算法/协议/产品形态首创。产品需求论证和竞品来源统一引用 [产品文档](产品调研.md)。

最终交付应绑定源码/参数/约束/工具版本与bitstream，附当前板级资源/时序、连续播放欠载/削波、四路独立音高/松键、两套真实音色、持音变调及延迟测量。现场多频测试必须走正式合成/DAC路径；独立LCD测试源不替代该证据。
