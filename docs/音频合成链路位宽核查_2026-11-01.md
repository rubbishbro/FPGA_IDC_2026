# 音频合成链路位宽核查（2026-11-01）

结论：当前下载版本的主链小数位可以对齐，未发现整体差 2^8/2^9/2^24 的缩放错误；但混响有确定的移位前乘积截断，另有一处潜在的饱和方向错误，不能给出“全链路满 signed64 范围正确”的结论。本次只核查、增加测试与报告，没有修复或重新下载 RTL。

## 核查版本与范围

与 `build/board_20261101_current/input_sha256.json` 的 109 项构建输入逐一核对，全部一致。器件上次下载位流 SHA256 为 `d73374bc839e43022750d37809071e2d1cf9129ad0cbf020d5f6c5fc9b641fe6`。本次审核的是这份当前工作区源码，包含未提交的录制接入；不是任意旧 demo 或 `rtl/core` 的另一套引擎。

范围：PAD/MIDI 力度选择、激励、资源量化/加载、eng0/eng1、调制、ADSR、声部求和、腔体、混响、声像/ITD、PCM、FIFO、标准 I2S 和 PT8211。模拟功放增益、电压/实际接线、板上 Flash 系数区的读回不属于 RTL 数值测试已证明的范围。

## GAIN 与引脚

实际生产约束是 `rtl/platform/tang_mega_138k_pro/instrument_board.cst`。当前顶层没有 GAIN 端口，CST 没有 GAIN 约束。

| 信号 | 管脚 | 行为 |
|---|---|---|
| amp_bclk | A19 | I2S 位时钟 |
| amp_ws | A18 | I2S 字选择 |
| amp_din | A20 | 动态串行音频数据 |
| amp_sd | A17 | 复位、失锁、音频未就绪或故障时低；正常就绪时高 |
| A21 | 未分配 | 没有 RTL 高/低赋值 |
| B21 | 未分配 | 没有 RTL 高/低赋值 |

生成物 `impl/pnr/device.cfg` 为 `unused_pin = default`，不能仅根据 RTL 给未分配脚断言某个实测电压。若功放 GAIN 接在 A21/B21，当前固件没有主动驱动它。完整的51项 IO_LOC 见[当前整板引脚约束](当前整板引脚约束_2026-11-01.md)。ADCV_P/N 为专用模拟脚，另列 N12/P11。

## 实际定点契约

下表用 F 表示小数位数，避免 Q 格式中整数位是否包含符号位的歧义。

| 处理级 | 输入/系数 | 运算与输出 | 结果 |
|---|---|---|---|
| PAD 力度 | 原始8位 | 负电压码归零；正数乘4，达到范围后饱和255 | 未发现溢出回绕；校准会影响力度，不是音频小数点 |
| MIDI 力度 | 7位 velocity | `{v,v[6]}` 扩展为8位，127→255 | 与PAD进入同一 strike_level |
| 激励 | 8位力度，SHIFT=16 | signed32，F24；`250<<16` 对应0.9765625 | 当前范围远低于 signed32 上限 |
| eng0矩阵系数 | a11/a22 F28，a12 F30，a21 F23，gq F32，gv F34，wo F29 | 32×32→64；各乘积独立舍入、按字段右移；q/v饱和32位 | 输出仍F24，64位模态求和 |
| eng1 ABC | G/a1 signed26 F24；a2 unsigned24 F24 | 三项64位乘积/累加，加2^23后右移24，饱和signed32 | 状态/输出F24，64位求和；有效字段正确符号扩展 |
| modulation0 | lambda F30，斜率F29 | 乘积F59；右移31/29/31/30写回a11/a12/a22/wo | 与目标字段F28/30/28/29一致；a21由a12右移7再取负为F23；前四模态限制保留 |
| ADSR | 非负signed32，F31 | Attack 用33位加法限到0x7fffffff；Release按实际lvl减步长 | 包络非负；钢琴R_STEP=27962@48k，从25%S约400ms |
| 声部包络 | signed64 F24 × signed32 F31 | 96位乘积，取[94:31]等效算术右移31 | 输出signed64 F24；合法包络≤1时不丢有效幅度高位 |
| 混音 | 每声部F24 | 64位相加 | 不改变F；由引擎状态/系数位宽得到的16槽保守上界也不需要64位以上累加 |
| 腔体 | signed64 F24，系数signed32 F27 | 输入加4位精度→68位F28；100位乘积、104位累加；每段>>27；末段>>4 | signed64 F24；512组宽输入对照通过 |
| 混响 | signed64 F24，系数F27 | 应先保留96位乘积，再>>27 | 当前表达式存在移位前截断，详见问题 |
| 声像 | signed64 F24 × 增益F12 | 77位保留乘积；无提前右移 | 小数位变F36 |
| 分数ITD | 历史F36，插值权重F6 | 84位输出，继续保留6位精度 | 小数位F42；含全signed64正负极值的独立参考通过 |
| PCM16 | 单声道F24，或声像后F42 | 舍入后右移9+H，或27+H，再饱和16位 | 目标F15；H为输出余量位数 |
| FIFO/发送器 | `{L16,R16}` 32位一对 | 跨域FIFO保持声道成对；标准I2S每声道32时隙中16有效位，余位补0；PT8211每声道16位LSBJ | 线端解码、顺序和格式测试通过 |

当前 H=0、声像居中每声道增益2896/4096≈0.70703125。这些是明确的输出增益，不是位宽丢失。钢琴Sustain=536870912/2^31=25%，不是符号翻转或格式不一致。

内部F24不等于输出24位PCM。16位有效数据在较宽I2S字中按MSB对齐、低位补零，会保持归一化幅度，不会因此比24位接收器小256倍；损失的是有效精度。若要外部I2S保留24位，需要另做PCM24/FIFO/发送器改造，板载PT8211继续16位。

### 资源与注释

钢琴和吉他资源生成器实际使用的 SH 字典与 `modal_step_pkg` 相符。重新量化现有文本后，与仓库钢琴64KiB、吉他有效64KiB BIN逐字节相同；两工具 `--verify` 均无系数量化饱和。loader只按大端32位搬运，不插入另一套小数位。

存在旧注释：例如 `piano_flash.py` 文件头仍写旧gq F31/gv F27/wo F15，`modal_step_pkg` 的旧峰值表也有旧位数；实际执行常量为F32/F34/F29。它们是文档维护问题，不能拿旧注释当作当前运行格式。

## 确认的问题

### W1：混响干湿乘法在移位前截断（历史F09仍存在）

`rtl/router/routers/reverb_router.sv:156` / `:157`：

```systemverilog
dry_w <= (xd[3] * gd) >>> G_FRAC;
wet_w <= (wet * gw) >>> G_FRAC;
```

目标69位使乘法表达式也只保留69位，而64×32完整乘积需要96位。移位在截断之后发生，末端饱和不能恢复丢失的位。直接用生产NONE路径复现：

| 输入整数 | 当前输出 | 正确输出 |
|---:|---:|---:|
| 2^24 | 2^24 | 2^24 |
| 2^40 | 2^40 | 2^40 |
| 2^41 | -2^41 | 2^41 |
| 2^42 | 0 | 2^42 |
| -2^42 | 0 | -2^42 |

NONE的正输入从2^41开始越过乘积符号边界。2^41在F24下是实际幅度131072，远大于PCM归一化满幅1；这个边界复现不能证明当前正常音乐实际达到该范围，不能直接归因当前小音量。

### W2：梳状混响反馈与加权乘法同类截断

`rtl/router/parts/comb_reverb.sv` B级的四条 `fb<=s*g>>>27` 目标64位、四条 `t<=s*w>>>27` 目标69位，都未显式保留96位中间乘积。对N=8、延迟2/3/4/5、g=0.5、w=0.25的真实RTL测试：

- 输入脉冲2^24：48样本与无界整数参考全部相同。
- 输入脉冲2^38：反馈尾音23个样本不符。例如第16样本期望103079215104，得到68719476736。
- 输入脉冲2^44：反馈/加权路径26个样本不符。

仍是大信号范围缺陷，未宣称普通演奏已触发。当前实用范围的通过与完整signed64接口声明的正确性需要分开。

### W3：加权求和的饱和方向取错位（潜在缺陷）

`comb_reverb.sv` 的sum4是signed71位，越界方向却取 `sum4[63]`，正确方向应取宽和的符号位 `sum4[70]`。独立强制内部加权项复现：

| 宽和 | 正确饱和 | 当前结果 |
|---|---|---|
| +2^63 | +2^63-1 | -2^63 |
| -2^63-1 | -2^63 | +2^63-1 |

此探针主动设置内部t1/t2等项，检查的是饱和电路本身。当前W2截断限制了t的实际范围，因而在现有未修复乘法路径上掩盖了这类大幅求和；不能把内部强制探针描述成当前普通输入已经触发的故障。修复W2后尤其要一起修复并验证W3。

## 修复方向（本次未实施）

- 显式signed96位中间乘积，先完成64×32，再右移27。
- 反馈结果保留足够的高位；必要时先饱和到64位，再与输入用65位加法饱和。加权结果保留69位、四路用71位求和。
- 干湿混合仍使用69位项/70位和，并按宽和符号位决定饱和方向。
- 审计已通过的体积边界、负数、舍入和正常音频对照必须保留；修改乘法宽度会改变DSP映射和时序，需重新PnR后才能替换当前已下载版本。
- 稳定极点与数值位宽是不同检查：现有一阶调制只限前四模态，不代表可直接扩大到全20模态；相关约50音分扫描见10月31日报告。
