## 一、结论摘要

- **核心递推和定点格式没有发现硬伤**：静态校准中位误差 0.02–0.17 dB，最大 1.24 dB；8 个代表音的整数递推原型与浮点参考差 ≤0.12 dB，0 饱和，尾音 −97 到 −118 dBFS。
- **当前模型“稳态谐波”可信，但整机音色还不是高保真**：15 个测试音中 12 个的 1/3 倍频程中位误差 ≤1.2 dB；主要差距在噪声、表情、音高量化、低音模态带宽和输出增益。
- **不能把 `verify()` 当音色验收**：它只测“静态驱动增益校准”，颤音/AM/roughness/噪声全部关闭。真正的音色问题见下面的 B-01 到 B-12。

## 二、测量口径（避免误读数字）

本次基线使用：

- 5 种乐器，每种取低/中/高 3 个有录音的键，共 15 个音。
- flute/trumpet/cello 用 `sustain_demo.py:VOICE` 的默认表情；oboe/violin 没有专用 `VOICE`，用通用表情（vibrato 16 cent、AM 0.08、roughness 0.12）。因此 oboe/violin 的数字只代表“通用表情”，不是最终调音。
- 对比段：录音取音符区域 30%–70% 的稳态；模型取 1.5–3.3 s 稳态。
- 指标：
  - 1/3 倍频程：100 Hz–12 kHz，功率归一化到各自最大值，只统计双方都高于 −50 dB 的频带。
  - 谐波幅度：以 `k·f0` 为中心、±0.4·f0 内积分功率，只统计录音侧 > −45 dB 的 partial。
  - 噪声底：2–8 kHz 内避开 partial 的中位幅度，相对各自峰值。
  - 音高：48 kHz 下 `fdrive = 48000 / round(48000/f0)` 相对名义 f0 的 cent 误差；**未包含**硬件 48.828 kHz 播放的 +29.6 cent。
- 这不是受控听音测试，也不是多录音平均；数字用于定位问题，不用于宣称“音色达标”。

### 重点说明

#### B-01 噪声支路关闭

这是用户 2026-10-16 的决定（`rtl/DECISIONS.md` G6），不是实现 bug。但它决定了当前模型“干净但不完整”：

- 录音在 2–8 kHz 的噪声底通常比模型高 10–35 dB；flute F7 这类高音可达 69 dB。
- flute A4 的试验：`noise_gain=0/1.0/2.5/5.0` 对应 1/3 倍频程中位误差 `1.29/0.58/1.82/3.74 dB`，噪声差 `−29.5/−6.2/+1.7/+7.6 dB`。1.0 附近最平衡，2.5 已经过噪。
- 若以后重新开启，需要重新标定每乐器噪声增益，并承担 257-tap FIR 的资源；三乐器同时发声约 771 MAC/样本（折叠后 387），当前 466 周期余量接不住。

**建议**：保留“无噪声参考”作为默认，另留一个可选的 `noise_gain` 档；不要在没有资源预算时直接打开。

#### B-02 表情参数没有按音提取

当前 `VOICE` 是每乐器一组固定值：

- flute：5.4 Hz / 13 cent / AM 0.08 / roughness 0.12
- trumpet：4.8 Hz / 9 cent / AM 0.06 / roughness 0.15
- cello：5.8 Hz / 12 cent / AM 0.06 / roughness 0.30

但真实演奏的颤音速率/深度、AM、弓压起伏随音高、力度、持续长度变化。`sustain.py` 里的 `_vibrato_sweep()` 已经估了峰值频率偏移，却没有存进 NPZ；`roughness` 更是完全随机生成。

**建议**：先在提取表里增加 `vibrato_hz`、`vibrato_cents`、`am_depth`、`roughness`（或至少 per-note 的 vibrato），再让引擎读取；这是低成本、高听感收益的一项。

#### B-03 音高量化与采样率

两个独立误差：

1. 整数周期：`T = round(fs/f0)`，高音误差大；48 kHz 下 violin G7 约 +35 cent、flute F7 约 +18 cent，低音通常 <5 cent。
2. 采样率：A 类接受“48k 系数在 48.828 kHz 播放”的 +29.6 cent。B 类不能简单照搬：
   - 若 NCO 按 48.828 kHz 生成驱动，而模态系数仍是 48 kHz，驱动和模态会相对失谐 29.6 cent，稳态增益校准失效；
   - 若 NCO 沿用 48 kHz 增量，整体高 29.6 cent，但谐波关系保持。

**建议**：先决定统一在 48 kHz 还是 48.828 kHz；若要准确音高，用分数 NCO 或按实际采样率重新生成 `a1/a2/G` 和整数周期表，并重新验证 `steady_amp_unit` 的增益校准。

#### B-04 48 模态上限

`N_MODES=48` 对 A 类足够，但 B 类低音不够：

- cello C2（约 65 Hz）48 个谐波只到约 3.1 kHz；
- 录音在 3 kHz 以上仍有弓噪/高频谐波，模型没有；
- 1/3 倍频程指标只统计“双方都有能量”的频带，所以中位误差看起来很好，但高频缺失被隐藏了。

**建议**：评估低音乐器是否需要更多模态，或用独立的高频噪声/残差支路补；不要只看 1/3 倍频程中位数。

**2026-10-19 48 模态鼓补充测试（Python，只读；未改 RTL/ROM）**

- 把现有 64 模态鼓表按幅度保留最强 48 个：4 小节 groove 的 RMS 比 0.9984，多数 1/3 倍频程差 0 dB；听感上用户确认“没听出区别”。
- 用 `build_kit(n_modes=48)` 重新提取：kick/hat/ride 的频谱重心分别 +256/+296/+211 Hz，1/3 倍频程中位 0.3–2.5 dB，groove RMS 比 1.022；4 小节 groove 仍听不出明显区别。
- 暂定结论：**C 类保持 48 模态即可**，优先把资源放在噪声/残差、起振瞬态和 velocity，而不是把 `N_MODES` 扩到 64。
- 边界：这是当前鼓库、当前 groove、单次听感；单件 cymbal 高频独听或换录音可能更敏感。硬件生成必须按“最强 48”选峰，不能按频率顺序截前 48。
- 证据：`/tmp/opencode/drum48_20261019/`（未入库，含 64/48/post-hoc 48 的 A/B、`report.json`、`report_true48.json`、`README.txt`）。

#### B-05 输出峰值/限幅

单声部峰值已经超过 1：

- cello A3 完整表情 5.07；
- 全表 0.3 s 静态扫描 2.78–4.24。

demo 用整段峰值归一化 + `tanh`，这不是硬件策略。32 个持续声部同时发声时，混音和会远大于 1；必须定：

- 每声部/每乐器增益；
- 混音总线位宽和移位；
- 限幅/软削波/正常饱和判据；
- 峰值目标（例如 −1 dBFS）和削波计数。

#### B-06 Python 键回退

`SustainPatch._pick_key()` 的语义是“同音高任意合法力度优先，其次最近音高合理力度”，目的是避免跳到无关第一键；但硬件路径必须严格键查找，缺指定 MIDI/力度档就拒绝。

**建议**：Python 保留回退可以，但要在日志/报告里明确“用了替代键”；或者在音色调试模式下改为严格模式，避免把替代键的音色当成目标音色。

## 五、建议的回头调试顺序

按“低成本高收益 → 结构性改动 → 可选增强”排序：

1. **B-02 表情按音提取**：改 `sustain.py`/NPZ/`VOICE`，不动 RTL，先提升听感。
2. **B-08 动态层 + B-06 严格键模式**：让 forte/mezzo-forte 和 velocity 的语义正确，避免“替代键”污染评估。
3. **B-07/B-12 异常值复核**：检查 3.8 s/2.84 s attack 是否真实，检查 flute F7/violin G7 的极端误差来源。
4. **B-03 音高 + B-04 模态带宽**：结构性改动；先定 48k/48.828k，再决定整数周期/分数 NCO、是否增加模态或高频噪声。
5. **B-01/B-10 噪声与 roughness**：按资源预算决定是否开噪声；roughness 先简化/冻结，不要直接上 10 LFO/声部。
6. **B-05/B-11 混音限幅/room**：最后做整机听感和电平。
7. 重新跑基线指标 + 受控听音；更新本台账和工程汇报。

- 全部 5 张 B 表、7,624 条模态：
  - `a1 Q2.20` 频率误差最大 2.6 cent（cello 低音）；
  - `a2 UQ0.24` 衰减相对误差最大 2.6e-4；
  - `G Q2.24` 相对误差最大 1.75%，没有量化成 0；
  - 量化后 0 条不稳定极点。
- 8 个代表音的静态整数原型：
  - 与浮点参考的谐波幅度差 ≤0.12 dB；
  - 0 次饱和；
  - 释放后 5 s 尾音 −97 到 −118 dBFS；
  - 未见非零固定点卡死。
- 注意：原型只定点化了系数/状态，包络与驱动时序仍是浮点；NCO/AM/颤音/系数刷新还没有整数模型。
