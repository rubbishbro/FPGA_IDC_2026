## F01：系数表与调制参数表的选表边界不一致

**位置：** `rtl/router/voice_router.sv:234–239`，对照 `rtl/router/loader.sv:204–212`。

- `ld_addr`：loader产生的统一写地址。
- `ld_sel_pm`：是否选择调制参数表。
- `ld_idx`：去掉表基址后的表内地址。
- `SLOTS`：声部数；`N_MODES`：每声部模态数。

**原因：** loader的参数表从`SLOTS*N_MODES`开始，router却通过`ld_addr[CO_SLOT]`选表。16×48时，前者边界为768，后者为1024；768～1023的参数记录被误送到系数写口并越界。

**可能修改：** 保留loader的紧凑线性布局，统一为：

```text
T = SLOTS*N_MODES
ld_sel_pm = ld_addr >= T
ld_idx = ld_sel_pm ? ld_addr-T : ld_addr
```

写使能还应限制有效地址区间，不能把非法地址静默截断成合法地址。

## F02：系数、状态和调制参数的地址步长不一致

**位置：** `voice_router.sv:334–336、373–397`。

- `voi/mod_slot`：计算/调制中的声部号。
- `eng_co_addr`：本声部内待读系数的模态号。
- `eng_st_addr/eng_st_waddr`：本声部内状态读/写的模态号。
- `co_idx/st_rd_idx/st_wr_idx`：完整系数读、状态读、状态写地址。
- `mod_p_mode/mod_co_mode`：调制参数读、调制系数写的模态号。

**原因：** loader按`slot*N_MODES+mode`写；router按`{slot,mode}`读写。48模态时拼接步长64，80模态时步长128，与RAM深度及loader布局不同。参数加载下标`{ld_idx[VWID-1:0],ld_idx[IW-1:0]}`还重复使用低位，不能正确取得声部号。

**可能修改：**

- 所有模态地址统一为`slot*N_MODES+mode`，先扩位计算，再转换到足够的地址位宽。
- 参数加载使用F01中减去参数表基址后的`ld_idx`，不要再次拆低位拼接。
- 参数读取、调制写系数、状态读写及debug解释必须遵守同一契约。
- 若坚持使用拼接，则loader、RAM深度、参数表布局和选表边界都必须改成相同的64/128补齐步长。

## F03：激励循环只写第0个声部

**位置：** `voice_router.sv:668`，`S_XWR`。

- `xw_i`：当前写入激励的声部号。
- `SLOTS`：需要写入的声部总数。
- `xw_run`：激励RAM写使能。

**原因：** `SLOTS[$clog2(SLOTS)-1:0]`把16截成低4位的0，结束条件第一次就成立。16声部、4个采样点应写64次，原测试只有4次。

**可能修改：** 在写入最后一个槽的同一拍结束：

```systemverilog
if (xw_i == VWID'(SLOTS - 1)) begin
    // 结束写入，进入声部计算
end
```

确定错误是右侧显式截断上限。SV比较上下文可能扩展加法位宽，不能一概声称`xw_i+1 >= SLOTS`也必然回绕；直接比较末槽可避免这些位宽歧义。

## F04：激励读取遗漏当前采样序号

**位置：** `voice_router.sv:411–412`；`engines/eng0.sv:207`、`engines/eng1.sv:95`。

- `fidx`：本批次当前音频采样点序号，不是模态号。
- `xw_i/voi`：写入/计算中的声部号。
- `eng_x_addr`：引擎作业内的采样偏移，目前两套引擎都输出0。
- `X_DEPTH`：每声部激励缓冲容量，默认64。

**原因：** 写地址使用`{xw_i,fidx}`，读地址使用`{voi,eng_x_addr}`，后续采样一直读取第0个位置。默认X_DEPTH=64时拼接步长本身正确，错误在读地址缺少fidx。

**可能修改：**

```text
写地址 = xw_i*X_DEPTH + fidx
读地址 = voi*X_DEPTH + fidx
```

当前每次引擎启动只处理一个采样点，可直接使用fidx；若将来引擎支持作业内偏移，再明确采用`fidx+eng_x_addr`并处理范围。重复激励次数取决于后续采样点数量，不是模态数量。

## F05：eng1使用上一模态状态，st_zero未正确清除全部模态

**位置：** `rtl/router/engines/eng1.sv:75–82、138–145`。

- `st_q/st_qdot`：同步RAM返回的当前模态旧状态。
- `y1_cur/y2_cur`：引擎内部状态寄存器。
- `p_a1/p_a2`：反馈乘积。
- `st_zero_lat`：本次作业要求按零状态计算。
- `first_done`：是否已经捕获过首个模态。

**原因：** S_MUL同拍更新`y1_cur/y2_cur`并计算使用它们的乘积；非阻塞赋值使乘法看到更新前的状态，发生模态/作业间串扰。清零只屏蔽首个捕获，也没有作用于所有模态的实际乘法输入。

复现：G=0、a1=1、a2=0，初始状态[10,20,30]应更新成[-10,-20,-30]，实际为[0,-10,-20]。

**可能修改：** 先捕获当前状态再乘法，或直接对已经有效的同步读结果做乘法；零状态选择必须覆盖本次作业全部模态。补非零反馈、不同模态初值、连续作业和全模态清零测试。

**参考模型：** `python/modal_sim/router_eng1.py` 的 `rtl_compat=True` 已按本行为复刻；
`python/modal_sim/eng1_cosim.py` 用 iverilog 跑 66 个作业逐位对拍当前 RTL 并 PASS。
修完本项后改用默认（intended）模式，见 `docs/ENG1_PY_MODEL.md`。

## F06：调制器重复启动

**位置：** `voice_router.sv:678–693`，对照`parts/modulation.sv:103–112、171–172`。

- `mod_start/mod_done/mod_busy`：调制请求、完成、忙信号。
- `mod_slot`：当前调制声部。
- `mod_co_we`：调制结果的四字段写使能。

**原因：** 顶层保持start到done；子模块完成后返回IDLE，可能再次采到仍为高的start，启动第二轮。顶层也没有复位初始化mod_start/mod_slot。原测试16×48出现17轮、816次提交，而非16轮、768次。

**可能修改：** start使用单拍请求或明确请求/接收协议；初始化控制寄存器，锁存每轮声部/压力，保证一次请求只有一轮计算，并限制调制写口的授权期。

## F08：ADSR起音超过正数上限，产生负包络

**位置：** `rtl/router/parts/envelope.sv:67–70`，`envelope_ADSR/E_ATK`。

- `lvl[i]`：第i个声部的包络增益。
- `A_STEP`：每采样起音增量。
- `E_ATK/E_DEC`：起音/衰减状态。

**原因：** `lvl+A_STEP < lvl`只检测32位unsigned回绕，没有钳位signed Q1.31正上限。默认A_STEP=0x01000000，第128次attack更新得到0x80000000，输出解释为-1.0。

**可能修改：** 用33位保留`lvl+A_STEP`的进位；和达到0x7fffffff时，同时把lvl钳位到0x7fffffff并进入DEC。若改成“剩余量比较”，还要防止A_STEP大于上限时减法下溢。

默认修复后仍需128次attack更新；正常从峰值衰减到S_LEVEL所需时间不是bug，不应删除正常decay段。

## F09：混响乘法先截断再移位

**位置：** `rtl/router/routers/reverb_router.sv:128–132`；同类表达式在`parts/comb_reverb.sv:137–144`。

- `xd[3]/wet`：64位干声/湿声。
- `gd/gw`：32位干湿增益。
- `g1…g4/w1c…w4c`：反馈/抽头增益。
- `G_FRAC`：增益小数位数，默认27。

**原因：** 64×32乘积未完整保存，先在64位表达式中截断，再右移。外层`64'(...)`不能恢复高位。NONE输入2^40应原样输出，实际输出0；输出定义YF=40，2^40对应量纲上的1.0。

**可能修改：** 显式保留signed96位乘积，再按既定规则缩放、舍入/截断和饱和到64位；同时检查湿声求和、干湿相加和反馈回写溢出。新增流水时必须同步修改valid及干湿对齐。

## F10：NONE切换HALL读取未初始化延迟RAM

**位置：** `parts/comb_reverb.sv:115–129`及`routers/reverb_router.sv`预设切换。

- `p1…p4`：各延迟线指针。
- `n1…n4`：各延迟线有效长度。
- `clr_run`：初始化期间屏蔽旧数据的标志。
- `clr_cnt`：累计输入样本数。

**原因：** NONE长度1，仅覆盖地址0；累计N个输入后却解除整个RAM的初始化屏蔽。切HALL后扩大访问范围，读出未写区域。

**可能修改：** 切预设时重新初始化，或按各延迟线实际覆盖范围维护有效标志；预设参数也要与流水中的样本对齐。测试应预置非零RAM，避免二态默认零掩盖问题。

## F11：清理/起音事件可能错过采样节拍

**位置：** `routers/exc_router.sv:75–87`、`parts/excitation.sv:65–72`、`parts/envelope.sv:37–52`。

- `clear`：清理激励状态。
- `onset`：起音沿。
- `smp_tick`：音频采样节拍。

**原因：** clear/onset只保持一个主时钟周期，消费逻辑却只在smp_tick执行；两者不重合时事件可能丢失。首次gate可能由IDLE兜底，但重触发、切音色不能据此保证正确。

**可能修改：** 事件挂起到采样消费后清除，或在采样节拍内统一检测门控；明确reload、换引擎、按住键换音色时q/v及待处理事件的清理/保留规则。

## F07：计算周期超出音频预算

**位置：** `engines/eng1.sv`逐模态FSM，以及`voice_router.sv/S_MOD`等待`parts/modulation.sv`。

- `n_modes/n_voices`：每次采样要处理的模态数/声部数。
- `SR_HZ/CLK_HZ`：音频采样率/主时钟频率。
- `S_MOD`：等待当前声部调制完成的阻塞状态。

**原因：** 100MHz、48kHz每采样预算约2083拍。原16×48测eng1相邻输出3922拍；吉他16键同时起音，首输出36276拍。调制实际每模态15步×3拍加参数等待，放在音频帧内串行等待会超时。修复完整16槽激励写后对应测量还增加15拍。

**可能修改：** eng1并行/流水化或减少承诺的复音规模；调制移出每帧硬实时临界路径，以后台计算及安全提交更新系数。分别验证首帧、稳态和批边界，不能只比较平均吞吐。

## P01：压力矩阵行选择按 clk_en 连续轮转，而非按行采样完成推进

**状态：源码确认；真实 ADC／板级影响待测试。**

**位置：** `rtl/drivers/pad_driver.sv:163、180–188、210–229、258–260`。

**原因：** `row_scan` 的使能是 `(chn_s == 2'b11) & cr.clk_en`，但 `chn_s/idx` 只在 `cr.clk_en & (cnt == '1) & adc_rdy` 时推进。列号停在 3 的期间，每个有效驱动时钟都会换行，不是一次成功采样只换一次行；摇杆阶段也没有禁止该行轮转。

理想无等待时，相邻取样相隔 256 个有效驱动时钟；列 3 的等待期间可轮转 256 次，4 行循环后回到原行。**idx 从 0 走到 15 不能证明真实四行已依次采到。**ADC 等待还会改变轮转次数，造成行与数据槽位关系不确定。

**建议：** 在明确的采样完成事件后推进列／行；只在压力垫一行最后一列采集完成后换行。确保下一次 ADC 请求前行列选择已稳定，摇杆采样不推进压力矩阵扫描。

**关闭测试：** ADC 模型按行列返回不同值（例如 `row*4+col`），逐一核对 16 个 fmap 槽；断言行只在指定行末事件改变；插入不同完成延迟并穿插摇杆采样后，映射仍一致。板上再逐键核对位置及四键同时按下。

## P02：ADC 请求／完成时序及跨域消费尚未验证

**状态：待核实风险，不直接判定 ADC IP 协议违规。**

**位置：** `rtl/drivers/pad_driver.sv:165–172、191–210`；`rtl/drivers/gowin_adc/gowin_adc.v`。

`adc_req` 除复位和一次采样消费条件外，每个主时钟都被置 1；满足条件时仅拉低一个主时钟周期。`adc_rdy/adc_val` 直接参与采样，文件中没有显式完成事件同步／数据锁存，也未见当前 ADC 时序模型证明其消费方式正确。

ADCLRC 包装使用内部时钟配置，**不能仅凭 RTL 猜测 ready 是脉冲还是电平、低脉冲所需宽度、数据保持期或跨域安全性**。`pad_driver` 与 router 共用主时钟，不等于 ADC 原语的完成信号也已同步；`PAD_ADAPTER.md` 的同域说明不能替代 ADC 接口检查。若 ready 是短脉冲，与 `clk_en && cnt==255` 同时出现才消费的逻辑可能漏采；若完成信号保持，也要验证一次结果不会被重复使用。

**建议／关闭测试：** 对照对应器件 ADC 手册冻结请求、完成、数据有效和时钟关系；按手册决定是否需握手／事件同步及结果锁存，不能只给多位 ADC 数据各加两级寄存器。用真实仿真库或符合协议的模型覆盖不同完成相位／延迟，验证每次请求恰好接收一次正确结果、无漏采／重复／卡死；上板确认模拟输入和行列稳定时间。

## P03：pad_voice_top 的固定强制位宽截断参数

**状态：源码确认的参数化错误；默认 16／48／64 不触发此截断。**

**位置：** `rtl/router/pad_voice_top.sv:127–129`。

适配层使用 `.n_voices(5'(SLOTS))`、`.n_modes(6'(N_MODES))`、`.n_samples(7'(X_DEPTH))`，而 router 端口按参数计算数量位宽。`N_MODES=80` 时，`6'(80)` 已截成 16；`X_DEPTH=128` 时，`7'(128)` 截成 0，接到更宽端口也无法恢复。默认配置下能工作不能证明参数化正确。

**建议／关闭测试：** 用 `$clog2(参数+1)` 对应的数量位宽传参，并对实际支持的 SLOTS／模态数／批长度加静态约束；至少验证 48／64／80 模态及 64／128 批长度的接收值。eng1 内部满额计数问题另见原“其它接口与参数错误”，不能只修外层 cast。

## I01：不同键位到不同音高的映射尚未闭环

**状态：功能缺口，不是“16 槽未实例化”。**

**位置：** `rtl/router/pad_voice_top.sv:106–129`、`rtl/router/loader.sv:202–224`。

适配层将每个压力单元直接交给对应槽；loader 仍把同一乐器的同一模态记录复制到全部槽，没有按键位／音符选择不同音高表的当前接口。不同压力、独立状态和多个槽，不自动产生四个不同音高。

**建议／关闭测试：** 和系数表负责人明确 `pad/slot → note → 系数／调制参数` 契约；四个不同键同时持音，确认四种目标频率、独立起音／松键、状态互不串扰。不要把后续生成多音高表当成当前 loader 已经能选表。

## I02：新增适配顶层仍止于数字合成结果，没有 PCM／I2S／DAC 输出

**状态：集成缺口。**

**位置：** `rtl/router/pad_voice_top.sv:38–43、110–145`。

`pad_voice_top` 目前输出 64-bit `y_data` 和 `y_valid`，没有 PCM 缩放／饱和、音频缓冲、I2S 串行输出或 DAC 时钟／管脚约束。`start(run)` 是高电平自动重复批作业，不是已经实现连续 DAC 采样；还需验证每批排空／重启的间隔、`run` 拉低后当前批次的行为。`reload` 若持续保持高，会在后续每批重新装载，需定义上层请求语义。

**关闭测试：** 合成→PCM→缓冲→I2S→真实 DAC，同一路径先单音、再四音、再持续播放；覆盖批边界、换音色／装载期间和停止／重启，测实际采样率、欠载、幅度／削波及输入到输出最坏延迟。上述是验收要求，不是本轮已测结果。
