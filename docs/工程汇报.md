# FPGA模态合成工程汇报

更新：2026年10月9日；当前版本：歌曲工程v5。本文件是**唯一的当前汇报**，汇总各轮结果并去除重复叙述；旧报告仅作追溯，不要求逐份阅读。

## 一、当前结论

- **已实现**：自动歌曲调度 → 32声部模态合成 → guitar共享箱体 → 标准I2S → MAX98357A喇叭输出的数字链路，已有真实Gowin配置文件。
- **已验证**：元数据导致的原歌曲首帧卡死已修复；当前RTL与限定范围的真实综合网表通过独立数值/协议检查，满载运算满足不超过1,800周期。
- **资源充足、时序余量很小**：整机占用15,416逻辑单元、8,911 FF、52 BSRAM、14 DSP资源单元、2 PLL。100MHz普通setup/hold各0违例，最坏setup裕量仅1ps。
- **实板优先、模型留档**：按用户决定先做有限SRAM试验，MPW模型负裕量继续分析；不因模型疑点暂停此次试验，也不改约束求绿色结果。
- **实板结果尚不完整**：持续测试音已由用户确认出声；修复歌曲出声/完整循环/≥60s稳定性和100MHz高低脉宽数字尚未收到，不能写成已通过。

## 二、实现范围与关键设计

```text
电脑：采样库 → 离线FFT/参数提取 → 定点系数ROM
FPGA：歌曲调度 → 系数装载 → 四通道模态阵列 → 共享箱体
                                            ↓
                                 PCM适配 → 异步FIFO → 标准I2S
                                                        ↓
                                             MAX98357A → 喇叭
```

| 项目 | 当前实现 |
|---|---|
| 板卡 / 构建目标 | Tang Mega 138K Pro；Gowin `GW5AST-LV138FPG676AES`、版本B；实物完整型号/速度级待核实 |
| 模态规模 | 32声部 × 每声部最多48模态，最大1,536个状态；四条共享运算通道 |
| 时钟与吞吐 | 核心100MHz，启动间隔II=3；满载bank/engine最大1,506/1,508周期，即15.06/15.08μs |
| 工作缓存 / 数值 | 同步单端口工作缓存；Q2.30模态状态；64bit混音累加 |
| 箱体 | guitar混音后共享四节biquad，生产配置开启，不为每声部复制一套 |
| 音频 | 12.5MHz参考时钟；BCLK3.125MHz；采样率48,828.125Hz；标准I2S每槽32bit，16bit单声道左右复制 |
| 歌曲 | 42事件循环，约10.32s；缺少指定MIDI/力度档则拒绝，不近音替代 |
| 拒绝契约 | 失败装载保留原声部；非法帧同握手报错、busy低、不stall，不改运行状态/缓存/历史 |

FFT和参考合成在电脑上运行，FPGA播放参数而非录音。Python支持的多乐器/持续音/打击乐范围**不等于当前板级实现范围**；本轮不包含麦克风、噪声支路、Note Off、完整声部分配/抢占、USB-MIDI或压力阵列ADC。

12.5MHz使用48k系数时快1.725%，约高29.6音分：接受其先出声，不称精确48k保真。本次整理未改FFT、浮点参考、激励、音量、模态算法、II或频率。

## 三、真实整机资源占用

来源是**2026年10月7日已有v5完整工程P&R**，工具Gowin V1.9.12.04，不是今天重跑，也不是旧84MHz、测试音或时钟观测工程。

| 资源 | 占用 / 容量 | 按数量计算 |
|---|---:|---:|
| 逻辑单元合计 | **15,416 / 138,240** | **11.15%** |
| 其中LUT / ALU | 13,866 / 1,550 | 已包含在逻辑合计中 |
| 逻辑FF | **8,911 / 138,240** | **6.45%** |
| 逻辑簇CLS | 11,687 / 69,120 | 16.91% |
| 块存储器BSRAM | **52 / 340** | **15.29%** |
| DSP资源单元 | **14 / 298** | **4.70%** |
| PLL | **2 / 12** | **16.67%** |
| I/O端口 | 6 / 312 | 1.92% |
| 主时钟资源PRIMARY | 3 / 8 | 37.50% |
| 长线资源LW | 1 / 8 | 12.50% |

BSRAM为16个SPX9＋2个SDPB＋34个pROM；SSRAM、ROM16、I/O寄存器与锁存器均为0。7个`MULT27X36`原语对应本次构建14个DSP资源单元，不能将原语数当物理资源占用。工具Register总容量139,140含900个I/O寄存器，上表逻辑FF仅以逻辑容量138,240为分母；工具百分比取整数，可能与上表精确比例不同。LUT/ALU/CLS不能再次与Logic合计相加。

### 模块分摊（综合阶段，不冒充最终P&R分摊）

| 模块 | LUT | ALU | FF | 27×36乘法原语 | 存储计数 |
|---|---:|---:|---:|---:|---:|
| 模态引擎，含装载器与四通道bank | 11,646 | 1,123 | 6,664 | 4 | 49 |
| guitar共享箱体 | 1,281 | 304 | 1,518 | 3 | 1 |
| 歌曲调度 | 556 | 0 | 237 | 0 | 0 |
| FIFO与I2S传输 | 215 | 4 | 328 | 0 | 0 |
| 时钟/复位与两套PLL初始化 | 109 | 32 | 79 | 0 | 0 |
| 其余顶层控制/连接 | 62 | 0 | 85 | 0 | 0 |
| **合计** | **13,869** | **1,463** | **8,911** | **7** | **50** |

综合与P&R统计阶段不同：综合存储计数50，最终物理BSRAM52；不混算或凭差值猜分配。容量尚有余量，但当前瓶颈是控制译码、高扇出与实际布线，不能据DSP余量直接推断可增加复音或提频。

## 四、验证结果与剩余风险

| 层次 | 已取得的结果 | 不能据此声称 |
|---|---|---|
| 当前共用核心RTL | v4时独立34项回归、60组地址等价矩阵通过；v5仅改约束，共用同一核心，数值和原子拒绝契约保持 | 物理时序/PLL通过 |
| 当前bank真实综合网表 | 独立3/3通过，覆盖饱和、1,536提交、变长度150帧、cfg乱序/空洞、clear/reset/reload与非法帧拒绝；最大1,506周期 | 完整歌曲实板通过 |
| 当前生产网表 | 完整未改vendor库，两个启动/reset阶段34个I2S帧及64bit模态和与黄金一致，30个非零帧 | 整首歌曲网表/物理PLL reset闭环 |
| v5数字启动/复位 | RTL生产wrapper32个黄金样本及24个数字reset相位扰动通过；此项使用测试PLL行为时钟 | 真实PLL lock/reset或亚稳态验证 |
| 箱体与早期整链 | 箱体逐位与真实DSP/ROM验证；当轮冻结整链4,096样本通过 | 将旧整链结论直接当当前v5整曲验收 |
| 普通STA | setup0/hold0，Fmax100.007MHz，最坏setup+0.001ns；异步第一级hold例外经核对，第二级与两向10ns max_delay保留 | 完整PVT、动态抖动或外部I2S签核 |
| MPW模型 | 最坏slack−0.612ns，actual0.288ns、required0.900ns；源早晚路径差与边沿相关性继续查证 | 将模型actual当示波器实测，或判定必为假违例 |
| 实板 | 持续测试音已出声；修复歌曲及100MHz脉宽实测尚待明确反馈 | 当前歌曲已稳定可用 |

最关键的两项修复是：每声部独立元数据避免原综合网表的装载误记账；配置地址改为窄位移位/加法，消除两个地址乘法DSP。仅保留已验修复，撤回恶化P&R的中间优化，不降频或改成II=4。

测试目的、分类与运行方式只维护在[测试说明](../sim/README.md)，完整清单使用`python sim/run.py --list`查看。此处只汇报结果，不再列一份重复脚本表。

物理分析已找到96扇出网的驱动与两个负载位置，**完整96负载坐标仍未取得**，不能绘成完整扇出/拥塞图。最大已知分支3.979ns，欧几里得距离并非单独解释延迟的依据；局部布局、并行译码和预寄存地址仍为分析候选，尚未实施。

核心PLL输出使用PRIMARY全局时钟；50MHz输入存在普通路由警告，源路径分量/相关性尚未完全证明。官方800MHz例程送给AE350硬核CPU，不是任意fabric、DSP/RAM或PMOD的800MHz能力证明。模型与实测分别保留，实测通过仅覆盖记录的板卡、供电、温度与测试时间。

下一步按优先级：

1. 确认修复歌曲成功下载、出声，观察完整循环和连续≥60s，补重复下载启动及物理复位结果。
2. 测100MHz稳态频率、周期、高/低脉宽Mean/Min/Max及占空比；记录探头倍率/带宽、采样率、阈值和截图。×10探头、1MΩ、短地弹簧、关闭20MHz限制，不直接50Ω终端负载FPGA。
3. 将实测写回本汇报，再继续MPW源路径相关性与完整96位置分析。引脚包含IO/探头影响，不等于内部DSP/RAM端点脉宽；独立观测工程也没有生产100MHz内部时序负载。
