## 一、当前结论

- **已实现**：自动歌曲调度 → 32声部模态合成 → guitar共享箱体 → 标准I2S → MAX98357A喇叭输出的数字链路，已有真实Gowin配置文件。
- **已验证**：元数据导致的原歌曲首帧卡死已修复；当前RTL与限定范围的真实综合网表通过独立数值/协议检查，满载运算满足不超过1,800周期。
- **资源充足、时序余量很小**：整机占用15,416逻辑单元、8,911 FF、52 BSRAM、14 DSP资源单元、2 PLL。100MHz普通setup/hold各0违例，最坏setup裕量仅1ps。
- **实板优先、模型留档**：按用户决定先做有限SRAM试验，MPW模型负裕量继续分析；不因模型疑点暂停此次试验，也不改约束求绿色结果。
- **实板基础验证已取得正面结果**：2026年10月10日用户明确确认歌曲和测试音都通过，观测电平持续时间稳定、远超要求、接近完美方波。这是用户实测反馈，不再标为“歌曲尚未确认出声”；未提供的脉宽数字、持续播放时长和复位次数不补造。
- **后续方向已更新**：范围收敛为 **ENG1 重构**（A/B/C 统一格式，只动 ENG1；UI/BLE/Flash/乐器级 EXP 暂不做）；B 类迁移并入这次重构，不再单独立项。200MHz/400MHz 作为后续探索，当前 100MHz 基线、PLL 和 II=3 不变。
- **B类Python明确bug已修复**：DS按用户授权修复LFO时间推进（含AM-only）、`verify()`七项解包、最后声部回收后的噪声控制量清零；父独立验收通过，其他算法选择未改。

## 二、专题文档摘要

`docs/` 下四份专题文档负责推导和证据，本节只摘结论；数字以本节为准（旧草案里的 120-bit/`c1/c2`/`+40–50 BSRAM` 已被取代）。各节标题即原文链接。

### 2.1 B 类迁移：[B类迁移硬件估算](archive/2026-10/docs/B类迁移硬件估算.md)

- **同一递推，只换外围**：B 仍是 `y = G·x − a1·y1 − a2·y2`，差异在周期激励、AR 包络、颤音/AM/roughness、噪声和生命周期。
- **三级**：L0 静态（无调制/噪声）、L1 表情、L2 高保真。
- **资源（已删 `c1/c2`）**：L0 约 26–28 BSRAM / 2 DSP；L1 约 32–34 / 3–5；L2（5 全动态 + 噪声）约 60–64 / 5–10。整机远低于 340 BSRAM。
- **a1 刷新**：`a1 = a1_nom·cos(δθ) + s·sin(δθ)`，`δθ=(ratio−1)·θ`，`s=sqrt(4a2−a1²)`；θ 用 14-bit mini-float 放 a1 影子剩余位宽，`r` 不存。
- **主要风险**：旧 loader 216 周期/音不够；48k 系数在 48.828k 播放 +29.6 音分；整数周期高音误差；时序仅 +1 ps。

### 2.2 双引擎顶层：[双引擎统一顶层架构](archive/2026-10/docs/双引擎统一顶层架构.md)

- **一个 `synth_top` shell**：ENG1/ENG2 各自本地 bank；**系数源可共享**（max-width、按 engine 分 region），**每采样 state/result 不共享**（端口不够）。
- **并行**：ENG1 1,508 + ENG2 480 在同一 2,048 周期 tick 内并行，不是相加；结果先统一 Q2.30 再混音。
- **POST/RVB**：POST 复用 body，支持每引擎 bypass；RVB 放 POST 后，send/return 干湿混合。
- **资源**：8 声部 ENG2 约 103 BSRAM / 42 DSP / 18.7k logic；16 声部 + RVB 约 160–168 / 72–78，器件 340/298 可行。
- **风险与路线**：时序（ENG1 +1 ps、ENG2 104 MHz 余量 4%）、格式对齐、ENG2 loader/allocator、BUF 仲裁；路线 S0 shell → S1 ENG2 → S2 混音 → S3 POST → S4 RT → S5 RVB。

### 2.3 统一格式与 C 类：[统一IIR合成数据格式与C类设计](archive/2026-10/docs/统一IIR合成数据格式与C类设计.md)

- **统一记录（2026-10-20 冻结）**：Event(64) / Key(13) / Index(64) / Control(256) / Core(72) / Seed(64)；类差异只保留 5 处：激励、起振、控制块、噪声、后级。
- **记录流无 ext**：B 的 `c1/c2` 删除，表情层给 `ratio`；C 的 seed 不进记录流，直接写状态槽 `{y2,y1}`（ROM V=4，48 个/击）。
- **C = 48 模态**：`N_MODES=48`、`M_ACTIVE_MAX=1,536`，周期仍 1,506；工作缓存 221 kbit 不增；生成时必须按“最强 48”选峰，不能按频率截断。
- **力度/键**：Key 只含 `{class,instrument,note}`，**没有 layer**；`velocity` 8-bit；`n_vel=4` 力度带，`band=vel8[7:6]`，地址 `mode_offset + band*n_modes + mode`；硬件严格拒绝缺失 key。
- **阶段**：格式包/Python 对拍已完成；下一步按 sythsound `modal_voice_top` 模板做共享 BUF + `synth_top`，再迁 A/B/C 引擎。

### 2.4 音色缺陷：[音色合成缺陷台账](archive/2026-10/docs/音色合成缺陷台账.md)

- **递推/定点无硬伤**：静态校准中位 0.02–0.17 dB、最大 1.24 dB；整数递推 vs 浮点 ≤0.12 dB，0 饱和。
- **整机音色未达高保真**：15 音中 12 个 1/3 倍频程中位 ≤1.2 dB；差距集中在噪声、表情、音高量化、低音模态带宽、输出增益。
- **B-01–B-12**：噪声默认关、表情未按音提取、整数周期音高、48 模态上限、峰值/限幅、键回退、attack/release、动态层、覆盖、roughness、room、极端音。
- **调试顺序**：表情 → 动态/严格键 → 异常值 → 音高/带宽 → 噪声/roughness → 混音/room。
- **验收阈值（草案）**：静态中位 ≤0.3 dB / 最大 ≤1.5 dB；1/3 倍频程中位 ≤1.5 dB / 最大 ≤6 dB；音高 ≤5 音分。

### 2.5 当前统一口径

- **范围**：只做 **ENG1 重构**；ENG2、双引擎 shell、POST/RVB、UI/BLE/Flash、乐器级 EXP 暂不做。
- **预设**：全局“风格/参数”预设（8 字节），不按乐器；UI 以后只做控制面板，不做数据面板。
- **不做**：状态跳变补偿、运行时 LFSR seed（用 ROM V=4）。

## 三、实现范围与关键设计

```text
电脑：采样库 → 离线FFT/参数提取 → 定点系数ROM
FPGA：歌曲调度 → 系数装载 → 四通道模态阵列 → 共享箱体
                                            ↓
                                 PCM适配 → 异步FIFO → 标准I2S
                                                        ↓
                                             MAX98357A → 喇叭
```

| 项目 | 当前实现 |
|---|---|
| 板卡 / 构建目标 | Tang Mega 138K Pro；Gowin `GW5AST-LV138FPG676AES`、版本B；实物完整型号/速度级待核实 |
| 模态规模 | 32声部 × 每声部最多48模态，最大1,536个状态；四条共享运算通道 |
| 时钟与吞吐 | 核心100MHz，启动间隔II=3；满载bank/engine最大1,506/1,508周期，即15.06/15.08μs |
| 工作缓存 / 数值 | 同步单端口工作缓存；Q2.30模态状态；64bit混音累加 |
| 箱体 | guitar混音后共享四节biquad，生产配置开启，不为每声部复制一套 |
| 音频 | 12.5MHz参考时钟；BCLK3.125MHz；采样率48,828.125Hz；标准I2S每槽32bit，16bit单声道左右复制 |
| 歌曲 | 42事件循环，约10.32s；缺少指定MIDI/力度档则拒绝，不近音替代 |
| 拒绝契约 | 失败装载保留原声部；非法帧同握手报错、busy低、不stall，不改运行状态/缓存/历史 |

FFT和参考合成在电脑上运行，FPGA播放参数而非录音。Python支持的多乐器/持续音/打击乐范围**不等于当前板级实现范围**；本轮不包含麦克风、噪声支路、Note Off、完整声部分配/抢占、USB-MIDI或压力阵列ADC。

12.5MHz使用48k系数时快1.725%，约高29.6音分：接受其先出声，不称精确48k保真。本次整理未改FFT、浮点参考、激励、音量、模态算法、II或频率。

## 七、持续音B类讨论草案（2026-10-13，已被第二节取代）

> 本节写于 2026-10-13，保留当时的推导和证据；其中 `c1/c2`、120-bit 表、`+40–50 BSRAM`、`N_MODES=64` 等已被第二节取代，**以第二节为准**。本节仍有效的部分：参考语义、Python bug 修复记录、验证链要求。

用户当时选择**先讨论B类**；打击乐C类、A类噪声/Note Off/抢占以及外部控制器暂不展开实现。当时建议先长笛，再加入小号与大提琴，之后扩展已有提取表的小提琴/双簧管；分阶段不代表删掉噪声或颤音后就称完成B类。

### 算法与参考的边界

`python/modal_sim/sustain_engine.py`仍使用同一递推：`y = G·drive − a1·y1 − a2·y2`。变化在于周期激励、包络、调制、噪声和声部生命周期，而非重做整套谐振器。

| 部分 | 当前Python实际行为与迁移约束 |
|---|---|
| 激励 | 以`T=round(48000/f_MIDI)`确定基准驱动频率`48000/T`，相位累加溢出发一个脉冲；开音从相位0起，首脉冲不是立即发出。输入是`impulse × env × velocity × AM`。 |
| 系数/增益 | 模态放在实际驱动频率的整数倍上，`r=exp(-gamma/fs)`，`a1=-2r cos(theta)`、`a2=r²`；`G=w/A_peak(unit drive)`由`steady_amp_unit()`离线计算，不直接用简化公式或A类的脉冲增益。 |
| 包络/关闭 | AR指数趋近，gate开向1、关向0；关音立即停激励，但原参考**不将输出模态和再乘release包络**，尾巴按模态gamma衰减。改变这一点是算法选择，不是等价迁移。 |
| 颤音/AM | 驱动频率与所有模态必须使用同一比率、同一更新世代；只改驱动或只改模态会失谐。调制系数更新必须保留历史，不走重新装载音符的清除流程。 |

候选数值设计：沿用模态`a1 Q2.20 / a2 UQ0.24 / G Q2.24 / y Q2.30 / 64bit混音`；NCO采用32bit无符号环绕相位，包络与连续velocity采用独立非负定点格式，AR衰减系数优先讨论30个小数位，避免慢起音每步增量被舍成0。包络更新为`e = target + (e-target)·alpha`，`alpha=exp(-1/(fs·tau))`离线预计算；无论采用何种舍入，必须验证最慢attack能离开0、release能进入回收阈值。FIR候选signed24bit、22小数位（范围[-2,2)），噪声样本与累加器位宽按PRNG上界及滤波器L1范数定，不能用RMS替代溢出界。上述均待定，不是新的冻结格式。

颤音可按`ratio=2^(cents/1200)`、`a1=-2r cos(2πkf_drive·ratio/fs)`生成；a2在gamma固定时不必重算。共享LUT/CORDIC的相位/幅度误差要覆盖低频高Q模态，而非只看cos函数平均误差。即使每个静态系数集合的极点都在单位圆内，也仍须验证时变系数的增能、控制阶跃和饱和。首脉冲、原子切换及控制率都应进入整数黄金，不凭稳态谱图代替时域验收。
