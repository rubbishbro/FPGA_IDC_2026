# 通信协议约定

日期：2026-11-02。

本文记录当前 v1 有线/蓝牙协议格式（蓝牙 UART 9600 8N1，HC-05 需配置为 9600；有线 UART 115200）。2026-11-02 已同步网页上位机的帧编解码、配置回复、重发和演奏录制序号；73 项上位机测试通过，生产 RTL 编解码模块的帧级交叉仿真通过（覆盖配置回复和单个录制起点帧），但完整录制回传链路及真实串口录制仍待联测。蓝牙 v2 上位机链路不属于本次同步范围。本文中的类型、命令、结果码及示例字节均使用十六进制；字节数和时间使用十进制。

## 1. 帧格式

```text
C0 | TYPE | SEQ | LEN | PAYLOAD | CRC低字节 | CRC高字节 | C0
```

| 字段 | 大小 | 规定 |
|---|---:|---|
| 起始标记 | 1 字节 | 固定 C0 |
| TYPE | 1 字节 | 消息类型 |
| SEQ | 1 字节 | 请求序号，00～FF 循环使用 |
| LEN | 1 字节 | PAYLOAD 字节数，最大 64 字节 |
| PAYLOAD | LEN 字节 | 具体消息内容 |
| CRC | 2 字节 | 低字节在前，高字节在后 |
| 结束标记 | 1 字节 | 固定 C0 |

不包含 VERSION。LEN 不包含 TYPE、SEQ、LEN 本身、CRC、首尾标记及转义增加的字节。

## 2. 消息类型 TYPE

TYPE 由发送方按消息用途填写，是双方约定的固定编号。

| TYPE | 方向 | 含义 |
|---|---|---|
| 01 | 上位机 → 板子 | MIDI 演奏数据 |
| 02 | 上位机 → 板子 | 配置请求 |
| 80 | 板子 → 上位机 | 配置结果回复 |
| 82 | 板子 → 上位机 | 演奏录制事件回传，24 字节 PAYLOAD 见 3.3.1 |

## 3. COMMAND 和 PAYLOAD

COMMAND 是具体操作的命令号，占 1 字节，位于配置 PAYLOAD 的第一个字节。

```text
配置请求 PAYLOAD = COMMAND + 参数
配置回复 PAYLOAD = 原 COMMAND + 结果码
```

配置帧展开后为：

```text
C0 | TYPE | SEQ | LEN | COMMAND | 参数/结果 | CRC低 | CRC高 | C0
                       └───── PAYLOAD ─────┘
```

| 消息 | PAYLOAD 内容 | LEN（十进制） |
|---|---|---:|
| 混响配置 | 02＋混响预设 | 2 |
| 有线录制开始 | 12＋32位录制ID（小端） | 5 |
| 有线录制停止 | 13＋同一录制ID（小端） | 5 |
| 整套键位配置 | 20＋16 组“乐器编号、音符编号” | 33 |
| 配置回复 | 原命令号＋结果码 | 2 |
| MIDI Note On／Off | MIDI 状态＋音符＋力度，无额外 COMMAND | 3 |

EQ 暂不接入。其他 MIDI 消息按其实际长度发送，例如 Program Change 为 2 字节。

### 3.1 混响配置

TYPE=02，COMMAND=02，LEN=2。

```text
PAYLOAD = 02 [混响预设]
```

| 预设 | 含义 |
|---|---|
| 00 | 关闭混响 |
| 01 | 大厅混响 |
| 02 | 浴室混响 |
| 03 | 室内混响 CHAMBER（当前参数为 NONE 干声占位，待调试） |

编号与 `router_pkg::reverb_preset` 一致：NONE=0、HALL=1、BATHROOM=2、CHAMBER=3。

### 3.2 整套键位配置

TYPE=02，COMMAND=20，LEN=33（线上填写 21）。

一次发送全部 16 个键位，按键位编号 0～15 固定排列，不再逐项携带键位号：

```text
20
[键0乐器]  [键0音符]
[键1乐器]  [键1音符]
……
[键15乐器] [键15音符]
```

- 每个乐器编号占 1 字节，编号见 3.2.1，必须是设备支持的编号。
- 每个 MIDI 音符编号占 1 字节。旋律乐器每种仅支持 32 个音高，起止编号按3.2.1固定，不能将 MIDI 的编码范围 0～127 当成本机支持范围；鼓组仅采用底鼓、军鼓、嗵鼓、闭合踩镲、叮叮镲、吊镲六类，具体见 3.2.2。
- 16 组映射数据共 32 字节，加命令号后 PAYLOAD 共 33 字节。
- 板子先完整接收并校验长度、CRC 和全部参数，通过后整表一次性生效。
- 失败时保持原配置，不允许部分键位生效；全部提交成功后才能回复成功。

2026-11-03源码已接通同一乐器的16键自定义绑定：允许乱序、重复和跨该乐器高低音组取音；16项乐器号必须相同。混合乐器表整表返回03。加载成功且释放旧按键后UI显示“自定义键位”并回复00；失败尝试恢复旧绑定，不部分提交。尚未烧录。实现与指引设计见[自定义键位与演奏指引](自定义键位与演奏指引.md)。

### 3.2.1 自定义键位乐器编号与音符范围

乐器编号采用设备已有乐器枚举，避免与现有资源编号冲突；“钢琴0/1、吉他0/1”中的0/1表示本设备的两套音色版本。原有界面中的“钢琴1/2、吉他1/2”分别对应这里的“钢琴0/1、吉他0/1”。

本节线上字节使用十六进制；另列十进制便于核对。MIDI 音符号使用十进制，采用中央 C = C4 = 60 的音名约定。

| 乐器 | 乐器编号（线上十六进制） | 乐器编号（十进制） | MIDI 音符号（十进制） | 音符字节（十六进制） |
|---|---|---:|---|---|
| 钢琴0 | 00 | 0 | 21～52 | 15～34 |
| 钢琴1 | 0A | 10 | 21～52 | 15～34 |
| 吉他0 | 01 | 1 | 40～71 | 28～47 |
| 吉他1 | 0B | 11 | 40～71 | 28～47 |
| 班卓琴 | 08 | 8 | 48～79 | 30～4F |
| 曼陀林 | 09 | 9 | 55～86 | 37～56 |
| 长笛 | 02 | 2 | 60～91 | 3C～5B |
| 小号 | 03 | 3 | 51～82 | 33～52 |
| 小提琴 | 05 | 5 | 55～86 | 37～56 |
| 大提琴 | 04 | 4 | 36～67 | 24～43 |
| 双簧管 | 06 | 6 | 58～89 | 3A～59 |
| 鼓组 | 07 | 7 | 36、38、45、42、59、49（鼓件编号，见3.2.2） | 24、26、2D、2A、3B、31 |

- 以上是自定义键位的设备乐器编号，**不是 GM Program Change 编号，也不是 MIDI 通道号**。两套钢琴或吉他音色由乐器编号区分，不能用音符号区分。
- 对旋律乐器，第二字节始终表示原始 MIDI 音高编号，不重新编号为 0～31。每种乐器支持连续 32 个音高，起止编号按上表固定，两端均包含；每个区间恰好32音。0～127 只是 MIDI 编码范围。
- **32音选区按本节约定冻结（2026-11-01）。** 钢琴按最低源音高21起选21～52；钢琴0/1均以eng0钢琴系数为参考补齐该区间，再按各版本需要生成对应格式。吉他0/1采用源系数完整覆盖的40～71。班卓琴、曼陀林、长笛、大提琴、双簧管均从各自最低源音高开始取连续32音；小号、小提琴先补齐所选区间缺音，再分别采用51～82、55～86。
- 补齐指离线生成目标音高的系数，并以目标MIDI号建立资源索引；不允许接收配置时把缺音临时替换成邻近音高。钢琴的eng0矩阵格式不能直接作为eng1的ABC格式读取，转换后仍须验证。
- 这是目标资源及协议约定，**本次文档更新不代表系数补齐、32音镜像生成、RTL逐乐器范围校验或实板烧录已完成**。2026-11-02已为当前启用的六音色生成schema5逐乐器32音镜像，范围分别为钢琴0/1 21～52、吉他0/1 40～71、小号51～82、小提琴55～86；默认加载各自低16音。其它乐器尚未接入，未测试、未编译、未烧录。旧测试的40～71不能代表全部乐器；板级单一 `FIRST_MIDI=48` 也不能覆盖上述不同乐器的正式选区，正式板级代码已改为逐乐器映射；单一FIRST_MIDI仅保留给旧独立探针，生产32音模式不使用它。
- 板子按实际已启用的乐器和资源音符集合校验全部 16 项。编号未定义、资源未支持或音符超出对应范围时，整表不生效，返回结果码 `03`；不得静默移调、截断或替换成其他乐器。后端未就绪仍按结果码 `06` 处理。

### 3.2.2 鼓组统一外部编号与内部索引（2026-11-03冻结）

**手机自定义键位配置和MIDI乐谱演奏，统一使用标准GM鼓件的MIDI Note编号。外部不使用0～5。**
在自定义配置中，乐器编号仍为`07`；紧随的音符字节就是该GM鼓件编号，不是鼓组预设、GM Program编号或资源索引。
截图中的7、10～14属于旧界面条目号，不作为协议鼓件编号。

本机首版限定以下六件鼓/镲，与`FFT_results/params/drums.npz`及资源打包顺序一致：

| 鼓件 | 参数名 | 外部MIDI号（十进制） | 线上音符字节（十六进制） | 内部资源索引 | 鼓组区内字节偏移 |
| --- | --- | ---: | --- | ---: | --- |
| 底鼓 Bass Drum 1 | kick | 36 | 24 | 0 | 0x0000 |
| 原声军鼓 Acoustic Snare | snare | 38 | 26 | 1 | 0x1000 |
| 低嗵鼓 Low Tom | tom | 45 | 2D | 2 | 0x2000 |
| 闭合踩镲 Closed Hi-Hat | hat | 42 | 2A | 3 | 0x3000 |
| 叮叮镲 Ride Cymbal 2 | ride | 59 | 3B | 4 | 0x4000 |
| 吊镲 Crash Cymbal 1 | crash | 49 | 31 | 5 | 0x5000 |

内部0～5仅用于查表结果、资源排序和地址计算，不在线上传输、不用于手机显示。
不能直接把GM编号乘步长，也不能用`note-note_first`替代鼓件查表，因为上述编号不连续。

```text
自定义键位：乐器07 + GM Note38 ─┐
                             ├→ 统一GM鼓件查表 → 索引1 → 鼓组区内偏移0x1000
MIDI乐谱：第10通道 + Note38 ──┘
```

每件鼓仍保留64条记录×64字节=4096字节（0x1000）。52个有效计算槽不改变物理资源步长。
最终地址为`FLASH_BASE + 鼓组乐器区偏移 + drum_index*0x1000`，其中乐器区由`INST_DRUMS=7`选择。
保持当前每乐器32资源位置布局时，鼓组乐器区偏移为`7*32*4096=0xE0000`；其余位置保留，不扩展外部支持清单。
军鼓的两条噪声seed相对于鼓组区起点分别为0x1C00和0x1C80。

**两种入口保持相同的Note语义，但消息格式各自不变：**

- 手机键位表仍为`TYPE=02, COMMAND=20, LEN=33`。一项`07 26`表示鼓组军鼓（38）；每项仍是乐器、音符两个字节，不增加通道或内部索引。
- 标准GM鼓乐谱使用第10通道（线上的channel字段为9）。例如`99 26 64`表示军鼓Note On、力度100；`89 26 00`或`99 26 00`表示该Note结束。这里的字节均为十六进制。
- `TYPE=01`仍承载原始MIDI消息，Note字段保持38等GM编号，转换在识别为鼓组之后进行。
- 旋律乐器继续按自己的原始MIDI音高编号和范围处理，不受鼓件索引影响。
- 演奏指引、录制和手机展示保留外部GM编号；只有资源寻址使用内部索引，不能把索引1重新当作MIDI Note1发送。
- 本机首版只接受表中六个编号。其他GM鼓件（例如35、40、46、51、57）不自动折叠到现有六件，不作邻近编号替代；配置整表返回03，演奏事件按不支持事件处理。以后若增加别名，须显式扩展映射表和协议清单。
- MIDI Note Off的接收与鼓声自然尾音的生命周期分开处理，不能因编号转换而把松键变成直接截断尾音。

**实现状态：本节冻结的是协议与资源映射约定。当前鼓资源尚未安装，RTL仍需接入六项查表、默认鼓键位和第10通道鼓组路由；本次文档提交不宣称这些功能已实现或已烧录。**
此前“外部使用0～5、起始编号为0”的讨论方案由本节替代。当前同乐器16键自定义输入的范围不变，资源未开放前鼓组配置仍会被拒绝。

依据：[MIDI Association消息定义](https://midi.org/summary-of-midi-1-0-messages)、[General MIDI规范入口](https://midi.org/general-midi)、[Yamaha GM鼓件表（PDF第34页）](https://hu.yamaha.com/files/download/other_assets/5/317925/W7v2E.pdf)。

### 3.3 有线演奏录制

COMMAND=12/13 沿用已有录制启停编号，使用本文无 VERSION 帧格式，LEN=5。
录制ID由上位机指定，占4字节、小端编码；TYPE=82回传事件中的ID保持一致。
仅有线连接支持录制，蓝牙请求返回01。开始时要求音频后端已就绪、来源为PAD，
且当前乐器具有有效通道；未就绪返回06，已有录制或正在排空时返回04。
开始请求在真实采样帧边界进入active后才回复00。

停止请求必须匹配当前录制ID；ID不匹配或从未开始过录制返回03。
停止在采样帧边界生效，等待END描述符被发送编码器接收后回复；
同一录制正常完成后再停止仍回复00，失败的录制返回06。
启停完成等待上限为400ms，超时取消该次录制并返回06，为500ms主机期限预留回复时间。
来源隔离或本地撤销有线远程权限会取消录制。重复配置仍按第5节缓存规则处理，
不会重新启动录制。TYPE=82 的 24 字节事件 PAYLOAD 见 3.3.1。

### 3.3.1 TYPE=82 事件 PAYLOAD

TYPE=82 的 LEN 固定为 24。PAYLOAD 按小端存放；帧头 SEQ 取该事件 `ordinal` 的低 8 位，完整序号仍保留在 PAYLOAD 的 `ordinal` 字段中。

| 偏移 | 大小 | 字段 | 规定 |
|---|---:|---|---|
| 0 | 1 | kind | 00=录制起点；01=按下；02=松开；03=录制结束 |
| 1 | 1 | flags | bit0=1 表示录制失败或不完整；仅 kind=03 有意义，其余为 00 |
| 2 | 1 | channel | 设备通道，00～0F；等于界面 1-based 通道号减 1 |
| 3 | 1 | slot | 压力垫槽位，00～0F |
| 4 | 4 | id | 录制 ID，与 12/13 命令中的 32 位小端 ID 相同 |
| 8 | 4 | ordinal | 事件序号，起点为 0，每发一个事件加 1 |
| 12 | 4 | tick | 设备音频帧计数；起点为 0，按 frame_tick 递增 |
| 16 | 4 | a | 由 kind 决定，见下表 |
| 20 | 4 | b | 由 kind 决定，见下表 |

| kind | a | b |
|---|---|---|
| 00 起点 | 12500000（`20 BC BE 00`），采样率分子 | 256（`00 01 00 00`），采样率分母 |
| 01 按下 / 02 松开 | bits 7:0=MIDI 音符；bits 15:8=力度 01～7F；bits 31:16=0 | 0 |
| 03 结束 | 0 | 最后一个事件的 `ordinal` 减 1 |

- 时间换算：`秒 = tick × b / a`；起点使用 `a=12500000、b=256`，即板端 frame_tick 为 48828.125 Hz。
- 同时按下的多个键各自发送一条事件，`tick` 相同，用 `slot` 区分；按下与松开用同一 `slot` 配对。
- 起点在录制真正进入 active 的采样帧边界发送；结束描述符在停止回复前发送，且 `b` 指向结束前最后一个事件。
- 录制帧与配置回复共用同一 SLIP/CRC 帧格式；上位机按 `kind`、`slot` 和 `ordinal` 还原音符，不按到达时间计时。
- 当前默认钢琴低音组为 21～36，因此首音回传为 MIDI 21，不是旧 40～76 映射的 40。

## 4. 配置回复

TYPE=80，SEQ 沿用原请求，LEN=2。

```text
PAYLOAD = [原 COMMAND] [结果码]
```

不回传整张键位表，也不额外携带原请求 TYPE。

| 结果码 | 含义 |
|---|---|
| 00 | 成功，配置已生效 |
| 01 | 不支持该命令 |
| 02 | 命令长度错误 |
| 03 | 参数越界或不支持该乐器／音符 |
| 04 | 设备忙，本次未生效 |
| 05 | 相同 SEQ 对应的请求内容不同 |
| 06 | 后端未就绪或提交失败 |

## 5. SEQ、超时和重发

SEQ 用于匹配请求与回复，并识别重复请求。它是请求编号，不是命令号。

- 同一时刻最多有一条配置请求等待回复。
- 新请求使用新 SEQ，按 00～FF 循环；超时重发保持相同 SEQ 和相同内容。
- 板子对重复请求只重放结果，不重复执行。
- 上位机收到 CRC 有效且 SEQ、COMMAND 匹配的配置回复后，结束本次等待。
- 收到明确的成功或失败回复后，不再按超时规则重发。
- 明确失败后若要再次尝试，作为新请求使用新的 SEQ。

### 5.1 超时间隔

**配置回复超时为 500 ms，超时后立即重发，最多重发 3 次。**

1. 从请求帧最后一个字节发送完成开始计时。
2. 500 ms 内未收到匹配的有效回复，重发原请求。
3. 每次重发完成后，重新计时 500 ms。
4. 首次发送加 3 次重发，最多发送 4 次。
5. 最后一次仍超时，上位机报告“配置结果未知”，停止自动重发。不能据此断定板子没有执行。

板子必须在 500 ms 内完成配置并回复，不能无限等待按键释放。若暂时无法提交，应及时返回 04 BUSY，保持原配置不变。上位机计时还包含回复传输时间，板子应预留回复发送余量。

键位表 0x20 在等待旧按键释放时，板端约 400 ms 超时：回滚旧表并返回 04；来源隔离或权限丢失时取消在途表并返回 06。

## 6. CRC 校验

使用 CRC-16/CCITT-FALSE：

```text
width   = 16
poly    = 1021
init    = FFFF
refin   = false
refout  = false
xorout  = 0000
check("123456789") = 29B1
```

覆盖原始未转义的以下字节：

```text
TYPE + SEQ + LEN + PAYLOAD
```

CRC 本身和首尾 C0 不参与计算。计算完成后，先追加 CRC 低字节，再追加 CRC 高字节。

## 7. 帧边界和转义

首尾标记均为 C0。先计算并追加 CRC，再对首尾标记之间的所有字节进行 SLIP 转义：

| 原字节 | 实际发送 |
|---|---|
| C0 | DB DC |
| DB | DB DD |
| 其他 | 保持原值 |

LEN 始终按转义前的 PAYLOAD 长度填写。接收端先反转义，再检查长度和 CRC。

连续 C0 之间的空帧忽略。CRC 错误、非法转义、帧长度不符或 PAYLOAD 超过 64 字节时，丢弃该帧，不执行、不回复；上位机通过超时规则重发配置请求。

## 8. 收发示例

以下 CRC低、CRC高为占位说明，实际发送时必须计算并进行转义。

### 8.1 设置大厅混响

请求 SEQ=04，PAYLOAD 为命令 02 和预设 01：

```text
C0 | 02 | 04 | 02 | 02 01 | CRC低 | CRC高 | C0
```

生效后回复，PAYLOAD 为原命令 02 和成功结果 00：

```text
C0 | 80 | 04 | 02 | 02 00 | CRC低 | CRC高 | C0
```

### 8.2 整套键位配置

请求 SEQ=05，PAYLOAD 共 33 字节，LEN 在线上填写 21：

```text
C0 | 02 | 05 | 21 | 20 [键0乐器][键0音符] … [键15乐器][键15音符] | CRC低 | CRC高 | C0
```

全部生效后回复：

```text
C0 | 80 | 05 | 02 | 20 00 | CRC低 | CRC高 | C0
```

表示编号 05 的整套键位配置命令 20 已执行成功。

如果参数不合法，则回复：

```text
C0 | 80 | 05 | 02 | 20 03 | CRC低 | CRC高 | C0
```

表示该请求未生效，原键位配置保持不变。
