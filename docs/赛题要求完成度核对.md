# 赛题要求完成度核对

核对日期：2026-10-23；代码基线：`4809eb1e`。仅核对设计、代码与测试，不改 RTL、不烧录。

主要依据：[仓库赛题原文摘录](../reference_agent_readfirst/competition_requements_most_important.md)。本轮重新运行 `sim/run_core.sh`，**21 项 PASS**；这是模块／小规模系统仿真证据，不代表下表所有整机要求均已达标。

## 1. 先说结论与判定口径

**合成计算与部分后级已经做出来，但按当前正式路径，基础要求还不能整体勾“完成”。**主要缺口是完整演奏输入、可控包络、实时变调、新板级音频集成、四复音与延迟验收。与此同时，电脑编辑器、手机控制和频率增益等产品规划，已有不少超出基础必做范围。

“完成”必须注明层级：

- **模块已实现／已测**：有 RTL 与对应仿真，不保证正式顶层已经使用，也不保证实板达标。
- **部分实现／待集成或验收**：有架构或可复用模块，但题目要求的整条功能链缺失，不能笼统说“没做过”，也不能说“已完成”。
- **已设计、未实现**：有方案、流程或协议草案，尚无可工作的实现。
- **未细设计**：只有模块名、目标、历史概念或题目提及，未见当前可执行的接口／状态机／映射／验收方案；不是断言作者线下从未考虑。
- **自主增加／超出最低要求**：可以有产品价值，但不能替代基础项；也不代表天然获得额外分数。

`architecture-checklist.md` 的旧勾选不是新架构整机验收：例如压力／摇杆／LED 驱动代码仍在，但当前正式 `router_system_top` 并未接成完整演奏链；旧 I2S／FIFO 已归档，当前平台目录没有新板级 top。

## 2. 基础要求与总体设计：逐项核对

| 编号／原文要求 | 当前状态 | 实际证据 | 尚缺什么，才能按题验收 |
|---|---|---|---|
| **B1 自研交互，至少 2 个独立可控维度** | **部分实现，整机未闭环** | 旧 `pad_driver` 有 4×4 压力、摇杆和 LED；`excitation_convert` 已做线性转换；正式 frontend 只取 `fmap[7:0]`，top 只覆盖 slot0 激励 | 接入实际驱动；完成位置／键码与力度等独立映射、多键触发／释放、校准和稳定性验证。仅接 128 bit fmap 或存在两个 ADC 通道不能作为完成证据 |
| **B2 FPGA HDL 逐样本实时合成** | **计算核心已实现／仿真通过** | ABC 二阶递推、E2 状态空间、共享系数／状态 RAM、调度与混音均有 RTL 和测试 | 新板级采样 tick、装载／计算仲裁、持续音激励等闭环；验证连续运行无欠载。当前核心完成不等于完整音频生成通路已验收 |

| **B2 总延迟 ≤10 ms** | **目标明确，尚未证明** | 有探针 Fmax 与核心仿真；没有当前整机端到端测量结果 | 明确计时起止、扫描与缓冲最坏预算，测输入→音频输出的最坏延迟／抖动。100 MHz 或每样本预算不能代替这个指标 |
| **B3 ≥4 路独立声部同时可闻** | **有设计和部分实现，未完成该验收** | 默认 16 槽；当前 `tb_engine_mux` 实测 2 voice×5 mode，系统冒烟主要为单槽 | 至少四个不同音高同时、独立开关／控制、混音和周期验证，再上板频谱／听音。参数写 16 不自动证明 ≥4 达标 |
| **B3 单音实时变调** | **有方案／占位，未实现闭环** | 上位机分析 §8 有系数更新候选方案；`linear_modulation` 有独立多项式单测，但未接正式 top，系数单字段写口关闭 | 持音时改变频率，安全更新系数、状态连续、稳定性和音准验证。加载另一个音符或电脑编辑弯音曲线不等于板端实时变调 |
| **B3 ADSR 包络调控** | **乘法已做，完整控制未细化／未实现** | `envelope_mul` 是乘法器；系统 env 固定 1；pure ABC 的每 voice env 也固定 1；Note Off 直接清 active | 定义并实现 A/D/S/R 或经认可的替代包络、参数、触发／重触发和 release 语义；不能把自然模态衰减或常数增益当作完整可调包络 |
| **B3 多声部实时混音** | **模块已实现／小规模验证** | ABC 汇总 lane／voice，mux 和 post/final 路径已有测试 | 与四声部以上真实激励联测、输出电平／饱和、吞吐和连续播放验证 |
| **B3 禁止预录 PCM／整段录音触发** | **当前核心路线符合，最终 top 仍需审核** | loader 读取模态系数／索引／seed，合成核按状态递推，不播放样本音频；离线提参不在实时发声链 | 最终源清单与 RTL 审查；不能把 FFT 仿真使用的乐曲 ROM 或电脑渲染 PCM 接到主发声路径 |
| **总体多音色／拓展 ≥2 音色自由切换** | **有系数／loader 设计，交互切换未验收** | 多音色参数库、逐 voice 装载和 ABC/E2 计算路径已有；body 固定 instrument 0 | 选定至少两种实际音色、覆盖音域／激励／包络、用户切换入口和清音策略；class 个数不等于实际可切换乐器数 |

**ADSR 的补充说明：**仓库答疑 `gowin_q&a.md` 技术相关第 76 题说“命题相对灵活，应该不是定死的”。这是补充线索，不覆盖原文；若采用替代包络，需确认认可口径并展示可控行为。即使允许 AR 等替代，当前恒定增益和无 release 管理也不能据此自动算达标。

## 3. 拓展要求：哪些已做、哪些还欠缺

| 拓展项 | 原文口径 | 当前状态与设计缺口 |
|---|---|---|
| **E1 大规模并行合成** | ≥32 复音，**或**单音 ≥32 加法分量，**或**多条并行物理建模单元 | 已有 4 lane、ABC 默认最多 48 mode、E2 默认最多 80 mode 的设计；当前选择更接近并行模态路线。没有完成有效可闻单元统计／满载周期／现场谱峰验证。不能用 16 voice 说达成 32 复音，也不必为这一项强行做 32 voice |
| **E2 ≥3 维表情、力度／滑音／颤音** | 在基础交互上扩展表现力 | 力度转换有局部实现，摇杆采集有旧驱动，变调有候选方案；但“哪三维、如何独立操作、调制何参数”未形成当前完整设计。正式 top 未接滑音／颤音链；手机有三个滑块不能自动替代演奏表情 |
| **E2 FPGA 效果器** | 混响、延迟、合唱等 | **四梳状混响已实现并默认接入**，body、dry/wet 等已有。混响参数固定、听感与峰值待验收；独立 delay／chorus 未见当前实现／细设计。混响内部延迟线不是独立可调 delay 产品功能；也不应把列举的所有效果器擅自改成必须全部实现 |
| **E3 ≤5 ms、确定性无抖动** | 比基础延迟更强的拓展指标 | 目前没有当前整机的预算闭环和测量证据；必须把扫描、事件时刻、加载、缓冲和音频链一起计算／测试，不能只看 DSP 核延迟 |
| **E3 FPGA 可视化反馈** | LED、李萨如、实时频谱、波形等 | FFT／频谱／瀑布有独立 RTL 和集成设想，但未接主引擎，当前已记录编译阻塞。波形仍占位，李萨如只见历史后续计划；LED 驱动不等于演奏指引。电脑 WebGL 显示不替代 FPGA 硬件可视化 |
| **E4 脱机 LED 曲目指引** | 曲目／节奏辅助 | LED 底层驱动已有；未见当前曲目存储格式、音符／键位→LED 映射、节拍调度、播放／暂停／重启等完整设计。**这是实际的设计空缺**，不是只差把 LED 接上 |
| **E4 蓝牙＋手机 App** | “可搭载”，属于拓展 | 有简化 App 产品规划：连接、选音色、音量／效果宏参数；无 BLE 协议／模块接入及 App 实现。它是题目内拓展，不是题外创新 |
| **E4 在线曲谱下载** | 智能联动的列举功能 | 未见服务来源、授权／格式、下载到板端／手机的流程、离线缓存等当前设计；本地 MIDI 导入不是在线曲谱下载 |
| **E4 演奏键位自定义** | 智能联动的列举功能 | 产品稿提过键位／音阶映射，但无当前 pad→note 表格式、保存、下发和冲突策略；属于**概念级提出，尚未细设计／实现** |
| **E4 演奏录音回传** | 智能联动的列举功能 | 电脑 UART PCM 抽头／分包方案已有，尚未实现；手机接收／录制／保存的链路未设计闭环。保存 MIDI 事件、电脑模型渲染、硬件 PCM 实录须区分，不能互相冒充 |

拓展项可选，不把“没选中的例子”全部列为基础缺陷。尤其不能把 E1 的三个分支改为同时必须满足。E4 的具体得分／验收组合仍应向赛方确认，本文不推导分值。

## 4. 题目另外要求的现场证明：目前缺专门方案

| 要证明什么 | 当前已有 | 未形成的当前交付 |
|---|---|---|
| 多路不同频率同时输出、看到对应独立谱峰 | 递推核、旧单独测试音／诊断素材、独立 FFT 核 | 可选择数量与频率的**正式现场测试模式**，与主合成链使用同一计算／输出路径；不能只展示旧方波或任意频谱图片 |
| 独立振荡器／模态数及吞吐 | voice／mode/lane 结构与相关参数 | 实际同时活跃且可闻数量、独立状态／控制的统计说明、频谱证据、实际 DAC 输出采样率与 `数量×采样率` 结果 |
| 纯硬件生成，没有预录播放 | 当前算法源码与系数 ROM | 最终源清单、现场演奏改变实时结果的演示、排除 PCM 播放通路的证据 |

## 5. 按用户关心的四类归纳

### A. 已经做出来的部分（不是整机全通过）

- ABC／E2 定点合成核心、共享 RAM、loader、显式槽位记账、混音。
- 后级增益乘法、四段腔体 biquad、四梳状混响、dry/wet／final。
- 压力线性转换原型；压力／摇杆／LED 有可复用旧驱动。
- 当前核心 21 项回归 PASS；旧音频链有历史实现／出声记录。

### B. 已设计或已有模块，但尚未实现／集成／验收

- 完整矩阵演奏、16 槽运行、音色切换与新 I2S/DAC 板级集成。
- 变调方案和调制占位；包络位置已设计，但发生器／完整控制语义未完成。
- FPGA 频谱／瀑布接入与已有编译／对齐问题修复。
- 电脑 UART 协议／MIDI 工作台／音频回传草案；手机简易控制的产品规划。
- 四复音、满载周期、≤10 ms／≤5 ms 都缺最终证据，不能只算“写完代码”。

### C. 超出题目最低功能清单的自主设计

| 自主设计 | 与题目的关系 | 对当前排期的含义（建议，不是删除决定） |
|---|---|---|
| 完整电脑 MIDI 编辑器、多轨卷帘、量化／撤销等 | 题目没有要求做一个编辑／编曲软件 | 可先做最小测试／控制面板，完整编辑器不能替代演奏闭环 |
| WebGL 前端、WASM 本地试听／模型 WAV 导出、桌面打包 | 属于产品实现与分发方式，不是 FPGA 题目指标 | 不应比硬件端变调／包络／出声更优先 |
| 频率—增益曲线、逐模态音色塑形 | 用户音色设计附加能力，不是原文明列的基础必做；也不等于实时变调 | 可作特色，但要与 DSP 安全更新和实际听感一同验证 |
| A/B/C/E2 多种计算路径并存 | 题目允许任选合规算法，不强制两套不同递推核 | 是自选实现复杂度；若服务 ≥2 音色／并行模态可有价值，但核数量本身不是额外必做 |
| 频谱之外的瀑布历史、精细页面和跨端预设协同 | 题目鼓励可视化／联动，但没有强制这些具体形式 | 属于展示／产品体验深化，不自动抵消缺失的硬件可视化或 LED 曲目指引 |

**不应误归到题外：**蓝牙手机联动、录音回传、实时频谱、混响，原文都已列为拓展方向；16 槽高于基础 4，但仍是题内复音方向，不是独立的题外创新。

### D. 提过名字或目标，但还没有细设计的地方

优先补的是：

1. 可控包络发生器及逐 voice Note On／Off／重触发／release 语义。
2. 具体的三维演奏映射，特别是摇杆／压力如何分别驱动滑音、颤音等参数。
3. 脱机 LED 曲目指引的数据、节拍和显示控制。
4. 当前正式现场测试模式、独立可闻模态统计和延迟验收方案。
5. 在线曲谱下载、可保存／可下发的自定义键位、手机端硬件录音回传闭环。

独立 delay／chorus、真波形／李萨如可列为未选择或低优先级候选，不因未细设计就判基础不合格。32 voice 是 E1 的可选路线之一，当前未选它也不是必须补的漏洞。

## 6. 建议的先后：先基础闭环，再选拓展，最后产品增强

1. **P0：冻结最低可交付演奏语义**：至少两个可独立操作维度、至少四复音、可控包络、持音实时变调；明确是否采用替代 ADSR 及其认可口径。
2. **P0：新音频板级闭环**：采样 tick→合成→后级→PCM→FIFO→I2S→DAC，完成连续播放／复音／峰值与 ≤10 ms 验收。可先使用现有可用音色路径，不强制四种 class 同时齐全。
3. **P1：选定少数拓展闭环**：建议先做 ≥2 音色切换、现有混响和 FPGA 频谱；并行模态达标与吞吐用正式测试模式证明。≤5 ms 先测再承诺。
4. **P1/P2：按选择补 LED 曲目指引、三维表情或 BLE 简易控制**，不要把这些都当成已被产品方案覆盖。
5. **P2：扩展电脑 MIDI 编辑器、频率曲线、WASM／多轨／跨端预设体验**。这些可以强化产品，但不是基础交付的替代物。

不提供“已完成百分之多少”：缺少官方细分权重，且模块通过、历史板级通过和当前整机达标不是同一分母。
