## 1. 证据口径

源码存在、功能仿真、独立时序探针与当前整机上板分别记录。历史歌曲工程、Python WAV、LCD 测试音源均不能直接证明当前压力→合成→DAC 主链合格。

本页是要求→实现→验收证据的唯一总表，原架构检查表和设计报告底稿已并入。日期化测试数字见 [工程评审与验证](工程评审与验证.md)，源码缺陷/复现/关闭条件见 [问题台账](bugs.md)，模块实例树见 [代码架构](../CODE_ARCHITECTURE.md)，不在多份总表重复更新。

## 2. 基础及总体要求

| 要求 | 已有实现 | 达标前还需什么 |
|---|---|---|
| 自研交互，至少 2 个独立可控维度 | 4×4 压力采集、原始摇杆 X/Y、校准/八方向/连发；侧栏已接摇杆适配接口 | 真实 ADC/矩阵位置、独立演奏映射与多键稳定性；控制菜单的摇杆不自动等于第二个声音表情维度 |
| HDL 逐样本实时合成 | 双 bank voice_router、eng0/eng1、激励/包络/混音/腔体/混响 | eng1流水/空作业已修且本次256组对拍通过；持续音色前端、全路径数值、当前系统吞吐/混响和实板仍待验 |
| 禁止预录 PCM 触发播放 | 当前核为系数/状态递推；Flash 保存参数；电脑 WAV 用于验证 | 审核最终综合源清单，现场演示通过同一输出链实时改变声音 |
| I2S→DAC 发声 | PCM16/FIFO/I2S模块已有；当前演奏顶层缺音频端口/实例，系统回归展开失败 | 恢复接线并重验完整系统，再完成DAC、时钟复位/管脚、PnR与连续播放 |
| 总延迟 ≤10ms | 独立模块/时序数据已有，尚无当前输入→DAC 测量 | 冻结计时起止，计入扫描/加载/排队/音频缓冲，测最坏值和抖动；平均吞吐不能代替延迟 |
| ≥4 路独立可闻声部 | 默认 16 槽，前后半 bank 并行；Flash 按 slot 独立音高，钢琴镜像 16 音 | 至少四个不同音高的独立起音/松键/控制、频谱/听音；已有bank独立状态/43帧混音检查，仍不能代替真实声学与板级验收 |
| 单音实时变调 | PAD吉他后台调制已接，持音压力变化也挂请求；一阶近似只调最低4模态 | 整帧安全提交、独立UI开关/深度、音准/稳定性及最坏周期验证；MIDI Bend DSP尚未接 |
| ADSR 包络调控 | 钢琴ADSR、压力dyn0及默认起音钳位已有；四种eng1持续音色仍走常数包络 | 接持续音色ADSR/逐槽周期，验证PAD/MIDI松键、清理退休和开放参数 |
| 多声部实时混音 | 逐槽乘 Q1.31 包络，再跨槽 64 位累加、腔体/混响 | 满力度溢出/削波、全槽独立性、连续供样与真实幅度定标 |
| 多音色/至少 2 音色自由切换 | 统一乐器编号、选核、待松键重载、逐槽资源布局 | 钢琴/吉他默认16音镜像已匹配当前表，联合配置与失败保护已接；正式资源、忙时panic、真片/实板验收待收口 |

赛题对包络的补充答疑可作为讨论依据，但不替代实际可控行为和验收口径。当前“乐器 0..9”是目录，不能按枚举数计算已交付音色。

## 3. 拓展要求

| 拓展方向 | 当前进度 | 尚缺闭环 |
|---|---|---|
| ≥32 复音，或单音 ≥32 加法分量，或多条并行物理建模单元 | 默认 16 槽×64 物理模态、双 bank 并行；钢琴计算64/吉他20/eng1首版48，物理存储64，按顶层限幅 | 选择实际申报分支，统计有效且可闻的独立分量、谱峰、吞吐和满载；三个分支不要求同时满足 |
| ≥3 维表情、力度/滑音/颤音 | 压力参与激励/动态包络/吉他起音调制；摇杆原始双轴和 UI 已有 | 明确独立输入到声音参数的映射；同一个压力驱动多个参数不自动成为三维；持音变调待收口 |
| FPGA 效果器 | 五段腔体、四梳状混响和 NONE/HALL/BATHROOM | 数值范围、预设安全切换、真实配置后端和音频验收；EQ parser 存在不代表 EQ DSP 已实现 |
| ≤5ms、确定性低抖动 | 未有当前整机测量 | 与基础延迟同一路径、同一定义，测最坏值；探针 Fmax 不代替此指标 |
| FPGA 可视化反馈 | FFT/BARS/WAVE/FALL/中文侧栏；17 项 UI/可视化用例通过 | 合成器 PCM 定标、异步 FIFO、现场同源显示；LCD 内部三音/扫频只是独立测试 |
| 脱机 LED 曲目指引 | LED 底层驱动存在 | 曲谱格式、键位映射、节拍/播放控制和实物指引 |
| 蓝牙+手机 App | HC-05 透明 UART、可选 STATE、双链路协议和会话协调已实现 | 实物HC-05、手机软件和物理链路恢复；MIDI消费者已有但尚未完成整机联机；HC-05 不应写成已经实现 BLE/GATT |
| 在线曲谱下载/自定义键位 | 产品规划，逐槽音高资源已有基础 | 来源/格式/缓存、映射保存/下发/冲突规则及应用闭环 |
| 演奏录音回传 | 上位机带宽与分包方案讨论，v1 没有 PCM 上传命令 | 音频抽头/分包/主机存储/手机接收；MIDI 事件记录与硬件 PCM 实录分别验收 |

拓展项按最终选择实施，不把所有列举功能都算基础缺陷。电脑多轨编辑器与有线UART软件首版已有；WASM物理模型试听、精细频率塑形和跨端预设仍属规划。软件编辑能力不计为硬件复音/多音色验收。

## 4. 现场证明材料

1. 同一路主合成/DAC 链支持可选多频测试模式，展示独立谱峰；不能由 LCD 内置测试源替代。
2. 记录承诺的声部/模态数、有效音高/幅度、首帧/稳态/切换周期、实际采样率及 `数量×采样率`。
3. 通过演奏实时改变输出，并检查最终源清单，证明硬件生成。
4. 用约定输入/输出标记测延迟，保存重复次数、最坏值、抖动及测试条件。

## 5. 当前优先级

- 先收拢当前工作区：恢复音频顶层接口/统一采样连接，核对忙时panic与原快照差异，重跑系统及MIDI/UI/loader回归。
- 为四种eng1持续音色实施逐槽周期驱动、ADSR与释放退休，绑定同源真实资源；冻结正式六种32音范围及烧录清单。
- 解决混响乘积、调制表提交和真实控制消费者；完成真Flash、ADC键位与四路独立可闻声部验证。
- 在最终时钟/约束/引脚上完成PnR、DAC连续播放和≤10ms测量，再接独立PCM可视化抽头。
- 上位机优先做物理UART演奏联调；App、录音回传、WASM和LED指引按选定范围推进。

## 6. 设计报告素材与交付材料

报告可以围绕“离线参数准备、硬件逐样本合成、交互配置、通信接入、可视化反馈”组织，具体结构引用架构导读和各专题合同。录音只用于参数提取/对比，模型WAV、RTL仿真WAV、板级录音分别标明来源。正文按前表标注已有/待接/待测，不再维护一份容易漂移的完成勾选表。

可说明的设计取舍：参数化模态递推；双bank分离并行存储访问、复用混音后级和后台调制；配置区分接收与真实生效、显示帧头提交；通信分层并保留物理来源及恢复确认。这些是本项目采用的方法，不宣称算法/协议/产品形态首创。产品需求论证和竞品来源统一引用 [产品文档](产品需求与竞品调研.md)。

最终交付应绑定源码/参数/约束/工具版本与bitstream，附当前板级资源/时序、连续播放欠载/削波、四路独立音高/松键、两套真实音色、持音变调及延迟测量。现场多频测试必须走正式合成/DAC路径；独立LCD测试源不替代该证据。
