# 音频回传

日期：2026-10-31。基于当前工作区核对，仅新增设计文档，未实现协议、RTL 或录音 UI。目标：网页开始录音 → FPGA 按 DAC 音频时间轴实时回传 → 网页停止录音 → 排空并保存 WAV。不在 FPGA 保存整段录音，不采集麦克风或 DAC 后模拟信号。

> 需求更新（2026-10-31）：当前优先目标是“演奏回传生成可编辑 MIDI 音轨”，实施入口改为[演奏录制与可编辑音轨设计](演奏录制.md)。本文保留为后续 PCM/WAV 音频参考录制方案，不能用PCM文件替代可编辑音符。新增蓝牙v2已占用TYPE81为CONTROL_REPLY；本文TYPE81只属于待定的有线v1扩展，实施前须重新审定协议版本和类型分配。

## 1. 结论与现状修订

48,828.125 Hz、PCM16 单声道、3 Mbps 有线 UART 可作为首版目标，需实测桥接器持续吞吐并重新验证时序。蓝牙继续 115200，不承担录音流。保留实时演奏，录音队列不得反压 DAC 或改变采样节拍。

核对入口：

- `web/midi-editor/src/serial.mjs`：RX 仅计数/日志，无音频消费者；`panic()` 会取消尚未发送的整个队列。
- `web/midi-editor/src/protocol.mjs`：仅 01/02/80；40-byte body 上限；编码 LEN 高字节写死 0，扩展大包时必须改成真正 u16 LE。
- `rtl/comm/transport_link.sv` / `slip_frame_tx.sv`：仅固定 REPLY 编码与两项回复队列。
- `rtl/drivers/analyzer/config_analyzer.sv`：只支持 EQ/REVERB；配置等待此前 MIDI 退休并独占 parser，去重缓存为每来源最近一次完整请求。
- `rtl/platform/tang_mega_138k_pro/instrument_system.sv`：有线/蓝牙仍共用 BAUD 输入；配置桥目前只实际转接混响。
- `rtl/audio/i2s_audio_output.sv`：默认双声道；core 域空间处理完成的 token_valid 比 sample_tick 晚约 26 拍。直接同拍读取这两个信号会错位。FIFO 写端与 DAC 消费端也不等价。
- 串行器在 audio 域 `rready` 边界锁存 `rvalid ? rdata : 0`，这是录音的推荐抽头。`sample_valid/sample_value` 及现有 FFT 抽头不能直接用作录音时间轴。

## 2. 范围、格式与带宽

首版固定：48,828.125 Hz（12,500,000/256）、单声道 signed PCM16、小端、无归一化、连续录音上限 600 秒。未来更换音频时钟时，传实际采样率，不继续写死 48828。

当前输出为左右 PCM16，首版录音取 `mono = (signed17(L) + signed17(R)) >>> 1`，加法先扩位防溢出。它是 DAC 数字左右声道的平均下混，不保留空间定位，也不等同于合成器空间处理前的单声道。若要保留立体声，另立扩展规格。

按本设计每包 256 个时间样本、24-byte payload 元数据计算：

| 项目 | 单声道首版 |
|---|---:|
| PCM 净荷 | 97,656.25 B/s |
| 满包频率 | 190.735 帧/s |
| 满包 payload / decoded body | 536 / 544 B |
| 未转义线上帧（含两枚 C0） | 546 B |
| 全 body 最坏转义线上帧 | 1090 B |
| 未转义 / 最坏流量 | 104,141.24 / 207,901.00 B/s |
| 3 Mbps 理论 8N1 容量占比 | 34.71% / 69.30% |
| 单包最坏串行时间 | 3.63 ms |

这些是连续满包预算，不含 UART 实现字节间空隙、USB/驱动停顿、回复及故障后短包开销。现有 TX 状态机有字节间额外周期，实际持续能力必须测量。

2 Mbps 无法覆盖最坏转义。立体声在 3 Mbps 下未转义数据可能传得动，但不能保证最坏转义下持续无损；不能笼统解释为任何立体声数据都传不动。录音期间限制无意义的控制面刷新，REPLY 帧边界优先，诊断中统计 PCM 等待与 FIFO 水位。

50 MHz core 下 RX 使用 NCO 时钟使能，3 Mbps × 16 = 48 MHz 不是新增的 48 MHz 时钟域。16× 与 8× 都需做位相/波特率偏差/连续字节测试；可优先评估有线 8×，不以降低过采样替代时序验收。使用已有 WIRED_OVERSAMPLE/BT_OVERSAMPLE 分参数，顶层另拆 WIRED_BAUD/BT_BAUD。

## 3. 端到端结构

```text
I2S / PT8211 共用的 audio 域帧消费边界
  → 实际锁存的 L/R（FIFO 空时零）→ mono 下混
  → record_capture：index、record_en、丢样计数
  → 异步 FIFO（audio 写 / core 读，16K × 48bit）
  → 连续 index 分包 / PCM 编码器（256 样本上限）
  → 帧级仲裁：已有 REPLY 编码器 + 新 PCM 编码器
  → 有线 UART TX

Web Serial RX → 有界 SLIP/CRC → REPLY 请求匹配 / PCM 分发
  → PcmRecorder（补零、去重、上限、完整性）
  → PCM 块列表 → WAV header + Blob → 下载
```

音频取样使用串行器**同一锁存边界**的握手和数据，不能在 registered frame_tick 的后一拍重新读取已被弹出的 FIFO 项。最好从音频模块暴露 `{record_sample_valid, record_sample_left, record_sample_right}`，其中数据在该边界锁存，valid 每个音频帧一次。录音模块不自行猜测 FIFO 读时序。

控制请求通过 mailbox/握手送 audio 域；STOP 同时返回稳定的最终计数快照。多位计数不能各 bit 简单双触发同步。FPGA FIFO 是短期弹性缓冲，PC 才是整段音频的存储方。

## 4. 协议扩展草案

沿用 VER=01 的外层 header、SLIP、CCITT-FALSE 和 u16 LE LEN，新增方向限定的类型/命令；旧固件对新命令返回 UNSUPPORTED，UI 明确提示不支持。实施时先更新 PROTOCOL_V1.md 和黄金向量，本文不是另一份已生效合同。

### 4.1 CONFIG

| 命令 | payload | LEN | 结果语义 |
|---|---|---:|---|
| 10 RECORD_START | cmd:u8, recording_id:u32 LE | 5 | audio 域已在确定边界开始采集，状态已锁存 |
| 11 RECORD_STOP | cmd:u8, recording_id:u32 LE | 5 | 停采集、最终样本快照和全部 PCM/END 已有序交给有线 TX |

只允许有线来源；沿用现有远程配置权限，不静默放宽权限。recording_id 由主机生成，当前串口会话内不复用，区别于 CONFIG SEQ。CONFIG 仍独立 16-bit 序号，最多一个在途请求；重试使用原 SEQ 和完全相同 payload，缓存命中不重置采样计数。

同 ID 重复 START 不重复开启；不同 ID 在 recording/draining 阶段返回 BUSY。STOP 的 ID 不匹配拒绝，不停别的录音；同 ID 已完成 STOP 可重发原 END，避免 END 损坏而缓存只重放 ACK。录音期间其它 CONFIG 首版在主机禁用，设备明确返回 BUSY；避免替换最近缓存后迟到 START 被再次执行。不要让 CONFIG 等待占用 PCM 排空所需的编码器。

START 完成后，先排入并发送 START REPLY，再放行该录音的 PCM 帧；采样可以先进入 FIFO。主机仍从 arming 起安装接收器，避免等待 ACK 的代码路径丢弃早到样本。

### 4.2 TYPE 81 PCM_STREAM（仅设备 → 有线主机）

| offset | 字段 | 说明 |
|---:|---|---|
| 0 | format:u8 | 0 = PCM16 mono |
| 1 | flags:u8 | bit0 END；bit1 该录音累计发生设备端丢样；其它为0 |
| 2 | count:u16 | DATA 为1..256；END 为0 |
| 4 | recording_id:u32 | 与 START / STOP 一致 |
| 8 | first_index:u32 | DATA 首样本 index；END 为 total_samples（排他结束位置） |
| 12 | sample_rate_num:u32 | 首版 12,500,000 |
| 16 | sample_rate_den:u32 | 首版 256；不得为0 |
| 20 | dropped_total:u32 | 本次录音设备端累计丢弃的样本数，END 为最终值 |
| 24 | samples | count × signed PCM16 LE |

DATA LEN=24+2×count；END LEN=24。END 永远单独发，即便 0 个样本、恰好整包、尾部全部丢失也发送。流 SEQ 独立递增，仅诊断；重建音频依据 recording_id + index，不依赖 SEQ 的16bit回绕。

PC 接收 decoded body 上限扩为544，按 TYPE 独立验证长度，继续保持 MIDI≤32、CONFIG≤16、REPLY=3。不把 FPGA 的 MIDI/CONFIG RX 缓冲整体扩大：新增大包只在设备 TX / 主机 RX 路径。最大线上1090B，超长/非法转义/CRC失败必须丢弃并重同步。

## 5. 丢样、分包与尾部恢复

- index 每个**实际 DAC 时间帧**递增，第一帧为0；计划静音/加载/停演奏/欠载帧均录零，不能缩短时间。
- FIFO 满丢最新样本，index 仍递增，dropped_total 递增；不回压 DAC。
- FIFO 存 `{index32, mono16}`。分包器遇到 index 不连续时，立即结束已有短包，把不连续的下一项保留为下一包首项；一帧内只能包含连续 index。否则一个 first_index 无法描述包内缺口。
- PC 从 expectedIndex=0 开始；first>expected 时补零；first<expected 时仅保留未覆盖后缀，整包旧数据丢弃。不能因为一个重复帧把 expected 倒退。
- 合法 END 中 total_samples>expected 时补齐结尾静音；total<expected 为协议错误，保留数据并标记不完整，不静默截断。
- dropped_total 是设备丢样；主机补零总数还可能包含 CRC/传输丢帧，二者不相加重复计数。UI 分别报告缺失样本、设备丢样、坏帧和重复帧。
- 单包 index、最终总数和补零分配均受600秒上限约束；越界时停止并标记异常，禁止按任意 u32 index 分配 GB 内存。
- END 丢失但 STOP ACK 成功：重试同一 STOP 获取 END；仍缺 END 时文件只能标记不完整，不能宣称长度完整。ACK 丢失但合法 END 到达：可完成本次录音；不要接着用新 SEQ 重新开始采集。

## 6. FPGA 状态、CDC、仲裁与异常

状态：IDLE → STARTING → CAPTURING → DRAINING → END_TX → COMPLETE；FAULT/ABORT 可从在途阶段进入。STOP 在 audio 帧边界生效：在同一帧到来的 STOP 优先，不再采这帧；total_samples 等于此前已计数时间帧数。START 在边界生效并采集该边界样本。边界语义应做明确 TB 断言。

16K×48bit FIFO 为786,432bit（96KiB），对应约335.5ms采样弹性，不是无限驱动停顿保障。实际 BSRAM 占用取决于宽度/深度映射与缓冲副本，PnR 后报告，不能只拿净bit数除总量代替资源验收。需要新 CDC FIFO 的 Gray 约束及复位审查。

保留现有 REPLY 编码器，另加 PCM 编码器，共用有线 UART 的帧级 arbiter：

1. REPLY 在空闲帧边界优先；一次锁定一个生产者，到它的末尾 C0 被 UART 接收才释放。
2. 不从字节值猜测结束：SLIP 的首尾都是 C0，仲裁应使用显式 last / done。
3. 等 STOP 时，DATA 和 END 仍能排空；仅在 END 末尾 C0 已交付后，才能生成 STOP 成功结果，防止优先级让 ACK 越过 END。
4. cfg_done 不能依赖“PC 收到了 ACK”，也不能依赖 cfg parser 先退出 WAIT_DONE 才允许 PCM 发送，防止环形等待。
5. 录音排空/音频控制 CDC / 编码器背压必须有有限超时和故障出口。建议 STOP 主机超时初值2秒，最终按已验证排空上界设置；不是硬件达标承诺。

会话恢复/有线来源隔离/复位：关闭采集，取消旧录音和尾包，旧 recording_id 永不拼入新 WAV；异步 FIFO 不可仅在一侧随意清指针。通过明确的双域复位握手，或停止写入后丢弃排空再允许新 START。编码器在中帧被中止时，下一次 TX 必须先以 C0 恢复边界。蓝牙故障不取消独立有线录音。

普通有线 UART 无硬件连接状态时，拔线可能无法被 FPGA 观察。首版设置设备自主600秒上限，即使主机消失也有限停止；不能用“10秒没有收到MIDI”判断断线，因为长音和只录音本来就可能无主机帧。更快自动停止需后续定义专用 keepalive/租约，不在此版本凭空推断。

## 7. 上位机结构与 UI

- `protocol.mjs`：新增81解码、大包严格边界、LEN高低字节正确编码，消费者异常与帧校验异常分开处理。
- `serial.mjs`：增加通用帧分发及 CONFIG pending 请求；按连接代际/SEQ/request_type/command匹配 REPLY，超时/断线明确拒绝。MIDI 和控制队列分开，panic 只取消旧 MIDI，不能取消在途录音 STOP。
- 发送 CONFIG 时遵守现有 stop-and-wait：暂停后续 MIDI 发送至最终回复；演奏时钟不回放暂停期间旧事件。START/STOP 的控制屏障导致的走带中断需明确测量；首版建议先录音再播放，需要结束演奏时先正常停止走带再停录音。
- RX PCM 不逐帧写日志或重建 DOM；100ms 合并刷新统计，数据持续消费。Web Serial bufferSize 可提高到64KiB作突发缓冲，不视作可靠投递保证。
- 新 `recorder.mjs`：PcmRecorder、分块PCM缓冲、缺口/重复/完整性、WAV头；避免 JS Number 数组逐样本存储及反复合并整段内存。600秒最大样本数29,296,875，PCM58,593,750B，约55.9MiB；封装复制还需额外内存预算。
- `app.mjs`：idle / arming / recording / stopping；接收器先安装再发 START；非OK不进入正式录音，清理临时数据。录音按钮停止后显示“收尾中”，禁止新录音，得到 END / 有界超时后只封装下载一次。
- 顶部增加独立红色录音按钮和 `REC 00:12 · 1.2 MB · 缺失0`；右侧增加3000000、实际采样率/单声道/完整性指标。无连接禁用；较低波特率拒绝此固定格式。
- 停录默认**仅停止录音回传**，不自动清音、不停止MIDI走带；这是与“停止演奏”分开的操作。若当前 parser 的短暂屏障不足以连续演奏，首版可明确采用“结束演奏并保存”入口，不能在实现里隐藏改变按钮含义。
- 页面隐藏：发 STOP 收尾，界面提示已因后台而停止。断线：立刻保存已收片段并加 incomplete 标记。pagehide 仅尽力发 STOP，不能保证完成下载；需 beforeunload 提示正在录音，恢复页提供已收片段的保存入口时另评估持久化。
- 零数据不下载空文件，提示“未收到音频样本”；START不支持/NOT_READY/BUSY须显示设备结果。录音真实数字波形，与电脑参考试听严格区分。

## 8. WAV 与完成判据

PCM WAV：RIFF/WAVE，fmt chunk16，format=1，channels=1，bits=16，blockAlign=2，sampleRate=round(num/den)=48828，byteRate=97656，dataBytes=N×2，RIFF size=36+dataBytes。整数采样率与真实帧率相差约2.56ppm（0.000256%），600秒约1.536ms；不做插值、不归一化。精确有理采样率和丢样诊断可随录音另存JSON，WAV不假装拥有分数采样率。

完整文件至少需要：有效 START、同一 ID、合法END最终长度、无状态冲突。存在补零可保存且时间轴完整，但必须标“已补静音/有缺口”；无END或异常断开标“不完整”。“停止后已发数据排空”不等于串口点击瞬间停止传输：需允许约FIFO排空时间后才下载，实时显示收尾状态。

## 9. 实施顺序与验收

1. 冻结协议与黄金向量：含LEN>255、header/样本/CRC转义、0样本END、两次录音隔离；保留旧六组向量和旧通信回归。
2. PC先实现协议、CONFIG请求、录音/WAV，以模拟串口注入完整录音、CRC错帧、缺口、重复、跨包重叠、尾部丢失、ACK/END单独丢失、上限、断线。
3. FPGA实现DAC取样抽头、双域控制与FIFO、连续index分包、编码器/仲裁、配置桥和自主上限。独立线端接收器验证每帧不交错，STOP尾包先于ACK，ACK重试不重开录音。
4. 音频对拍：独立解码I2S/PT8211，每个实际锁存L/R下混与回传PCM逐样本一致；覆盖静音、资源加载、欠载/溢出、FIFO满、慢TX、停止边界和中途会话复位。录音开/关对DAC线端序列应相同。
5. 真实3Mbps：长时间持续流 + 0xC0/0xDB最坏转义图样 + 双向MIDI/回复；报告有效吞吐、坏CRC、主机缺口、FIFO最高水位及输入延迟。桥不支持则不宣称可用，另选受测波特率/格式。
6. 整板综合/PnR：资源、50MHz约束、CDC、三时钟域及最小脉宽门禁；实际导出WAV交由独立解析器核对N/格式/时长/样本，播放试听。仿真通过不替代硬件验收。
