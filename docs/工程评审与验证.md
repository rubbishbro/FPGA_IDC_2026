## 1. 评审输入与证据规则

记录HEAD、分支、工作区/暂存差异、工具版本、参数、源清单/约束和评审范围；不要把脏工作区全部归入某个提交。评审当前可交付性、正确性、最坏实时性、覆盖、可解释性和可复现性。

| 证据 | 含义 | 使用边界 |
|---|---|---|
| E0 | 板级测量/签核 | 绑定bitstream、源码、约束、仪器/测量定义 |
| E1 | 当前基线可复现仿真/综合 | 附命令、日志、判据与参数；独立探针不证明整机 |
| E2 | 当前源码静态事实 | 给文件/行、端口、状态或表达式，不能写成已实测 |
| E3 | 历史记录/文档声明 | 标日期/范围，不能升级为当前通过 |
| E4/U | 推断/未验证 | 说明推断和缺少证据，不猜测通过 |

区分已实现已证、已实现未证、部分实现、未实现、实现错误、工具阻塞和文档过期。Python/离线WAV不充当板级音频；进程退出0、非零音频或报告存在都不单独构成正确性证明。

## 2. 评审流程与可复用提示词

以下可作为人类/代理评审任务的统一说明；是否改代码由当前用户任务决定，单纯评审时不修改实现。评审可能生成隔离日志/报告。

1. 固定基线：从真实top/实例/源清单查音频出口、参数/资源来源、实际连接和未接端点。默认参数、实例覆盖和镜像格式一起看。
2. 执行与改动相关的既有验证，命令入口只引用 [sim说明](../sim/README.md)。记录失败、跳过、工具阻塞和未测范围；不伪造测试结论。
3. 静态核对下表，关注会导致错误声音/错误验收的条件；为严重问题提供最小复现或测量方法。
4. 交叉验证模型/量化/RTL、加载器/镜像/RAM、配置/真实消费者、时序报告/top/约束，以及测试实际判据。
5. 输出按严重度排序的问题、证据等级、影响、最小验证/关闭条件和未测范围；再映射赛题项，不重复粘贴整套设计说明。

| 检查域 | 评审重点 |
|---|---|
| 地址/参数 | RAM padding与Flash紧凑表区别、sel/slot/mode、非二次幂、bank偏移、零/满额数量、默认48/64与镜像一致 |
| 算术/模型 | 每核字段Q/符号/sq-sv、反馈/零状态、负数舍入/饱和、乘积完整位宽、满槽峰值、激励口径与golden模式 |
| 握手/事务 | valid背压、最后一笔排空、加载/调制竞争、reload挂起、tag/id匹配、接收与生效、取消/复位 |
| 实时/时序 | 首帧/稳态/切换/满载、实际Fs、供样欠载、探针与整机区分、时钟/IO/例外约束和源码绑定 |
| CDC/存储 | 同步RAM延迟/同址读写、完整快照/所有权、复位释放、延迟RAM有效性及X传播 |
| 输入/业务 | ADC请求/完成/行列、音高归属、踏板/重触发/抢占、物理来源清理/退休和配置屏障死锁 |
| 覆盖/交付 | TB是golden还是统计、有无删除覆盖、真实Flash还是直灌RAM、满幅/故障/多种子、最终DAC及现场证据 |
| 文档 | 专题职责、日期/基线、路径/链接、状态与证据一致；不得用历史PASS覆盖当前失败 |

验证缺口要写明原测试覆盖什么、删除后由谁承接。若做变异验证，用隔离副本和明确授权范围，不能在评审中直接改坏共享源码。

严重度沿用：S0错误结论/静默损坏/致命链路，S1功能或实时性不达标，S2覆盖/复现/文档误导，S3维护/优化。S0/S1必须附最小验证，S2指出具体失实语句或覆盖缺口。

报告模板：

```text
基线与范围：HEAD、工作区、工具/参数/源清单
证据表：入口/结果/日志/等级/未覆盖
问题表：编号/严重度/定位/触发/影响/证据/关闭条件
与上次差异：新问题、源码已改、证据已闭合分别写
验收映射：引用要求项，不另维护完成度总表
未测与下一步：按依赖/风险给出有限行动
```

## 3. 文档职责和变更规则

每个当前主题只设一个主文档，职责表见 [docs索引](README.md)。产品维护用户/功能含义，上位机维护软件/链路可行性，控制维护本地参数/提交/CDC，MIDI维护演奏消费者/协议桥接，模型维护数值合同，验收维护要求→证据，bugs维护问题→关闭条件，本页保存方法和执行记录。

根目录只保留README/CODE_ARCHITECTURE；非docs目录最多两份说明，专题可放任意层级docs内。依赖清单、系数/向量、许可文本不合并，忽略的build/第三方工具分发不当作者文档整理。

合并前保存临时快照，先迁入独有内容并删除重复正文，再移除旧入口；不以“又复制一份到历史目录”替代合并。更新相对链接、锚点、索引和引用标签；真实历史记录保持日期/适用范围，不能升级为现状。

## 5. 2026-10-28 ModelSim／Questa 补测

### 基线与执行前提

HEAD仍为 `8e9d1cda520b9184909bda97853583342d4ae28f`，包含当时工作区；实际二进制为 **Questa Altera Starter FPGA Edition-64 2025.2（May 31 2025）**。当次与前轮快照比较，`.sv/.v` 内容差异为0。补测期间另有文档整理，不能声称全部Git状态未变；本轮没有修改仓库RTL，也没有将隔离测试写回正式回归。

**原版编译仍阻塞。** 用 `run_all.ps1` 的21文件源清单执行 `vlog -sv`，`voice_router.sv` 报14条错误：`CO_SLOT`、`input_hold`、`dead_f`、`state/S_RUN_V`、`inst_prev` 等先使用后声明。为继续评审，只在 `/tmp` 建立兼容副本，前移声明，并将等价的 `CO_SLOT=$clog2(SLOTS)+$clog2(N_MODES)` 放到参数列表；算法、状态转移和RAM读写未改。下面标注“兼容副本”的结果均受此条件限制，**不是仓库原版已能直接运行**。

原音乐TB直接写DUT的 `inst_prev`／RAM，触发Questa的 `always_ff` 多进程驱动诊断7061；采用 `-suppress 7061 -voptargs='-suppress 7061'` 保留原白盒初始化。部分补充夹具也直接初始化参数／状态RAM，使用相同条件。其它错误保留；通过不等于无警告。

整合预算／配置夹具先走全0 Flash的错误填零路径（load_err=1），再检查固定调度与配置状态；这不证明有效音色或Flash读取正确。调制和bank检查另用白盒参数／状态夹具，来源必须与真实镜像区分。

默认音乐TB的CLK_HZ参数为48MHz，但时钟仍为10ns周期，1000拍作为逻辑样本间隔。不能用该TB的绝对仿真时间签核100MHz整机；预算夹具明确使用100MHz／48kHz。音乐输出按48kHz导出且峰值归一化，WAV是RTL仿真试听，不是DAC录音或固定PCM定标证明。

输出另有小幅残留：默认片段末512点均为−35，ALL16末512点均为+35，未严格归零。这里只记录残余直流，尚未判为可闻缺陷；不能把“松键后归零”写成已通过。
