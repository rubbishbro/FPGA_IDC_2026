# 自定义键位与演奏指引（2026-11-03）

## 本次接通的行为

蓝牙或有线收到 `TYPE=02, COMMAND=20, LEN=33` 后，沿用原SLIP、CRC、来源权限和重试缓存。
PAYLOAD为命令20＋按键0..15的16组`[乐器字节, 原始MIDI音符字节]`。
本轮支持16键属于同一种已安装乐器，允许乱序、重复、跨该乐器高低16音组取音。
不支持每键混合不同乐器；越界、混合、未安装资源整表拒绝，结果03，不截断或替换。
目前已安装的六种音色沿用各自32音资源范围；鼓组资源尚未安装，不能因已有枚举而接受。
鼓组后续统一使用GM外部Note号36/38/45/42/59/49，手机表与乐谱发送相同编号；
内部查表才转换为0～5。指引匹配、标签和录制保留GM编号，具体合同见通信协议约定§3.2.2。

处理链路：

    蓝牙UART → SLIP/CRC → CONFIG解析/来源屏障
      → instrument_system整表检查 → midi_voice_top复核并暂存
      → 清理旧声部/指引 → 逐键offset加载Flash → 首帧状态清理
      → 等物理键释放 → 提交音色/键位表/绑定身份 → 回复00

正常使用保留当前演奏来源和自动/引导模式；表内乐器决定音色及其匹配通道。
蓝牙发送配置本身不会把“压力垫演奏”强制切成“蓝牙自动演奏”。
对于第i键，外部匹配表为`slot_note_map[i]=收到的MIDI号`，加载偏移为
`(MIDI号-note_first(乐器)) × N_MODES × 64`。生产N_MODES=64，每音资源步长4096字节。
按键i继续对应声部槽i，复用原loader和演奏入口。上述减起始音公式仅用于旋律乐器；鼓组后续通过GM编号查表得到索引，再乘资源步长。

只有整表成功加载并释放旧按键后，`audio_config_t.custom_keys`才置1。
UI通过后端已提交快照显示“音域 → 键位绑定 → 自定义键位”，指引页右上角也显示同一身份。
`active_values[5]`读取0/1/2分别表示低组/高组/自定义；标量0300仍只允许写0或1。
编辑自定义状态下的默认分组时，草稿从低组开始；取消不改变当前自定义表。
切回默认高/低组、主动选择乐器或切到不同音色会恢复默认绑定；其余同音色配置保留自定义表。
切回默认后若要重新使用自定义表，需手机重发；重启恢复默认低音组，不写Flash持久保存。

参数校验失败不会启动加载。加载失败自动重新装载原已提交音色和键位表，恢复后回复06；
如果旧资源也无法恢复，则静音并进入故障，不伪装成旧表仍可演奏。
CONFIG重复帧重放最终结果，不重复加载；坏CRC帧不更改配置。
按住实体键时会显示“请松手”，不提前成功，不让旧压力触发新绑定。

## 演奏指引的定位

现有指引是实时MIDI提示，不是独立的曲谱播放器、节奏评分器或自动纠错系统。
外部播放器/手机负责何时发送Note On/Off；FPGA显示此刻应按哪些键。
从“输入 → 演奏来源”选择有线MIDI或蓝牙MIDI，再在“演奏方式”选择“引导演奏”。
压力垫来源不允许启用指引；切换来源会退出指引，需在新来源重新开启。

同一份实际生效的`note_map`同时用于：

1. 物理键/声部槽对应的资源加载。
2. MIDI事件到声部的自动演奏匹配。
3. 指引目标匹配、LCD每键音符号与录制音符号。

因此自定义键位切换时，不存在显示沿用默认音符、声音使用新音符的两套映射。

## 事件准入和发声分工

`midi_voice_top`先检查配置运行状态、来源隔离、选中的有线/蓝牙来源及MIDI通道。
不属于当前来源/通道的消息被消费但不点亮目标；配置清理期间旧消息不进入新映射。

    自动演奏：外部MIDI → midi_note_state → voice_router → 音频
    引导演奏：外部MIDI → midi_guide_state → LCD目标提示
               实体压力 → voice_router → 音频，同时反馈LCD实际按下状态

引导模式不会把外部MIDI的Note On送进合成声部。即使同时收到和弦，未按压力键也不发声。
实体压力按键仍使用原力度、激励、包络和引擎路径；MIDI Off、CC64不改变实体键门控。
收到外部清音CC120/123时只清提示，不替用户停止实体演奏。

## 目标状态与颜色

`midi_guide_state`每个有效Note On遍历16键，按外部MIDI号比较，匹配位进入target。
Note Off或零力度Note On清对应target；重复On采用一次Off释放策略，不累计重叠次数。
每次On将匹配键的hold_count设80ms，产生glow，短促MIDI也能看见。
持续target优先于glow，因此长按目标不会80ms后消失。

| LCD状态 | 条件 | 颜色 |
| --- | --- | --- |
| 应按 | target=1，实体未按 | 黄色 |
| 按中 | target=1，任意同音绑定实体键仍按住（matched=1） | 绿色 |
| 已按 | 实体已按，target=0 | 蓝色边框 |
| 余辉 | target=0，80ms保持尚未结束 | 暗黄色 |

同一个音符绑定到多个键时，所有匹配键都提示；按住任意同音键，所有同音目标格均显示绿色“按中”。
这是电平判定，无命中锁存：最后一个同音实体键松开，matched立即清零，尚未结束的MIDI目标恢复黄色；
MIDI目标结束也立即清matched，不伪造实体松键。
`pressed`始终保留真实物理键状态，`matched`是单独的显示字段，绝不用于声音门控、录制或力度。
匹配在core域完成，随目标、真实按下和音符表一起跨时钟发布；目标格的背景/边框/文字使用matched，
非目标格的蓝色“已按”仍使用pressed。
和弦可同时点亮多个键。超出当前16键表的Note On递增outside_count并记录last_outside，LCD显示最近超区音符；
不会近似匹配、自动换音组或修改键位。

## 页面、跨时钟和切换

`lcd_pad_guide`是全屏4×4页面：顶部显示模式、来源、乐器、通道和绑定身份；
每格显示键号、原始MIDI音符号和提示状态，底部显示图例及超区音符。
默认方向为行优先0..15，`guide_cell_slot`是统一方向映射入口，实板方向仍需核对。

`guide_display_t`将生效配置、完整note_map、target/glow/pressed、诊断及revision打包。
`sidebar_system`用独立整体邮箱从core时钟域传到pixel域，只在帧边界更新。
配置/声部切换会清旧target和glow，新音符标签与目标身份一起发布；显示不反压音频。
RGB叠加优先级为侧边栏菜单 → 指引页 → 常规FFT/波形/历史曲线。

切换流程与声音配置共用`C_CLEAN → C_APPLY → C_WAIT → C_DRAIN/C_RELEASE → C_RUN`。
切入引导清掉旧自动MIDI声部归属；切回自动恢复原MIDI消费者。
选中来源断连/隔离时清提示并显示通信异常，但手动压力演奏可继续。
Panic、配置切换和故障会清指引目标；新映射成功前不接受新的有效演奏事件。

## 验证与部署范围

本轮为源码及仿真实现，未综合/PnR、未烧录，手机实机和LCD实板仍需验收。

- 专用键位集成测试（37项检查，含同音按住联动）：乱序/重复/跨组偏移、等待松手、实际PAD发声、指引复用、默认切回、混合/越界拒绝、加载失败回滚。
- 蓝牙端到端：真实串口字节/SLIP/CRC/CONFIG缓存/Flash/UI/PAD，坏CRC和重复帧不重装。

- 修复了旧指引测试夹具的两处假设：小号激励ROM要求48kHz；全零系数不等于loader错误，故障路径使用真实load_err结果注入。

`sim/run_board.py --test keymap`，渲染用`tb_guide_render`。

本轮另外通过了配置快照、录制命令桥接及板级时钟回归；侧边栏和指引渲染均通过。
