# 通信实现

协议唯一依据：[通信协议约定](../../docs/通信协议约定.md)。

```text
UART / HC-05 -> transport_link -> frame_arbiter -> parser_dispatch
                         ^                         | MIDI -> event FIFO
                         |                         | CONFIG -> backend -> final result
                         +--------- reply ---------+
```

- 无 VERSION；TYPE、SEQ、LEN 各 1 字节；PAYLOAD 最大 64 字节。
- CRC16/CCITT-FALSE 覆盖 TYPE/SEQ/LEN/PAYLOAD，低字节先发送；SLIP 转义包含 CRC。
- TYPE 01=MIDI、02=配置、80=配置回复、82=录制事件回传。回复载荷只有 COMMAND/RESULT。
- 序号在线上只有 8 位；内部延用 16 位配置 tag 接口，RX 零扩展，TX 仅发送低 8 位。
- 配置 02=混响、20=16 键整表；EQ 和未列出的旧命令回复 UNSUPPORTED。
- 每来源缓存最近一次完整配置及结果，同 SEQ 同内容只重放，不同内容返回 05。
- CRC/长度/转义错误只丢帧并计数，不执行、不回复，不因单个协议错误清理演奏状态。
- 持续帧接收超时仅用于丢弃不完整候选帧，不是 App 的配置超时重发。
- 配置在提交前无法通过事件屏障或后端准入时回复 04 BUSY。已接受的请求等待真实完成。
- 板级外部混响准入最长约 20 ms，配置分发等待后端最长 20 ms，音频后端事务有 200 ms 上限（混响不会进入等待松键状态）；预留回复发送时间。
- 20 命令完整接收、检查 33 字节长度、所有乐器和 MIDI 字段；板级另检查已部署音符。当前音频后端不支持每键独立乐器，合法整表返回 06，原配置不变，无部分写入、无虚假成功。
- App 的 500 ms 超时及最多三次重发由 App 实现，RTL 不发送重发请求。

v2 codec、transport、构建参数及专用 RTL 用例已删除。当前修改尚未测试、未编译、未上板；历史通信测试向量仍需迁移，旧 PASS 不能作为本协议的验证证据。
