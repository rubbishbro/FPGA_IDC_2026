> **C2 为什么是无符号**：`a2 = r²`，而 `r = exp(−γ/fs)` 且 `γ ≥ 0.02`（参数表里 clip 过），
所以 **`0 < a2 < 1` 恒成立** → 不需要符号位，白省 1 位、精度一点不损。
（`22 + 25 + 26 = 73 = 18×4 + 1`，差 1 位就白扔一整块 BSRAM；改成无符号后 `22+24+26 = 72` 正好。）

## D. 系数从哪来

| 方案 | 做法 | 优 | 劣 |
|---|---|---|---|
| **D-a 离线表** | 离线把 `(a1,a2,G)` 算好存 ROM | 最简、最准、无需片上三角函数 | 占 ROM |
| D-b 片上算 | 存 `(f, γ, amp)`，note_on 时用 CORDIC 算 | ROM 小、天然支持移调 | 要写 CORDIC + 证明精度 |

**状态：已冻结 = D-a**（CORDIC 放到优化阶段）

### 表生成必须对齐的三个陷阱

1. **移调**：`params.py:Patch.modes()` 取最近的采样音，频率按 `f0(midi)/f0(采样)` 缩放，
   并对 `gamma` 乘 `gamma_scale`。表里只放"采样音本身"，一移调就不对。
2. **逐音归一化**：`params.py:modes()` 里的 `w = w / max(w.max(), 1e-12)`。
   ⚠️ 注意 **`_piece_norm` 不是这个**——它在 `drumkit.py`，是鼓件**完整输出**的峰值归一化，
   **不在** `ModalSynth` 的增益路径上，别混为一谈、别重复乘。
3. **`SR` 烘进系数**：`r = exp(−γ/fs)`、`θ = 2πf/fs`。表是 48 kHz 专用，换采样率要重算。

### 验证链（不能跳级）

```
① ModalSynth（浮点，从 f/γ 现算）        ← 已验证的参考
        ↓  表生成脚本要让它复现上一级
② 表驱动的 Python 渲染器（只读 a1,a2,G）
        ↓  这才是 RTL 的对齐目标
③ RTL（必须与 ② 逐位相等）
```

②必须先用 Python 证明"只靠表能还原①"（容差内），否则 RTL 对拍失败时你分不清是表错还是 RTL 错。

### 存储规模（72 位/模态）

* 全表（4 个乐器、250 个音/力度组合）：5483 模态 × 72 位 ≈ **395 kbit**
* 每声部缓存（32 声部 × 48 模态）：1536 × 72 位 ≈ **111 kbit**
  → 138K 的 6120 Kbit 非常宽裕，**容量从来不是问题，端口带宽才是**（见 §E）

## E. 时序与访存预算

```
100 MHz / 48 kHz = 2083 周期/采样
```

| | 数值 |
|---|---|
| 乘法（最坏 32×48 = 1536 模态） | `3 × 1536 = 4608` 次/采样 |
| 访存（打包后每模态 3 次） | `3 × 1536 = 4608` 次/采样 |
| 每周期需要 | **2.2 次访存** → 需 **≥3 路并行** |

| 方案 | 访存/采样 | 端口/周期 |
|---|---|---|
| 全遍历(32×64) + 不打包 | 14336 | 6.9 ❌ |
| 全遍历(32×64) + 打包 | 6144 | 2.95 |
| **只遍历(典型 672) + 打包** | **2016** | **0.97** ✅ |
| 只遍历(最坏 1536) + 打包 | 4608 | 2.2 |

**两个结论**：

* **打包**是把最坏值拉进可行区（14336 → 6144）；
* **只遍历**是把典型值拉到"一个端口就够"（6144 → 2016），但**不改善最坏值**。

**注意：IIR 的递归只在*时间*维度上不可并行，在*模态/声部*维度上完全可并行或时分复用。**

## F. 架构

| # | 事项 | 结论 | 状态 |
|---|---|---|---|
| F1 | 时钟域 | 核心 **100 MHz + `sample_en`**；**I2S 独立域**（BCLK/LRCLK）+ 异步 FIFO | **已冻结** |
| F2 | 遍历 | **只遍历活跃模态**：每声部一个 `n_modes` 计数器，遍历 `0..n-1`；**不用链表** | **已冻结** |
| F3 | 并行度 | **4 路**（每路 1 乘法器 + 1 存储端口）；3 路是下限 | **已冻结** |
| F4 | 跳过零输入乘法 | A/C 类可跳（脉冲只有 7~12 个采样）；**B 类不可跳** | **已冻结** |
| F5 | 验证链 | 浮点参考 → **Python 整数模型** → RTL **逐位相等** | **已冻结** |

### ⚠️ 两条容易搞错的关键限制

**F1**：**核心绝对不能跑 48 kHz。** 时分复用的前提是"每采样有多个时钟周期"；
若核心时钟就是 48 kHz，每采样只有 1 个周期，就要求 4608 个乘法器全并行。
真正需要独立时钟域的是 **I2S 输出侧**（BCLK 必须与音频时钟严格同步），不是核心。

**F2**：**"只遍历"省的是平均值，不省最坏值。** 32 个声部全忙时活跃模态就是 1536，
和最坏情况一样——所以端口数必须按最坏情况定（这就是 F3 要 3~4 路的原因）。

### F4 的细节

| 类 | 激励 | 能否跳过输入乘法 |
|---|---|---|
| A（拨/击） | 7~12 采样脉冲 | ✅ 能 |
| B（持续音） | **逐采样持续驱动** | ❌ **不能** |
| C（打击乐） | 短噪声 burst | ✅ 能 |

→ 乘法预算按 **3 次/模态** 算（不是 2 次）；建议把旁路做成**可配置**的，别硬编码。

## H. 位宽依据（扫全表实测）

### 系数小数位

实测四张参数表（`γ` 已过 `clip(0.02, 400)`）：

| 乐器 | 最慢的 γ | `1−a2 = 2γ/fs` | T60 |
|---|---|---|---|
| guitar | 0.2590 | 1.079e-05 | 26.7 s |
| **piano** | **0.1226** | **5.108e-06** | **56.3 s** |
| banjo | 0.3466 | 1.444e-05 | 19.9 s |
| mandolin | 0.5418 | 2.258e-05 | 12.7 s |

| 小数位 F | 半 LSB | 最坏衰减率误差（piano 最慢模态） |
|---|---|---|
| 20 | 4.77e-7 | **9.34%** |
| 22 | 1.19e-7 | 2.33% |
| **24** | 2.98e-8 | **0.58%** ✅ |

**关键认知**：决定衰减精度的不是 `1−r`，而是 **`1−a2 = 2(1−r)`（正好两倍）**，
因为 ROM 里存的是 `a2` 而不是 `r`。另外 **`a1` 的量化只影响频率**（`|z| = √a2` 只要根保持共轭），
所以 `a1` 只需要 20 位小数（f=55 Hz 时频率误差 0.38%）。

**全表复核（5483 条模态，`fixed_point_check` / 一次性扫描）**：量化后 **0 条模态的根翻成实数**，
`|z| = √a2` 处处成立，即 a1 只影响频率、不影响衰减。除 piano 最低的 9 条模态外全部 **< 5 cent**；
最大 **21.6 cent** 出现在 MIDI 24 / 32.7 Hz 的基频（∝1/f²，泛音误差远小，且低音基频弱、被掩蔽）。
→ **维持 `a1` Q2.20 与 72 位打包（C1/C4 不变）。**

### `G` 的格式

| | 值 |
|---|---|
| 全表范围 | **1.68e-6 ~ 1.577** |
| max/min | **940354（6.0 个数量级）** |
| 1% / 50% / 99% 分位 | 9.3e-5 / 3.0e-3 / 0.188 |

→ `G_max > 1`，**`Q1.F` 不够，必须 `Q2.F`**；好消息是**不需要浮点/指数**，`Q2.24` 够用
（最小那条 G 的相对分辨率 1.78%，而那是 1% 分位的极弱模态）。

### 状态位宽（含固定点平台 / 极限环）

| | 值 |
|---|---|
| 单模态状态最大 `\|y1\|` | **0.9994** |
| `Q2.F`（±2）余量 | 有 → 2 个整数位足够 |
| 单声部求和最大 `\|sum\|` | **6.31** → 混音/输出至少 3 个整数位 |

**为什么状态是 FS=30 而不是 24（关键）**：直接型递推存在一个**非零固定点**

$$
c_{\max}=\frac{2^{23}}{1+a_1+a_2}\quad(\text{状态码})
$$

每拍应减小 `(1+a1+a2)·c`，但小于半个 LSB 时被舍入抹掉，状态映射回自己、永久不变。
这与"量化极点稳定"是两件事；**只做 RTL↔② 逐位对拍发现不了**，必须用行为判据。

- 最坏模式 = piano MIDI21 基频，`D=(1+a1+a2)·2²⁴=213`。
- `c_max = 2²³/213 = 39383` 码（与 FS 无关），**real = c_max / 2^FS**：

| FS | 平台电平 | dBFS | 声部回收 |
|---:|---:|---:|---|
| 24 | 2.35e-3 | −52.6 | **永不**（高于 `free_thr`） |
| 28 | 1.47e-4 | −76.7 | 20.0 s（余量仅 1.36×） |
| **30** | **3.67e-5** | **−88.7** | **20.6 s（余量 5.4×）** |

→ **C5 取 FS=30**：平台稳在 `free_thr`(−74 dB) 之下，声部正常回收；回收时刻与 FS=24/32 一致，
说明加宽**不改变正常尾部**，只去掉卡死。全表 5483 条模态平台均 < `free_thr`（实测见
`python/modal_sim/limit_cycle_check.py`）。
