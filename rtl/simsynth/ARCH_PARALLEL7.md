# 架构：7 乘法器并联引擎 + 多槽声部层（最终方案 A）

> 起因：逐字段定 Q（每个字段一个编译期移位）在**单乘法器**的 TDM 里做不到 —— 移位量还是要由
> 运行时的 `k` 选出来。把 7 个乘积**并联**，每个字段的移位就成了编译期常量（连线），
> 关键路径只剩 `乘 → 常数舍入 → 累加`。7 个乘法器的成本由 8 个声部分摊。

## 1. 结构

```
            ┌───────────── modal_voice_top（存储 + 声部调度）──────────────┐
            │  系数块  SLOTS 槽 × N 模态 × 7 字段      引擎读 / 顶层写     │
            │  状态块  SLOTS 槽 × N 模态 × (q, q̇)      引擎读 + 引擎写     │
            │  激励块  SLOTS 槽 × 块长                 引擎读 / 顶层写     │
            │  结果    1 × 块长（每帧各声部求和）       引擎给流 / 顶层写   │
            └───────────────────────────┬─────────────────────────────────┘
                                        │  {槽号, 偏移}
                        ┌───────────────┴────────────────┐
                        │  modal_engine7（只算，不存）    │
                        │  a11·q a12·q̇ gq·x │ a21·q a22·q̇ gv·x │ wo·q │
                        │        qn / vn / y（三个累加器）        │
                        └────────────────────────────────┘
```

- 引擎对外只有 `start / st_zero / n_modes / done / busy` 和 5 组 SRAM 式端口，
  地址都是**本声部内的偏移**；`{槽号, 偏移}` 的拼接全在顶层。
- 引擎不知道有几个声部、也不知道自己在读写哪一块存储。

## 2. 五级流水（吞吐 1 模态/拍）

| 级 | 内容 | 序号（`ri` = 读指针） |
|---|---|---|
| R | 给系数/状态读地址（同步 RAM） | `ri` |
| M | 7 个 32×32 乘法 → `p_*` | `ri−1` |
| N | `(p + 2^(SH−1)) >>> SH` → `t_*` | `ri−2` |
| S | 三路相加 → `qn_q/vn_q`（`t_wo` 也过一级） | `ri−3` |
| W | 饱和 → 写回状态；`y_acc += two_q` | `ri−4` |

一帧 = `1 + 1 + (N+4) + 1 + 1 = N + 8` 拍；N=48 时 **56 拍**（`modal_bank_ram` 是 530 拍），
8 声部 + 声部切换 ≈ 480 拍/采样 = 48 kHz/100 MHz 预算（2083）的 23%。

**为什么必须切五级**：第一版把 M/N/S/W 压在一拍，PnR 实测最差路径 **16.0 ns（64 MHz）**，
一条路径穿过 乘法 → 64 位舍入加 → 常数移位 → 三路 64 位加 → 饱和 → RAM 写口。

## 3. 存储与声部（最终形态）

- **单份状态块**（1R1W）：引擎独占，原地更新（读 `ri`、写 `ri−4`，相差 4 拍，不会同址冲突）。
- **note-on 清零**用引擎内的 `st_zero` 清零 pass（N 拍，一次性），所以顶层**不需要写状态**，
  也就不需要 ping-pong / 双口 / 搬运。`st_zero_mask` 指定哪些槽是新音符。
- **换音色**：顶层停机（不启动作业）后整块刷系数块即可。
- **结果**：引擎给 `y_valid/y_data` 流（每帧一个 Σ wo·q），顶层每帧把各声部求和后写进
  "每采样一个"的输出缓冲，直接接腔体滤波/输出。

## 4. 存储核算（每模态 288 位 = 36 字节）

| | 吉他 32 声部 ×1 弦 ×20 模态 = 640 | 钢琴 32 声部 ×2 弦 ×40 模态 = 2560 |
|---|---|---|
| 系数（7×32 位） | 640 × 28 B = 17.5 KiB | 70 KiB |
| 状态（2×32 位） | 640 × 8 B = 5 KiB | 20 KiB |
| 合计 | **22.5 KiB**（≈28 块 BSRAM） | **90 KiB**（≈111 块） |

按 16 键 + 2 预装槽：吉他 ≈23 块、钢琴 ≈72 块（含激励缓冲）。详见 [RESOURCE_BUDGET.md](RESOURCE_BUDGET.md)。

## 5. 实测（GW5AST-138，100 MHz 约束，`fmax_e7` 探针）

探针配置：`N_MODES=48`、`X_DEPTH=64`、`SLOTS=8`（8 声部）、`DEBUG_PORT=0`。

| 项 | 结果 |
|---|---|
| Logic | **1495** |
| Register | **842** |
| BSRAM | **24 / 340** |
| DSP | 28（14 × `MULT27X36`） |
| 每声部摊薄 | 187 / 105 / 3 块 / 1.75 个 `MULT27X36` |
| 每采样拍数（8 声部 × 48 模态） | 8 × (56+4) ≈ **480** = 预算 23% |
| **PnR Fmax** | **115.0 MHz**（slack +1.307 ns，收敛） |
| 关键路径 | BSRAM 读出 → 乘法器输入，约 8.7 ns |

## 6. 与其它两种实现的对比（同器件、同流程、同约束）

| 指标 | `modal_bank_ram` × 8（每声部一个 bank） | **7 乘法器引擎 × 1（最终方案）** |
|---|---|---|
| Logic | 13104 | **1495**（8.8× 少） |
| Register | 6129 | **842**（7.3× 少） |
| BSRAM | 192（56%） | **24**（7%） |
| DSP | 32（16 × MULT27X36） | **28**（14） |
| 每采样拍数 | 530 | **480** |
| Fmax | 74.8 MHz（未收敛） | **115.0 MHz**（收敛） |

**为什么差这么多**：`modal_bank_ram` 一个 bank 只有 48 个模态，存储和引擎绑死，多一个声部就多
一整套地址/流水和 24 块 BSRAM；而且它的 7 个乘积靠一个乘法器轮转，移位量是运行量，
桶形移位器留在关键路径上（13.4 ns）。

另有一版"固定角色 A/B + 激励搬到顶层"的实验实现（`modal_voice_top_ab`，见
[RESOURCE_BUDGET.md](RESOURCE_BUDGET.md) 第 6 节）：DSP 同样是 14 个（乘法总数不变，只是换了位置），
但要多一份状态、多一套搬运 FSM，Fmax 只有 64 MHz（顶层把 `term()` 压在一拍里）⇒ **不采用**。

## 7. 验证（`local/run_xsim_engine7.ps1`）

7 个作业、0 失配：

1. 4 条黄金向量（钢琴/吉他 × 单帧/48 帧）逐位对拍 `modal_bank_ram`；
2. 一次 start 跑 2 个槽，结果各归各位；
3. 运行中装载（引擎跑槽 0 时把另一组系数装进槽 1，`busy` 仍为 1，槽 0 结果不受影响）；
4. 停机换音色重刷（两槽整块换掉再跑，与单独跑一致）。

## 8. 踩过的坑

- `coeff_t` 结构体阵列（224 位一个字）Gowin 不认 ⇒ 系数按字段拆成 7 个 32 位阵列，否则退回 FF；
- 探针把 7 个系数写成同一个值会被 CSE 合并（7 个乘法只剩 3 个），Fmax 不可信；
- 每声部每帧一个作业时，`x/y` 的帧号必须由顶层补进地址，否则每帧都读写第 0 个采样；
- `st_zero` 只能在"该声部首帧"置位，否则每帧都会把状态清掉。
