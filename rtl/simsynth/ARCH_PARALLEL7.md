# 架构方案：7 乘法器并联 + 声部/模态两级时分复用

> 起因：逐字段定 Q（每个字段一个编译期移位）在**单乘法器**的 TDM 里做不到 ——
> 移位量还是要由运行时的 `k` 选 ✗。但只要把 7 个乘积**并联**，每个字段的移位就真的是常量，
> 关键路径只剩 `乘 → 常数舍入 → 累加`。
> 而 7 个乘法器如果只服务一个声部就太贵 ⇒ 让它们**同时服务多个声部**。

## 1. 结构

```
                 ┌─ 系数 RAM（每声部 48 模态 × 7 字段 × 32 位）──┐
   voice/mode ──►│  状态 RAM（每声部 48 模态 × 64 位）            │
   地址发生器    └─ 激励/结果 RAM（每声部 1 个/采样）              ┘
                          │
          ┌───────────────┴───────────────┐
          │   7 个乘法器（每字段一个）      │  ← 移位/舍入偏置全是编译期常量
          │   a11·q  a12·v  gq·x | a21·q a22·v gv·x | wo·q
          └───────────────┬───────────────┘
                 3 个累加器（qn / vn / y）
                          │
                    写回状态 + y 累加
```

- 一个模态的 7 个乘积**一拍算完**（流水线化后 2 拍一个模态）；
- 声部之间只换"系数/状态基地址"⇒ **跨声部复用不需要任何额外数据通路**，正是 RAM 式的优势；
- 每个声部的 `y` 累加后写进结果 RAM，顶层按声部求和/移位成音频。

## 2. 周期预算（16 声部，48 kHz，100 MHz）

| 项 | 数值 |
|---|---|
| 每采样可用拍数 | 2083 |
| 模态总数/采样（16 × 48） | **768** |
| 允许每模态拍数 | **2.71** |
| 实现：读址与计算重叠 ⇒ 2 拍/模态 | 1536 拍 = **74% 预算** ✓ |
| 若一个引擎带 8 声部（2 个引擎） | 384 模态 × 2 = 768 拍 = 37% ✓ 很宽松 |

## 3. 资源估算（与现在的"每声部一个 bank"对比）

| 项 | 现在（每声部 1 个 TDM bank ×16） | **7 乘法器引擎 ×1（带 16 声部）** |
|---|---|---|
| 乘法器 | 16 × 1 = 16（32 DSP）| **7（14 DSP）** ✓ |
| 逻辑 | 16 × ~1.7k ≈ **27k** | ~850（乘加树）+ 地址/调度 ≈ **3–4k** ✓ |
| 寄存器 | 16 × 381 ≈ 6.1k | ~1.5k ✓ |
| BSRAM | 16 × 2 = 32 | 系数 172 kbit + 状态 49 kbit + 激励/结果 ≈ **15–20 块** ✓ |
| 关键路径 | 乘 → 64 位舍入 → **6 级桶形移位** → 累加 | 乘 → **常数舍入** → 常数移位（连线）→ 累加 ✓ |
| 每模态拍数 | 11 | 2 ✓ |
| 逐字段 Q | 移位仍是运行量 ✗ | **移位是常量** ✓✓ |

> DSP 数按实测：32 位 × 32 位 = 2 个 `MULT27X36`（27×36 粒度），所以 7 字段 = 14 个，
> 与声部数无关。器件共 298 个 ⇒ 用掉 4.7%。

## 4. 为什么它能顺手解决 100 MHz

现在两个顶层的关键路径都是 **LUT → `term_q`**（13.1 / 13.9 ns），也就是"乘 → 64 位舍入 → 6 级
桶形移位"这一段。并联后：

- 移位变成**连线**（常量移位不产生逻辑）；
- 舍入变成"加一个常数"（不进桶形移位器）；
- 7 个累加器各自是 64 位加法，且互相独立，可以分散到不同 LUT/DSP 附近。

⇒ 路径预计 2–3 级加法，**远超 100 MHz**（具体数要 PnR 才能给）。

## 5. 验证策略（关键：可以完全复用现有黄金向量）

新引擎必须与 `modal_bank_ram` **逐位相同**：

1. 单声部、单作业、`n_samples` 帧 → 用现有 `golden_seq_*.txt` 对拍（4 作业、0 失配基线已有）；
2. 多声部：把同一组系数/状态装进第 1..K 个声部槽、其余槽装零，跑一帧，
   每个槽的结果必须与"单声部跑一次的该声部结果"一致 ✓（零声部应输出 0、状态不变）；
3. 声部交错（不同声部不同模态数、不同采样数）时，结果仍要按声部对齐；
4. 饱和与 `y_sum` 的 64 位累加边界沿用现有约束。

## 6. 实施顺序（每步可验证）

1. **单声部版**：7 乘法器 + 常量移位/舍入 + 2 拍/模态 → 用现有黄金向量逐位对拍 → 综合/PnR 拿 Fmax；
2. **加声部维**：地址发生器加 `voice` 循环（系数/状态/激励/结果各加一段地址空间）；
3. **多声部测试**（第 5 节的第 2、3 条）；
4. README 写入四组数字（资源/周期/Fmax/精度）。

## 7. 遗留决定

- 每引擎带几个声部：16 声部单引擎是 74% 预算，**建议 8 声部/引擎 × 2 引擎**（37%，留一倍余量，
  且便于将来扩到 32 声部）；
- 是否保留"每声部一个 `y` 累加"还是要跨声部求和后统一移位（现在 `y_sum` 是 per-bank 的）。
