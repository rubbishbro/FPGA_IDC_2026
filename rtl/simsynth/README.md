# rtl/simsynth —— 弦模态递推的定点 RTL（最终方案）

物理模型合成：每个音被分解成若干模态，每个模态按二阶递推走一步。
本目录是它的硬件实现，**逐位等于 Python 黄金向量**，并且能在 GW5AST-138 上收敛到 100 MHz 以上。

```
q' = a11·q + a12·q̇ + gq·x
q̇' = a21·q + a22·q̇ + gv·x
y  = wo·q            （用更新前的 q）
```

## 定点格式（逐字段 Q + 32 位尾数）

| 字段 | Q（小数位） |
|---|---|
| `a11` / `a22` | 28 |
| `a12` | 30 |
| `a21` | 23 |
| `gq` | 31 |
| `gv` | 27 |
| `wo` | 15 |

- 常量 = `mant · 2^-Q`，`mant` 是 32 位有符号；**移位量不进记录**（编译期常量），
  所以一个模态只要 `7×32 + 2×32 = 288 位 = 36 字节`（系数 28 B + 状态 8 B）。
- 乘积规则：`(a·m + 2^(Q-1)) >>> Q`，**逐项舍入**后再相加（加法顺序无关，所以流水线可以晚几拍累加）。
- 状态写回前饱和到 32 位；`y_sum` 不饱和。
- 精度：极点半径误差 max 5.2e-10（旧的"24 位尾数 + 每条目移位"是 4.0e-08，差 78 倍）。

## 架构

### 引擎 `modal_engine7`（只算，不存）

7 个乘法器**并联**，每个字段的移位是编译期常量（`>>> SH_A11` 退化成连线），
关键路径里没有桶形移位器。五级流水，吞吐 1 模态/拍：

| 级 | 内容 | 序号（`ri` = 读指针） |
|---|---|---|
| R | 给系数/状态读地址（同步 RAM） | `ri` |
| M | 7 个 32×32 乘法 → `p_*` | `ri−1` |
| N | `(p + 2^(Q−1)) >>> Q` → `t_*` | `ri−2` |
| S | 三路相加 → `qn_q/vn_q`（`t_wo` 也过一级） | `ri−3` |
| W | 饱和 → 写回状态；`y_acc += two_q` | `ri−4` |

- **一次 `start` = 递推一个采样**；`y_valid` 那一拍既给结果（本采样全部模态的 `Σ wo·q`），
  也标志作业结束。时间维的循环交给声部层。
- 控制面：`start / st_zero / n_modes / y_valid`；数据面：5 组 SRAM 式端口
  （系数读、状态读、状态写、激励读、结果流）。地址都是**本声部内的偏移**。
- `st_zero=1` 时先跑一个 N 拍的清零 pass（note-on 用），所以顶层不需要写状态。

### 声部层 `modal_voice_top`（持有全部存储）

| 存储 | 端口 | 说明 |
|---|---|---|
| 系数块 SLOTS × N × 7 字段 | 1R1W | 引擎读、**顶层写**（换音色整块刷） |
| 状态块 SLOTS × N × (q,q̇) | 1R1W | **引擎独占**，原地更新（读 `ri`、写 `ri−4`，不撞） |
| 激励块 SLOTS × 块长 | 1R1W | 引擎读、顶层写 |
| 结果 1 × 块长 | 1R1W | 引擎给流，顶层每帧把各声部求和后写入 |

- 地址 = `{槽号, 偏移}`，换声部只是换地址；引擎不知道有几个声部。
- **没有 ping-pong / 双口 / 搬运**：顶层不写状态 ⇒ 状态块只有一个主人。
- 调度：外层采样、内层声部，每个（采样 × 声部）一个作业。
- 结果按采样求和后就是一个 64 位流，直接接腔体滤波/输出。

## 周期与存储

一帧（= 一个采样，一个声部）= `1 + 1 + (N+4) + 1 + 1 = N + 8` 拍，加约 4 拍作业切换。
48 kHz / 100 MHz ⇒ 每采样 2083 拍。

| 场景 | 每声部/采样 | 声部数 | 占用 |
|---|---|---|---|
| 吉他 20 模态 | 32 拍 | 16 | 512 拍（25%） |
| 钢琴 80 模态（2 弦×40） | 92 拍 | 16 | 1472 拍（71%） |
| 钢琴 80 模态 | 92 拍 | 32 | 2944 拍（需 2 个引擎） |

存储（每模态 36 B）：

| | 模态数 | 系数+状态 | BSRAM |
|---|---|---|---|
| 吉他 32 声部 ×1 弦 ×20 | 640 | 22.5 KiB | ≈28 块 |
| 钢琴 32 声部 ×2 弦 ×40 | 2560 | 90 KiB | ≈111 块 |
| 钢琴 16 键 + 2 预装槽（80 模态/声部） | 1440 | 50.7 KiB | ≈62 块 |

## 揉弦与按弦（变调）

模型里这两个演奏手法就是两个**无量纲比值**（`sim_guitar.py` 的 `length_r` / `tension_r`，
语义是 current/default，范围 0.9~1.1），它们只影响频率和输出增益，不碰阻尼：

| 派生量 | 公式 | 说明 |
|---|---|---|
| 频率平方比 | `k = tr / lr²` | 全体模态共享，等价于 `f ∝ √T / L`（弦振动标准结果） |
| 输出增益 | `g = lr / tr` | 模型里 `sum_weight ∝ lr/tr`，**变调同时改音量** |
| 模态频率平方 | `un = k·Ωn²`，`Ωn² = (2π·f0·n)²` | |
| 旋转角 | `θn = √k · θn0`，`θn0 = Ωn·Δt` | 因为 `γ²≪ω²`（我们参数下 `γ²/ω²`≈1e-5，折合 0.02 音分），`wd ≈ √un` |
| 旋转/衰减系数 | `c=cos θn`，`s=sin θn`，`d=exp(−γnΔt)` | `d` 每模态常数，不用实时算 |

由此每次更新要重算的系数（每模态）：

```
ec = d·c,   es = d·s
a11 = ec + es·γn·Δt/θn
a12 = es·Δt/θn            ← 需要 sinc(θ) = sinθ/θ
a21 = −es·θn/Δt
a22 = ec − es·γn·Δt/θn
wo  = wo0 · g
```

### 文献结论（Stilson & Van Duyne, ICMC 1998）

那篇 `_analysis/ref/bbp2372.1998.282.pdf` 讲的就是这件事。核心结论：

1. 余弦型谐振器（模态合成）的调音系数是 `c = cos θ`，频率比 `α` 对应的理想系数是 `cos(αθ)`；
   他们给出近似 **`cos(αθ) ≈ 1 + α²·(cos θ − 1)`**，即对 `d = c − 1` 乘 `α²`。
   该式在 **四阶**才首次偏离，且 `θ` 越小越准（低频/低模态），`α → 1` 时最准。
2. 多模态系统里 `α²` 对所有模态共享 ⇒ **每模态只要一次乘加**，`α²` 每次更新算一次。
3. 他们明确警告：**时变高 Q 滤波器可能不稳定**（即使每个中间状态稳态都稳定）⇒
   要加**状态钳位**；`c` 靠近 ±1 时 `|c̃|` 可能 >1 ⇒ 还要**系数钳位**。
4. 谐波列在大偏差时会变**非谐和**（我们所有模态正好是 `n·f0` 的谐波列）⇒ 小偏差（揉弦）没问题，
   大偏差（按弦）要用精确值。

### 套到我们的四个系数上

令 `ε = α² − 1`，`e1 ≡ d·(c − 1)`（每模态常数，note-on 时算好），`g = lr/tr`：

```
a11' = a11 + ε·e1        ┐ 共用同一个乘积 ε·e1
a22' = a22 + ε·e1        ┘
a21' = a21 + ε·a21       （因为 a21 ∝ ω²，正好乘 α²）
a12' = a12               （a12 ∝ sinθ/wd，两个 α 抵消，不变）
wo'  = wo · g
```

所以引擎里只需多 **3 个乘法器**（`ε·e1`、`ε·a21`、`wo·g`）+ 一个标量 `ε`、一个标量 `g`，
每模态多 2 次乘加 —— **不需要 CORDIC、不需要重算、不需要系数双缓冲**。

### 方案取舍（结论：外部 CORDIC 重算，引擎接口不变）

我们**不改引擎接口**，系数由外部重算后写回系数块。三条路的对比（论文的"引擎内调制"已否决，
理由是要往引擎里加乘法和 `e1` 字段，破坏接口一致性）：

| 方案 | 每模态代价 | 额外资源 | 精度 | 决定 |
|---|---|---|---|---|
| **外部 CORDIC 重算** | ~72 拍（`polar2cart` + `inv`） | 0 存储（见下） | 精确 | ✅ **采用** |
| 引擎内调制（`a += ε·e1`） | 2 乘 3 加 | +3 乘法器、+1 字段 | 揉弦 ≤1 音分，大偏差不行 | ❌ 破坏接口 |
| 一阶线性化（`c0 − s0·Δθ`） | 2 乘 2 加 | +`θ0` 字段 | ~0.2 音分 | 后备 |

**统一处理**：按弦和揉弦走同一条路径 —— 都是"改 `k`、重算系数"，区别只是按弦在 note-on 算一次、
揉弦每 ~2–3 ms 算一轮。

### 存储：不需要第二套系数表

重算需要的名义信息可以**现算**，不必保留原始系数：

| 量 | 来源 |
|---|---|
| `θ0 = 2π·f0·n·Δt` | `f0`（每声部一个寄存器）× `n`（计数器）× 常数 |
| `√k` | 每次更新算一次，全模态共享 |
| `θ = √k·θ0` | 一次乘法 |
| `d = e^{−γΔt} ≈ 1 − γ·Δt` | `γΔt ≤ 4e-5`（我们的 γ ≤ 2 s⁻¹），误差 6e-10，**不需要 exp 单元** |
| `γ` | **需要存**：每模态一个 32 位字段（第 8 个数组，引擎看不到） |

所以只多 **一个 `γ` 数组**：16 声部 × 80 模态 × 4 B = **5 KiB ≈ 7 块 BSRAM**（相对系数块 ~40 块，+17%）。

- `coeff_t`（引擎看到的 7 个字段）**不变** ⇒ 黄金向量不用重生成；
- `wo` 不参与重算：模型里 `wo ∝ lr/tr = g`，路由器的**输出累加那一级乘一次** `g` 即可
  （每声部每采样 1 次乘法，可忽略），这样重算单元不必知道 `wo0`；
- 重算写回的是 `a11 / a12 / a21 / a22`（4 个字段），每声部 80×4 = 320 拍。

### 稳定性

按论文的警告，两处钳位都要有：

- **状态钳位**：引擎写回前已经有 32 位饱和 ✅；
- **系数钳位**：`a11/a22` 落在 `[−1, 1]` 之外时钳住（`|a21|` 同理按稳态界），防止时变时发散。

### 调度

如果走"低速率重算"，系数块 1R1W 够用：引擎读第 v 个声部时重算单元写第 v′ 个（560 拍/声部，
排在空闲周期里，一轮 16 声部 ≈ 8960 拍）。若走**引擎内调制**，这一块全省掉。

## 踩过的坑

1. **`coeff_t` 结构体阵列不进 BSRAM**：224 位一个字的阵列 Gowin 不认，会退回 FF
   （48 模态 = 10752 个寄存器，比整条数据通路还贵）。**系数按字段拆成 7 个 32 位阵列**才行。
2. **7 个系数写成同一个值会被 CSE 合并**：探针里 `co_data <= {7{lfsr}}` 会让综合器把 7 个乘法
   当成公共子表达式，只留 3 个（`MULT27X36` 从 14 掉到 6），量出来的 Fmax 不可信。
3. **每声部每帧一个作业时，`x` 的帧号必须由顶层补进地址**，否则每帧都读写第 0 个采样。
4. **`st_zero` 只能在"该声部首帧"置位**，否则每帧都会把状态清掉。
5. **SV 乘法宽度**：`a * m` 的结果宽度是操作数最大宽度，32 位相乘只剩 32 位 —— 必须先符号扩展。
6. **同步 RAM 的数据晚一拍**：读过地址后不能再用组合值，否则整体错位一个模态。
7. **多驱动**：`pend` 这类"谁都能置位"的信号必须单一所有者，否则仿真和综合都会踩坑
   （AB 实验版就是在这儿翻的车）。


## 与 rtl/math 的关系

`modal_step_pkg` 的饱和直接调用 `rtl/math/pkg/fxp_pkg.sv` 的 `fx_sat`；
舍入右移是包内联实现的（语义与 `fx_shift_rnd` 逐位一致，但不吃 `int` 形参，
避免把 6 位移位量拓宽成 32 位桶形移位器——实测 Fmax 差 13%）。
等价性由 `rtl/math/tb/tb_fp_ops.sv` 证明（9680 项检查）。两套定点约定的差异见
[FORMAT_ALIGNMENT.md](FORMAT_ALIGNMENT.md)。
