# rtl/simsynth —— 弦模态递推的定点 RTL（最终方案）

物理模型合成：每个音被分解成若干模态，每个模态按二阶递推走一步。
本目录是它的硬件实现，**逐位等于 Python 黄金向量**，并且能在 GW5AST-138 上收敛到 100 MHz 以上。

```
q' = a11·q + a12·q̇ + gq·x
q̇' = a21·q + a22·q̇ + gv·x
y  = wo·q            （用更新前的 q）
```

## 定点格式（逐字段 Q + 32 位尾数）

| 字段 | Q（小数位） |
|---|---|
| `a11` / `a22` | 28 |
| `a12` | 30 |
| `a21` | 23 |
| `gq` | 31 |
| `gv` | 27 |
| `wo` | 15 |

- 常量 = `mant · 2^-Q`，`mant` 是 32 位有符号；**移位量不进记录**（编译期常量），
  所以一个模态只要 `7×32 + 2×32 = 288 位 = 36 字节`（系数 28 B + 状态 8 B）。
- 乘积规则：`(a·m + 2^(Q-1)) >>> Q`，**逐项舍入**后再相加（加法顺序无关，所以流水线可以晚几拍累加）。
- 状态写回前饱和到 32 位；`y_sum` 不饱和。
- 精度：极点半径误差 max 5.2e-10（旧的"24 位尾数 + 每条目移位"是 4.0e-08，差 78 倍）。

## 架构

### 引擎 `modal_engine7`（只算，不存）

7 个乘法器**并联**，每个字段的移位是编译期常量（`>>> SH_A11` 退化成连线），
关键路径里没有桶形移位器。五级流水，吞吐 1 模态/拍：

| 级 | 内容 | 序号（`ri` = 读指针） |
|---|---|---|
| R | 给系数/状态读地址（同步 RAM） | `ri` |
| M | 7 个 32×32 乘法 → `p_*` | `ri−1` |
| N | `(p + 2^(Q−1)) >>> Q` → `t_*` | `ri−2` |
| S | 三路相加 → `qn_q/vn_q`（`t_wo` 也过一级） | `ri−3` |
| W | 饱和 → 写回状态；`y_acc += two_q` | `ri−4` |

- **一次 `start` = 递推一个采样**；`y_valid` 那一拍既给结果（本采样全部模态的 `Σ wo·q`），
  也标志作业结束。时间维的循环交给声部层。
- 控制面：`start / st_zero / n_modes / y_valid`；数据面：5 组 SRAM 式端口
  （系数读、状态读、状态写、激励读、结果流）。地址都是**本声部内的偏移**。
- `st_zero=1` 时先跑一个 N 拍的清零 pass（note-on 用），所以顶层不需要写状态。

### 声部层 `modal_voice_top`（持有全部存储）

| 存储 | 端口 | 说明 |
|---|---|---|
| 系数块 SLOTS × N × 7 字段 | 1R1W | 引擎读、**顶层写**（换音色整块刷） |
| 状态块 SLOTS × N × (q,q̇) | 1R1W | **引擎独占**，原地更新（读 `ri`、写 `ri−4`，不撞） |
| 激励块 SLOTS × 块长 | 1R1W | 引擎读、顶层写 |
| 结果 1 × 块长 | 1R1W | 引擎给流，顶层每帧把各声部求和后写入 |

- 地址 = `{槽号, 偏移}`，换声部只是换地址；引擎不知道有几个声部。
- **没有 ping-pong / 双口 / 搬运**：顶层不写状态 ⇒ 状态块只有一个主人。
- 调度：外层采样、内层声部，每个（采样 × 声部）一个作业。
- 结果按采样求和后就是一个 64 位流，直接接腔体滤波/输出。

## 周期与存储

一帧（= 一个采样，一个声部）= `1 + 1 + (N+4) + 1 + 1 = N + 8` 拍，加约 4 拍作业切换。
48 kHz / 100 MHz ⇒ 每采样 2083 拍。

| 场景 | 每声部/采样 | 声部数 | 占用 |
|---|---|---|---|
| 吉他 20 模态 | 32 拍 | 16 | 512 拍（25%） |
| 钢琴 80 模态（2 弦×40） | 92 拍 | 16 | 1472 拍（71%） |
| 钢琴 80 模态 | 92 拍 | 32 | 2944 拍（需 2 个引擎） |

存储（每模态 36 B）：

| | 模态数 | 系数+状态 | BSRAM |
|---|---|---|---|
| 吉他 32 声部 ×1 弦 ×20 | 640 | 22.5 KiB | ≈28 块 |
| 钢琴 32 声部 ×2 弦 ×40 | 2560 | 90 KiB | ≈111 块 |
| 钢琴 16 键 + 2 预装槽（80 模态/声部） | 1440 | 50.7 KiB | ≈62 块 |

## 实测（GW5AST-LV138FPG676AES，探针 `fmax_e7`：8 槽 × 48 模态 × 块长 64，100 MHz 约束）

| 项 | 结果 |
|---|---|
| Logic | **1480** |
| Register | **832** |
| BSRAM | **24 / 340** |
| DSP | 28（14 × `MULT27X36`） |
| 每声部摊薄 | 185 / 104 / 3 块 / 1.75 个 `MULT27X36` |
| 每采样拍数（8 声部 × 48 模态） | 8 × (56+4) ≈ 480（预算 23%） |
| **PnR Fmax** | **105.4 MHz**（slack +0.512 ns，收敛） |

和旧方案（每声部一个 RAM 中心化 bank，`modal_bank_ram` × 8）对比：

| | `modal_bank_ram` × 8 | **本方案 × 1** |
|---|---|---|
| Logic / Register | 13104 / 6129 | **1480 / 832** |
| BSRAM | 192（56%） | **24（7%）** |

另测试过"固定角色 A/B + 激励搬到顶层"的变体（已移入 `local/`）：DSP 同为 14 个
（乘法总数不变，只是换了位置）、多一份状态和一套搬运 FSM、Fmax 只有 64 MHz ⇒ 不采用。

## 揉弦与按弦（变调）

模型里这两个演奏手法就是两个**无量纲比值**（`sim_guitar.py` 的 `length_r` / `tension_r`，
语义是 current/default，范围 0.9~1.1），它们只影响频率和输出增益，不碰阻尼：

| 派生量 | 公式 | 说明 |
|---|---|---|
| 频率平方比 | `k = tr / lr²` | 全体模态共享，等价于 `f ∝ √T / L`（弦振动标准结果） |
| 输出增益 | `g = lr / tr` | 模型里 `sum_weight ∝ lr/tr`，**变调同时改音量** |
| 模态频率平方 | `un = k·Ωn²`，`Ωn² = (2π·f0·n)²` | |
| 旋转角 | `θn = √k · θn0`，`θn0 = Ωn·Δt` | 因为 `γ²≪ω²`（我们参数下 `γ²/ω²`≈1e-5，折合 0.02 音分），`wd ≈ √un` |
| 旋转/衰减系数 | `c=cos θn`，`s=sin θn`，`d=exp(−γnΔt)` | `d` 每模态常数，不用实时算 |

由此每次更新要重算的系数（每模态）：

```
ec = d·c,   es = d·s
a11 = ec + es·γn·Δt/θn
a12 = es·Δt/θn            ← 需要 sinc(θ) = sinθ/θ
a21 = −es·θn/Δt
a22 = ec − es·γn·Δt/θn
wo  = wo0 · g
```

### 三条路径

| 场景 | 做法 | 代价 |
|---|---|---|
| **按弦 / 换把位**（半音级，`k` 最多变 ±35%） | note-on 时算一次，装载时写表，运行时不改 | **0** |
| **揉弦**（±25~50 cent，`k` 变 ±3~6%） | **低速率重算（精确 CORDIC）**：每轮更新"正在发声的声部"的系数 | 见下 |
| 揉弦（算力紧张时的备选） | 一阶线性化：`Δθn = θn0·δk/2`，`c ≈ c0 − s0·Δθ`，`s ≈ s0 + c0·Δθ` | 每模态 2 乘 2 加（无 CORDIC），误差 ≈0.2 音分；**需要多存 `θn0`** |

线性化只在小调制下成立（±50 cent 内误差 <0.4 音分），按弦这种大范围必须走精确路径。

### 算子够不够用（`rtl/math`）

| 需要 | 现成 | 位置 |
|---|---|---|
| `√k`（每轮一次，全场共享） | ✅ `sqrt` | `math.sv:276` |
| `cos θ` / `sin θ` | ✅ `polar2cart`（喂 `r=1.0`、`w=θ`） | `math.sv:146` |
| `1/θ`（算 `sinc`） | ✅ `inv` | `math.sv:387` |
| 乘/加/移位/饱和 | ✅ `fxp_pkg::fx_mul/fx_add/fx_sat`、`sfp_*` | `pkg/fxp_pkg.sv`、`pkg/fp_ops.sv` |
| `exp(−γnΔt)` | 不需要实时算 | note-on 时算好写进表 |

**结论：够用，不需要新算子**。`polar2cart` 和 `inv` 都是迭代式（约 36 拍/次），
所以每模态一次更新 ≈ 72 拍。

### 算力与更新率

| 项 | 数值 |
|---|---|
| 每模态 | ~72 拍（`polar2cart` + `inv`） |
| 16 声部 × 80 模态 = 1280 模态 | ~92k 拍/轮 |
| 每帧空闲（1472/2083 已占） | 611 拍 |
| 满声部时一轮占用的空闲时间 | ~150 帧 = **3.1 ms** ⇒ 更新率 ≈ 300 Hz（6 Hz 揉弦每周期约 55 点） |
| 典型 6 声部和弦（480 模态） | ~35k 拍 ≈ 57 帧 = **1.2 ms** ⇒ ≈ 800 Hz |
| 额外存储 | 0（`θn0`、`d`、`Ωn²` 都可以由系数生成时顺带存/推） |

所以：**按"正在发声的声部"更新，更新率天然随和弦规模自适应**；
满 16 声部时约 300 Hz（够用），6 声部和弦时约 800 Hz。
如果想把满声部也做到 1 kHz，需要把 CORDIC 改成全流水（吞吐 1 拍/结果，约 +1–2k LUT）。

### 调度（不需要系数双缓冲）

系数块 1R1W：引擎读"第 v 个声部"时，重算单元写"第 v′ 个声部"就行（不同地址、不同时序）。
每轮把"第 v 个声部 80 模态 × 7 字段 = 560 拍"的写操作排在该声部的作业之后、下一次作业之前；
一轮 16 声部 ≈ 8960 拍写带宽，占空闲周期的比例很小。

## 踩过的坑

1. **`coeff_t` 结构体阵列不进 BSRAM**：224 位一个字的阵列 Gowin 不认，会退回 FF
   （48 模态 = 10752 个寄存器，比整条数据通路还贵）。**系数按字段拆成 7 个 32 位阵列**才行。
2. **7 个系数写成同一个值会被 CSE 合并**：探针里 `co_data <= {7{lfsr}}` 会让综合器把 7 个乘法
   当成公共子表达式，只留 3 个（`MULT27X36` 从 14 掉到 6），量出来的 Fmax 不可信。
3. **每声部每帧一个作业时，`x` 的帧号必须由顶层补进地址**，否则每帧都读写第 0 个采样。
4. **`st_zero` 只能在"该声部首帧"置位**，否则每帧都会把状态清掉。
5. **SV 乘法宽度**：`a * m` 的结果宽度是操作数最大宽度，32 位相乘只剩 32 位 —— 必须先符号扩展。
6. **同步 RAM 的数据晚一拍**：读过地址后不能再用组合值，否则整体错位一个模态。
7. **多驱动**：`pend` 这类"谁都能置位"的信号必须单一所有者，否则仿真和综合都会踩坑
   （AB 实验版就是在这儿翻的车）。

## 怎么跑

```powershell
# 全部仿真（需要 Vivado xsim）
pwsh -File rtl/simsynth/local/run_all.ps1

# 单独跑（仿真产物都落在 local/scratch，源码目录保持干净）
pwsh -File rtl/simsynth/local/run_xsim.ps1          # 单模态一步：64 例
pwsh -File rtl/simsynth/local/run_xsim_engine7.ps1  # 最终方案：7 作业

# 重新生成黄金向量（需要 _analysis/ 里的模型工具）
python rtl/simsynth/local/gen_golden.py

# 综合 + PnR 拿 Fmax（GUI 也可以：把 modal_step_pkg / modal_engine7 / modal_voice_top /
# fmax_probe 和 fxp_pkg 加进去，顶层选 fmax_e7，约束用本目录的 fmax.sdc + fmax.cst）
$env:TOP='fmax_e7'; $env:SDC='fmax.sdc'
'source rtl/simsynth/local/synth_pnr_one.tcl' | & 'E:\Gowin\Gowin_V1.9.12_x64\IDE\bin\gw_sh.exe' -nocomp
```

工具版本：Vivado 2017.4（xsim）、Gowin V1.9.12（`sysv2017`），器件 GW5AST-LV138FPG676AES
（Tang Mega 138K Pro，device_version B）。

## 与 rtl/math 的关系

`modal_step_pkg` 的饱和直接调用 `rtl/math/pkg/fxp_pkg.sv` 的 `fx_sat`；
舍入右移是包内联实现的（语义与 `fx_shift_rnd` 逐位一致，但不吃 `int` 形参，
避免把 6 位移位量拓宽成 32 位桶形移位器——实测 Fmax 差 13%）。
等价性由 `rtl/math/tb/tb_fp_ops.sv` 证明（9680 项检查）。两套定点约定的差异见
[FORMAT_ALIGNMENT.md](FORMAT_ALIGNMENT.md)。
